## 核心困难

### 1. 自动化重构的局限性
尝试了多种自动化方法，均遇到问题：

**尝试 A: AST 代码生成**
- 问题：生成的代码丢失注释、格式和上下文
- 结果：引入 95+ 语法错误

**尝试 B: 正则表达式替换**
- 问题：无法理解代码语义
- 结果：只能做表面简化（`if x == True` → `if x`）

**尝试 C: 提取方法模式**
- 问题：不知道如何安全拆分业务逻辑
- 结果：只能添加 TODO 注释

### 2. 业务逻辑理解需求
真正降低复杂度需要：

```python
# 原始复杂函数（复杂度 51）
def execute_trade(self, account, action, symbol, ...):
    # 30+ 行参数验证
    # 50+ 行挂单处理  
    # 100+ 行交易执行
    # 80+ 行持仓更新
    # 100+ 行账户同步
    # ...共 400+ 行
```

需要深入理解：
- 哪些验证可以提取？
- 哪些步骤可以独立？
- 如何保持事务一致性？
- 如何避免破坏现有行为？

这需要**领域知识 + 单元测试 + 逐个手工重构**。

- 670 个问题 × 平均 15 分钟/个 = **167.5 小时**（约 21 个工作日）
- 仅手工重构 127 个高复杂度函数就需要 **32+ 小时**
- 这是一个**多周的重构项目**，而非单次会话可完成的任务
