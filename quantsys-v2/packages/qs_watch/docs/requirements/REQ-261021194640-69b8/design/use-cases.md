# 盯盘执行闭环 使用者旅程  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

> 本文是 Design Review 的评审对象之一，只回答一件事：**agent 与投资人在真实一天里怎么走完这条闭环**。
> 需求来源见 PRD（`requirement.md`），接口契约见 `design/interfaces.md`，实现视图见 `design/backend.md`。
> 本文不重复 PRD 的诉求陈述，只把诉求落到「谁在什么时候看到什么、下一步做什么、系统保证什么」。

## 摘要  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

- **问题**：盯盘能发指令、agent 能下单，但成交之后没有任何回写——待办悬空、持仓状态失真、消息没人判断、超时口径撒谎，投资人问「止损到底执行没有」时系统答不上来。
- **方案**：把「成交」「消息命中」「决定不执行」「期限到」四类事实都变成可观察的旅程节点；agent 只做判断与下单，收敛、投递、催办由系统保证。
- **影响面**：agent 多看到 1 个执行待办形态与 1 个统计端点；投资人多看到三态计数；交易服务成交后多一次进程内回调；其余使用方式不变。
- **读者地图**：五条用例见「方案总览」；谁能看到什么见「架构与依赖」的角色矩阵；状态怎么走见「数据模型」；契约见「接口设计」。

## 背景与问题  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

### 需求来源  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

### 现状与代价  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

今天 agent 的一天是这样断的：

1. 盯盘触发 P0 止损，卡片进群、待办进库、agent 被唤醒；agent 判断后经交易接口卖出。
2. **成交这一步之后没有任何代码回头**：待办仍「未收敛」，退出规则仍在，规则持仓状态仍按日频对账的旧值。
3. 三小时后执行期限到了，同样的待办被 L3 反复催；三天后被自动过期归档，**在统计里被算成已收敛**——未执行的止损看起来像是处理过了。
4. 盘中一条 critical 减持公告命中持仓，只发了一张卡；agent 没看到，第二天开盘才知道。
5. agent 决定「这次不执行」，只能口头说明；规则照旧，下一次同样触发。

代价可量化：生产 `watch_triggers.detail` 含执行明细 0 行、P0 待办长期未收敛、超时卡 3 分钟内连发 3 张、今日 `watch_triggers` 2336 条中统计先取 200 行再过滤必然截断。

### 为什么是现在  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

未执行止损被记成已收敛，会让「止损执行率」这个指标从第一天起就是错的；错得越久，历史样本越不可信，复盘与调参都建立在假数据上。三条接缝（成交回写、消息投递、待办闭环）都在同一批解决成本最低，拆开做要三次改同一批文件与同一批用例。

## 目标与非目标  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

### 目标  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

- **G1（UC-1）**：任一来源的卖出成交（agent 下单、挂单撮合、其它自动路径）在落库后 3 秒内让该标的未收敛执行待办转已处理，且同一成交号重复投递只收敛一次。
- **G2（UC-2）**：买入成交后，该标的规则持仓状态在下一拍前变为持有；下一拍入场类规则被状态门跳过、退出类照常求值。
- **G3（UC-3）**：交易日 15:00–22:00 内，critical 命中持仓标的或持仓板块时 1 个扫描周期内产出 1 条 P1 待办 + 1 次唤醒；soft 命中产出 0 条待办。
- **G4（UC-4）**：关闭为已忽略并带结构化动作时，规则字段真实变化且审计恰好新增 1 行、触发溯源非空；重复关闭返回冲突。
- **G5（UC-5）**：执行期限前 1 分钟不发超时回执、期限后 1 分钟发 1 次、同一期限周期重复巡检仍为 1 次；待办终态保持未收敛。
- **G6（UC-1～UC-5）**：投资人能在一次查询里看到已执行/未执行/超时三态计数与处理时延 p50/p95，空数据返回 0 且不报错。

### 非目标  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

- **不做 v2 侧自动下单**（D-1）：下单与最后判断永远是 agent；闭环 = 指令 → agent 执行 → 回执 → 兜底。若让 v2 下单，本期范围翻倍且违反既定架构。
- **不做消息语义的自动判定**：系统只负责把 critical 消息送到 agent 手上并留下证据；「是否破坏持有逻辑」由 agent 判断。自动判定会把误判写进规则。
- **不做减仓数量化与交易计划实体**（D-2）：指令仍为清仓口径，分批减仓由 agent 自行裁量；计划实体留待下一期。
- **不改既有待办状态机枚举**：复用已处理/已忽略/已过期三态；新增枚举要改 schema 与前端，而现有三态已够表达结局。
- **不改自动兜底止损（30 分钟百分比）的行为**：保留作为最后防线，收敛口径以成交为准。

## 方案总览  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

**一句话方案**：五条旅程共用一条脊柱——盯盘产出结构化事实 → agent 做判断与下单 → 系统把结局回写进同一份台账（待办终态、触发处置、规则字段、证据）。

```text
交易日
  ├─ 盘中：条件触发 ─▶ 执行待办 + 指令卡 + 唤醒 ─▶ agent 判断
  │                                              ├─ 执行 ─▶ 成交 ─▶ 回写收敛（UC-1）
  │                                              └─ 不执行 ─▶ close + 规则变更 + 审计（UC-4）
  ├─ 买入成交 ─▶ 状态转持有 ─▶ 下一拍不再喊建仓（UC-2）
  ├─ 盘中/盘后消息 ─critical 命中持仓─▶ P1 待办 + 唤醒（UC-3）
  └─ 期限到未收敛 ─▶ 超时回执 1 次 + L3 催办（UC-5）
                                    ▼
                        三态计数与时延可查询（G6）
```

### 关键概念  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

- **执行待办**：P0 且动作为交易类（卖出止损）的待办，是「有没有执行」的唯一载体；一标的一账户同时只保留一条未收敛实例。
- **成交事实**：成交落库后的结构化投影（账户、标的、方向、数量、价格、成交号、时间、来源），只描述发生了什么，不含任何下单意图。
- **证据**：待办附带的可追溯载荷（消息摘要、命中词、来源；成交号与「触发→成交」时延），只增不改，不参与状态机。
- **结局三态**：已执行（成交回写）、未执行（agent 显式关闭为已忽略）、超时（期限到仍未收敛，是状态不是终态）。

### UC-1 agent 收到 P0 止损 → 执行卖出 → 系统收敛（FR-1）  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

**触发条件**：盯盘判定某标的 P0 止损条件成立（价格跌破止损线），且该账户该标的当前没有未收敛的执行待办（有则刷新指令与期限、不重复建单）。

**主流程**

1. 引擎建执行待办（P0、动作为交易类、流转态 L1），并唤醒归属 agent；指令卡带结构化执行指令（动作=执行止损、方向=卖出、数量=T+1 可卖量、触发价、参考成本、执行期限）。
2. agent 判断后经既有交易接口卖出（接口形态不变，仍由交易服务做 T+1/持仓校验）。
3. 交易服务成交落库，随后同步发出成交事实（异常只记日志，不影响成交）。
4. 盯盘的成交收敛器收到事件，读持仓真值：该标的剩余持仓为 0。
5. 收敛该账户该标的未收敛执行待办为已处理（动作=交易、决策审计号）；重复投递同一成交号时不再二次收敛。
6. 退役该标的退出族规则（停用 + 生命周期闭合），并把规则持仓状态翻为无持仓。
7. 触发处置更新为已处理，并把成交号、成交价、「触发→成交」时延并入触发证据。
8. 统计口径下一次读取时该条计入「已执行」。

**异常分支**

- **回调异常**：成交已落库，回调失败只记日志；待办保持未收敛，继续走催办——绝不把未确认的成交记成已收敛。
- **部分成交**：剩余持仓大于 0 时不收敛，只在证据里记进度，继续走超时与催办（清仓才算闭环）。
- **不可执行**：T+1 可卖量为 0、无持仓、账户未知时，指令标记为不可执行；agent 不重试下单，改为「今日不可执行 + 下次条件」关闭为已忽略（进入 UC-4）。
- **重复事件**：同一成交号重复投递只收敛一次，时延只写一次。
- **并发关闭**：成交回写与 agent 手动关闭同时发生，先到者生效，后到者拿到冲突（台账零改动）。

**可观察结果**：待办终态为已处理；触发处置为已处理且证据含成交号、成交价与时延；退出族规则停用、持仓状态为无持仓；统计的「已执行」加 1、时延分位可读；重复投递不改变任何计数。

### UC-2 agent 买入 → 状态转持有 → 不再重复喊建仓（FR-2，联动 FR-8）  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

**触发条件**：任一来源的买入成交落库（agent 下单、挂单撮合），或日频持仓联动为新持仓补挂止损/止盈规则。

**主流程**

1. 买入成交落库后发出成交事实（与 UC-1 同一出口）。
2. 成交收敛器读持仓真值：总持仓大于 0 → 该账户该标的的全部规则持仓状态写为持有。
3. 下一拍盯盘：状态门对入场类与加仓类规则跳过（已确认持有，不再喊建仓）；止损、止盈、日内交易类照常求值。
4. 日频持仓联动补挂止损/止盈时，创建即写持有状态（FR-8），保证新规则下一拍就能被求值。

**异常分支**

- **持仓读失败**：不猜「没有持仓」，保持原状态并记降级日志；读失败不等于空仓（宁可多喊一次，不可漏喊止损）。
- **缺列库（未迁移）**：状态读出「不可知」，分支退化为「全部求值」，与今天行为一致。
- **买入后同日清仓**：第二次成交把状态翻回无持仓，退出规则按 UC-1 退役。
- **部分买入成交**：只要总持仓大于 0 即为持有。

**可观察结果**：规则持仓状态在秒级变为持有；下一拍日志里入场规则被状态门跳过、止损规则照常求值；补挂的止盈规则不再被跳过；状态与持仓表在同一分钟内一致。

### UC-3 盘后 critical 公告 → P1 待办 → agent 判断提前离场（FR-3、FR-4）  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

**触发条件**：交易日 08:00–22:00 窗口内（含 15:00–22:00 盘后段），消息扫描分级结果为 critical，且命中持仓标的或持仓板块。

**主流程**

1. 盘后巡检段按交易日历与时间窗执行消息扫描（不再被「仅交易时段」挡掉），扫描内部保留 15 分钟节流。
2. 分级命中 critical，且标的是持仓标的或属于持仓板块。
3. 消息桥建 P1 待办（动作为规则变更类），证据写入消息来源、标题摘要、命中词、级别、板块与扫描时刻。
4. 按既有归属路由唤醒 agent（消息类待办默认归该账户责任人）。
5. agent 读到待办与证据，判断这条消息是否破坏持有逻辑。
6. 判断「提前离场」则走 UC-1 的卖出路径；判断「不构成威胁」则走 UC-4（关闭并改规则）。

**异常分支**

- **soft 级别**：只发卡，不建待办、不唤醒（候选噪音，不该占待办队列）。
- **重复命中**：同标的在去重窗口内重复命中不新增待办；同一消息重复扫描同样不新增。
- **盘后与其它日频任务同拍**：回填、持仓联动、持仓板块映射仍「每日一次」，不因盘后段开启而重复执行。
- **消息源不可用**：该轮跳过并计数，不影响其它任务与既有卡片。
- **未装配消息桥（旧装配或回滚）**：消息照旧只发卡，盘后窗口本身不受影响。

**可观察结果**：待办表新增 1 条 P1 且证据非空；唤醒 1 次；soft 命中路径待办 0 条；盘后 16:30 的日志里存在扫描轮次；重复扫描不增加待办数。

### UC-4 agent 决定不执行 → 关闭待办 → 规则变更 + 审计（FR-5）  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

**触发条件**：agent 收到执行或消息待办后，判断本次不应动作（消息误报、计划时点未到、已通过其它方式处置），并需要给出下次条件。

**主流程**

1. agent 调待办关闭接口：终态=已忽略、必填下次条件，并带结构化规则动作（调阈值 / 延期 / 停用 / 退役）、动作参数与理由。
2. 服务校验：终态合法、忽略必须给下次条件、待办存在且未收敛；已收敛直接冲突返回。
3. 关闭成功后触发规则联动：动作落成规则字段的真实变更，并写一条带触发溯源、待办溯源与理由的规则变更审计；规则注记同步追加一条人读记录。
4. 触发处置更新为已忽略并记原因。
5. 下一次同类条件出现时，按新规则参数求值（阈值已调 / 已延期 / 已停用 / 已退役），不再原样复现。

**异常分支**

- **缺触发溯源**：联动在写任何东西之前拒绝（缺溯源无法复盘，宁可不写）。
- **宪法级止损停用/退役无理由**：被既有守卫拒绝，规则与审计都未被改动。
- **动作项非法**：未知动作、缺参数、缺理由 → 判为请求非法，调用方修正或去掉结构化动作。
- **规则已更新但审计写失败**：同一事务内整体回滚，不留「规则改了但没审计」。
- **重复关闭**：返回冲突，台账零改动。
- **未装配联动（回滚态）**：关闭仍生效但没有规则变更——这是回滚态而非正常态，装配即闭环。

**可观察结果**：规则对应字段变化且注记追加；规则变更审计恰好新增 1 行、触发溯源非空；待办终态为已忽略且下次条件非空；重复关闭返回冲突。

### UC-5 期限到未处理 → 超时回执 → L3 催办（FR-6）  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

**触发条件**：执行待办（P0、动作为交易类、可执行）到执行期限（= 待办创建时刻 + `WATCH_EXEC_SLA_MIN`，默认 30 分钟）仍未收敛。

**主流程**

1. 超时巡检扫描未收敛执行待办。
2. 时间基准统一：写库一律带时区（UTC），读侧归一到同一时区后再比较；只有确实超过期限才动作。
3. 发一次超时回执（含「已等待 N 分钟仍未执行」与执行指令摘要），唤醒归属 agent，流转态升到 L3、升级计数加 1。
4. 同一期限周期只发一次：重复巡检不再发，不重复打扰。
5. 待办保持未收敛（不写已过期）；三天的自动归档仍按旧语义（归档是台账动作，不是判定）。

**异常分支**

- **期限前 1 分钟**：不动作。
- **已收敛**（成交回写或 agent 关闭）：跳过，不发回执。
- **不可执行待办**（无持仓 / T+1 锁定 / 账户未知）：不算执行超时，按普通 P0 提醒节奏升级。
- **时区或裸时间**：带时区、裸时间、跨日三种形态按同一基准归一；无法解释的值不参与比较并记日志。
- **超时与关闭竞态**：先关闭者生效；巡检发现已收敛则跳过。

**可观察结果**：回执表新增 1 条超时类回执；流转态为 L3、升级计数加 1；重复巡检仍为 1 条；待办终态仍为空（未收敛）；统计的「超时」加 1。

### 不变量  serves: FR-5, FR-6

- 未有终态即未收敛；终态一旦写入不再改写。
- 超时不是终态：执行类待办超时后仍停在未收敛，等成交或关闭。
- 一标的一账户同时最多一条未收敛执行待办。
- 证据只增不改；成交号是成交证据的幂等键，时延只写一次。
- 已处理必须能追到成交或决策审计；已忽略必须能追到下次条件；规则变更必须能追到触发。

> 本节只列 agent 与投资人**直接使用**的三个契约（关闭、统计、消息待办）。成交回调端口属进程内契约，语义与错误处理见 `design/interfaces.md` 与 `design/backend.md`。

| 编号 | 接口 | 输入 | 输出 | 失败与错误 | 兼容性 |
|---|---|---|---|---|---|
| IF-3 | `POST /api/watch/todos/{todo_id}/close`（扩展） | 既有字段 + 可选结构化规则动作（动作类型、参数、理由） | 待办、回执、规则变更结果 | 400 终态非法或缺下次条件；404 不存在；409 已收敛；422 动作非法或缺触发溯源 | additive：不传动作时与现状逐字一致 |

| IF-5 | `NewsTodoBridge.dispatch(alerts)` | 已分级的消息命中列表 | 新建待办 id、跳过项、错误项 | 方法不抛错；单条失败进错误项 | 新增方法；未注入时旧行为 |

#### IF-3 待办关闭（扩展）  serves: FR-3, FR-5, FR-7

**语义**

agent 用一次调用同时完成两件事：给待办一个终态，以及把「这次为什么不执行、下次按什么条件动作」落成规则的**真实变更**。终态为已忽略时必须给下次条件；只有携带结构化规则动作时才触发规则联动，联动包含规则字段更新与一条带触发溯源与理由的审计，两者同一事务。动作词表固定为四类：调阈值、延期、停用、退役。关闭成功后回执照旧发送。

**错误码**

| 情形 | 码 | 调用方应如何处理 |
|---|---|---|
| 终态非法，或已忽略但缺下次条件 | 400 | 修正入参后重试 |
| 待办不存在 | 404 | 放弃，核对待办 id |
| 待办已收敛 | 409 | 不重试；改为读取终态确认结局 |
| 规则动作非法（未知动作、缺参数、缺理由、缺触发溯源） | 422 | 去掉结构化动作或补全后重试 |
| 规则或审计写库失败 | 422 + 可读原因 | 事务已回滚，可修正后重试一次 |

**兼容性**

结构化规则动作与响应里的规则变更结果都是 additive：旧调用方不传该字段时行为完全不变，旧消费方忽略新增响应字段即可。审计沿用既有规则变更表（已有触发溯源列），不加列。

#### IF-4 执行闭环统计  serves: FR-3, FR-5, FR-7

**语义**

只读聚合，回答「止损到底执行没有」：已执行、未执行、未收敛、超时四项计数，加上「触发→成交」时延的 p50/p95（秒）。治理类待办（规则重叠、元复核）不计入分母；空数据返回 0 而不报错；与待办台账同口径查询必须逐项相等。刻意不挂在既有「预判命中率」统计端点上——那是触发后 5/10/20 个交易日的方向命中率，口径完全不同，混用会把两个指标都做坏。

**错误码**

| 情形 | 码 | 调用方应如何处理 |
|---|---|---|
| 时间窗无法解析或结束早于开始 | 400 | 修正入参 |
| 聚合查询异常 | 500 | 稍后重试；不返回半份数字 |

**兼容性**

新增端点，无版本变更；字段名一次定死，后续只增不改。旧端点行为不变。

#### IF-5 消息待办桥  serves: FR-3, FR-5, FR-7

**语义**

把「已分级的消息命中」变成「agent 看得见的待办」：仅 critical 建 P1 待办（动作类型为规则变更类），证据写入消息来源、标题摘要、命中词、级别、板块与扫描时刻，并按账户归属唤醒 agent；soft 直接跳过。同标的在去重窗口内已有待办时不新增。它是消息扫描与待办服务之间的唯一桥，不产生任何交易动作。

**错误码**

方法不抛错，返回新建、跳过、错误三类结果；单条失败只进错误项，不中断整轮扫描，扫描任务按错误计数告警。重复命中返回「跳过」而不是错误。

**兼容性**

新增方法，消息服务未注入桥时行为与现状一致（只发卡）。待办证据是新增可空列，旧数据读出为空即「无证据」。

|---|---|---|---|

## 失败模式与回滚  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

| 失败场景 | 触发条件 | 用户可见影响 | 检测手段 | 回滚动作 | 决策人 |
|---|---|---|---|---|---|
| 成交回写失败 | 回调实现缺陷或库不可用 | 成交正常，但待办不收敛、统计少算 | 回写错误计数与日志（成交号可搜） | 注销成交监听，恢复旧行为 | 值班 |
| 状态翻转错误（把有仓写成无仓） | 持仓读取口径错误 | 入场规则被误跳过，漏喊建仓 | 状态与持仓表日频对账差值计数 | 停用状态门（全部求值）后核库 | 值班 + 投资人 |
| 消息待办淹没队列 | critical 词表过宽或消息源异常 | 待办里全是消息，真执行待办被挤后 | 每日 critical 建单数与待办队列长度 | 收紧词表或把窗口调回盘中 | 投资人 |
| 关闭联动写坏规则 | 动作参数错误或守卫缺陷 | 规则被停用或阈值被改错，保护失效 | 规则变更审计逐条复核 + 变更前后值 | 按审计的前后值反向应用 | 值班 + 投资人 |
| 超时误报 | 时间基准不一致或期限配置错 | agent 被反复催办 | 超时回执条数 / 同一待办重复次数 | 关掉执行期限巡检，只保留原提醒节奏 | 值班 |
| 盘后扫描拖慢日频任务 | 扫描耗时超预期 | 回填/持仓联动被推迟到次日 | 盘后各任务完成时刻日志 | 盘后段只跑消息扫描，其余移回盘中段 | 值班 |

- **开关**：成交监听可注销（等价关掉回写）、消息桥可置空（只发卡）、规则联动可去掉（只收敛不改规则）、执行期限巡检可关（保留原提醒节奏）；粒度均为进程级，默认全开。
- **回滚演练**：上线前用一次「注销监听 → 触发 → 成交」演练确认回旧行为，负责人 agent，预期 5 分钟内恢复。
- **不可逆动作**：规则的停用/退役与阈值修改会改变未来求值行为——事前保护是守卫拦截宪法级止损的无理由停用，事后保护是审计记录的前后值可反向应用；除此之外无不可逆动作（证据与统计均只增不改）。

## 跨关注点  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

| 关注点 | 结论 | 依据与措施 |
|---|---|---|
| 安全 | 无新增对外写能力，权限面不变 | 关闭接口沿用既有鉴权；统计只读；成交回执仅进程内调用，不开放网络入口 |
| 隐私与合规 | 证据只存摘要，不存原文与个人信息 | 证据只记标题、命中词、来源、扫描时刻；不落正文全文、不落账号外的人身份 |

| 可观测性 | 每条旅程都有结构化结局可查 | 日志固定带成交号/待办 id/规则 id/状态；回执计数、状态对账差值、审计行数三项可作为告警阈值 |
| 性能与容量 | 对成交主链路的影响远小于 50ms | 回写发生在落库之后、单表更新数条、无跨服务调用；消息侧每轮持仓标的数有限，每标的每轮最多一条待办 |

## 常见问题  serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6, FR-7, FR-8

| 问题 | 回答 |
|---|---|
| 为什么不让 agent 自己关单，省掉交易侧改动？ | 靠记性的闭环不是闭环：忘了就永不收敛，成交号与时延也取不到；统计与复盘会长期失真。 |
| 成交回调会不会拖慢或打断下单？ | 不会。回调在成交落库之后同步执行且被两层兜住，最坏情况只是没回写；不影响成交结果。 |
| 同一笔成交重复投递会不会重复收尾？ | 不会。成交号是幂等键：待办已终态时不二次收敛，时延只写一次。 |
| agent 看到消息待办会不会被淹没？ | 只有 critical 且命中持仓标的或持仓板块才建单，同标的窗口内去重；soft 维持发卡。 |
| 超时了为什么不算「已过期」？ | 已过期的语义是「超期未处置，系统归档」，不是判定。把未执行的止损记成已过期，等于把敞着的风险写成已处理。 |
| 「不执行」为什么必须带结构化动作？ | 只有结构化动作才能落成规则变更并留下可复盘审计；自由文本无法执行，也无法核对下次是否真的改了。 |
| 这套改动能不能单独回滚？ | 能。回写、消息桥、规则联动、期限巡检各自可关闭或置空，关闭即与现状逐字一致。 |
| 统计口径为什么要排除治理类待办？ | 规则重叠、元复核不是执行动作；计入分母会拉低执行率，掩盖真正没执行的止损。 |
