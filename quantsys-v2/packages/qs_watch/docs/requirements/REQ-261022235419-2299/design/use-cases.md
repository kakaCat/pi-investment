# 盯盘引擎 V2 · 用例设计  serves: FR-4, FR-5, FR-6, FR-7, FR-8, FR-9, FR-10

## 摘要  serves: FR-4, FR-7

- **问题**：判定逻辑要按真实使用场景校验，而不是只按单元拆解。
- **方案**：六个端到端用例（持仓四操作 + 非持仓买入 + 失效裁决 + 循环路由）走通全链路。
- **影响面**：用例即测试策略的冒烟层，也是 agent 提示词设计的输入。

### 现状与代价  serves: FR-7

V1 曾出现「规则触发但用户拿到卡不知道怎么操作」——用例缺失导致消息内容没被端到端校验。

### 为什么是现在  serves: FR-7

用例是消息模板与提示词设计的验收锚点，设计阶段不定，实施期会返工。

## 目标与非目标  serves: FR-7

### 目标  serves: FR-4, FR-5, FR-7

- 每个用例给出：初始状态 → 触发 → 路由 → 通知内容要点 → 终态
- 用例可直接转为冒烟测试

### 非目标  serves: FR-7

- 不覆盖异常流全组合（失败路径见 requirement.md「失败与并发路径」）
- 不写 UI 用例（无前端）
- 不写性能用例

## 方案总览  serves: FR-7

**一句话方案**：七个用例覆盖「持仓四操作 / 非持仓买入 / 失效裁决 / 循环路由」全链路。

```text
UC-1 增仓 / UC-2 止盈 / UC-3 止损 / UC-4 减仓（持仓类）
UC-5 买入范围（非持仓）
UC-6 失效裁决（目标过时）
UC-7 循环路由（首发 agent / 中段不处理 / 第10次直通）
```

**关键概念**：用例 = 初始状态 → 触发 → 路由 → 通知 → 终态。

## 架构与依赖  serves: FR-7

- **模块划分**：用例驱动 position_engine / unpositioned_engine / notify_agent / notify_feishu 四模块协作

- **外部依赖**：quant_test 库 + Fake 行情
