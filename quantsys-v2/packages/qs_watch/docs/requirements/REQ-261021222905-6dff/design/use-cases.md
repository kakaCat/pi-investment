## 方案总览 `serves: FR-1`

**一句话方案**：白天 UC-1 跑执行、收盘 UC-2 跑反思修改，两条线通过「重编译」首尾相接成日级闭环。

```text
UC-1（盘中）建计划→编译→触发→agent终判→回执收敛

```

## UC-1 执行日闭环 `serves: FR-1, FR-2, FR-3, FR-4`

- **用例角色**：投资脑 agent-dh（终判下单，经 trading_plan 工具调用全部计划面）、qs_plan/qs_watch/qs_trading（系统）；agent-ts 同剧本适用（fin-agent 本账户）。
- **前置条件**：迁移已跑；账户存在；目标标的有行情。
- **交互流程**：
  1. agent 建计划（IF-1：1 标的、staged_break 入场、止损 8%、两批减仓）→ draft；
  2. 激活（IF-6）→ 编译产出 4 条托管规则（entry/stop/reduce×2）；
  3. 盘前 agent 经 trading_plan 工具（IF-17 → IF-10）拉 today → 看到该计划、条件就绪度、环境闸 verdict；
  4. 盘中 staged_break 确认 → 指令卡+待办（带 plan_id）→ agent 终判买入（走既有 /trade）；
  5. 买入成交 → FillEvent(plan_id) → 计划 active→holding、position_state→holding；
  6. 价格到第一减仓批 → 指令卡 → agent 卖 1/3 → 部分收敛（该批退役，计划不收摊）；
  7. 价格到止损 → P0 指令 → agent 卖出 → 清仓收敛：待办 handled、计划 closing→closed。
- **异常流**：
  - 第 4 步环境闸拦截 → 信号只归档不动作（既有语义），计划保持 active；
  - 第 5 步事件发送失败 → 成交正常，回执缺失记 error，次日对账兜底；
  - 第 7 步 agent 未执行 → SLA 超时链（既有），计划不自动 closed。
- **后置条件**：plan_events 全链留痕；stats 可读到本计划命中率/盈亏/时延。
- **完成标志**：计划 closed 且回执链各环节留痕齐全（TC-9/10/11 断言同一剧本）。

## UC-2 反思改计划闭环 `serves: FR-5, FR-6`

- **用例角色**：qs_ops 定时器、reflection_pack_service、agent、plan_service/compiler。
- **前置条件**：UC-1 跑过至少一天（有成交/拦截/修改历史数据）。
- **交互流程**：
  1. 15:35 定时器逐激活计划组装材料包（四输入）；
  2. 唤醒 agent → 按五问作答 → 经 trading_plan 工具提交（IF-17 → IF-12）→ 落库；
  3. 报告含「止损 8%→10%」提案（附假设与证据）；
  4. 预览 diff（IF-11）→ 确认 → apply（IF-5）→ version++、基线冻结；
  5. 编译器重编译 → watch_rules 止损阈值=10%；
  6. 次日 UC-1 按新规则执行；下个反思周期「修改评估」对照基线审判本次修改。
- **异常流**：
  - agent 超时未写回 → overdue_count+1，连续 3 日告警；
  - 材料包某输入缺数据 → 该段 missing，报告仍可交但该项显式标注；
  - 五问缺项 → 400，不落库。
- **后置条件**：plan_reflections 一行（含材料包快照）；版本行带 baseline/window。
- **完成标志**：watch_rules 读数=新阈值，且次日反思材料包含本修改的对照数据（TC-12/13 同剧本）。

## UC-3 观察窗内横跳被拒 `serves: FR-6`

- **前置条件**：UC-2 完成（v2 版本 apply 于 3 日前，window=10）。
- **交互流程**：
  1. agent 再 PATCH 止损 10%→8%（反向）且不写理由；
  2. 系统拒：400 PLAN_CHANGE_LOCKED（观察窗内+反向+无说明）；
  3. agent 补上「上次判断为什么错」+ ≥2 条证据 → 重提 → 放行。
- **异常流**：人在窗口内修改同字段 → 同样适用（纪律门不分 actor，仅人工理由格式放宽）。
- **后置条件**：无变更发生（步骤 2 分支）或新版本带完整理由（步骤 3 分支）。
- **完成标志**：步骤 2 时 spec/version 零变化、事件零新增（TC-15/16 断言）。

## UC-4 紧急通道与次日复核 `serves: FR-6`

- **前置条件**：盘中，持仓标的出现资损风险（如利空急跌）。
- **交互流程**：
  1. agent/人走紧急 PATCH（bypass 观察窗），强制附理由 → 立即生效重编译；
  2. 事件 kind=spec_change 标 urgent=true；
  3. 次日反思材料包「修改评估」置顶该紧急修改 → agent 必须复核并写明结论。
- **异常流**：紧急修改缺理由 → 400（紧急不放松留痕）；次日反思漏复核 → 五问第二问判缺失，400。
- **完成标志**：紧急行与复核报告均落库，可追溯「谁、什么时候、为什么、后来怎么判」。

## UC-5 有持仓关闭计划 `serves: FR-1`

- **交互流程**：
  1. 对 holding 计划调 close（IF-9）不给处置方案 → 422；
  2. 附 close_disposition（如「市价清仓后关」）→ 退役全部托管规则、计划 closing；
  3. 清仓成交回执 → 计划 closed；30 日后可 archived。
- **异常流**：关闭后回执丢失 → 计划停 closing，对账任务（日频）提示人工介入。
- **完成标志**：托管规则 0 存活、事件链完整、close_reason 非空。

## UC-6 core_plan 批次适配（P2） `serves: FR-9`

- **交互流程**：
  1. agent 调 from-core-plan（IF-15，batch=1）→ 生成 4 个 draft（预算比例一致）；
  2. 逐个预览并激活；重复调适配 → 0 新增。
- **异常流**：core_plan 缺失/过期 → 422 CORE_PLAN_UNAVAILABLE，零写入。
- **完成标志**：4 个 draft 存在且 spec 预算与 core_plan 一致（TC-21 断言）。
