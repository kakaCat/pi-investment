# 交易闭环补口 需求文档（REQ-261022022657-857f）

## 摘要

**TL;DR**：交易计划闭环补三处断点——盘后反思叫醒 agent、减仓部分成交收敛批次、持仓消息 critical 进待办并唤醒；不改判定逻辑，只接线，让「计划→执行→反思→离场」真正转起来。

- **要解决什么**：交易计划已上线，但三处闭环断点：反思只组包不唤醒、减仓批次不收敛、消息只通知不进待办。
- **来源与证据**：2026-10-22 代码核查与生产日志（waker 未注入、on_fill 无批次逻辑、news 无 todo/wake）。
- **本轮结论**：4 条进 PRD（FR-1~FR-4），0 条被拒，0 条延期。

- **收集方式**：交易计划（REQ-261021222905-6dff）交付后逐链路验证，边验证边记录断点。

## 产品定义

交易计划闭环补口：把「计划已存在」升级为「计划在真实循环里被使用」。
核心价值：盘后反思真的会发生、减仓进度真的可见、消息风险真的能把 agent 叫起来判断。
与现状的区别：三处断点都在组合根/状态推进层，不改判定逻辑与消息分级。

## 需求明细

#### R-1 反思定时任务接入唤醒通道

**描述**

盘后/周六定时任务在材料包组好后，经组合根注入的唤醒通道叫醒 agent；失败计 overdue，不阻塞组包。

**来源与证据**

代码：`packages/qs_plan/qs_plan/application/reflection_job.py:39/44`（waker 缺省 None）；
`adapters/inbound/fastapi_app/main.py:141-142`（build_plan_jobs 未传 waker）。

**验收判据**

`pytest tests/plan/test_reflection_job.py -q` 全绿（新增注入 waker 被调用、waker 失败 overdue+1 两例）。

**优先级理由**

不做则反思闭环永远不启动，是 Must。

#### R-2 减仓批次收敛

**描述**

部分成交按累计卖出比例匹配批次，退役对应 reduce 规则并留痕进度；全部批次完成且清仓才 closed。

**来源与证据**

代码：`packages/qs_plan/qs_plan/application/plan_service.py:on_fill`（无批次逻辑）。

**验收判据**

`pytest tests/plan/test_plan_batch_convergence.py -q` 全绿；`quant.trading_plan_events` 出现 `kind=fill` 且 `detail.batch` 有值。

**优先级理由**

不做则「按计划减仓」只是文案，重复触发会重复喊，是 Must。

#### R-3 消息→离场链

**描述**

持仓标的 news/policy critical 命中 → 建 P1 待办（来源 news）+ 唤醒 agent；非持仓只通知；24h 去重。

**来源与证据**

代码：`packages/qs_watch/qs_watch/application/services/watch_engine/news_watch_service.py`（无 todo/wake）。

**验收判据**

`pytest tests/plan/test_news_exit_linkage.py -q` 全绿；`quant.watch_todos` 出现 `source='news'` 的 P1 待办。

**优先级理由**

流程图最大空白（消息→提前离场），是 Must。

#### R-4 回归与可观测

**描述**

三条链路有可查读数（wake 次数 / 批次进度 / 消息待办数），且既有套件不新增红。

**来源与证据**

2026-10-22 验证经验：无读数时断点只能靠读代码发现。

**验收判据**

`pytest tests/plan -q` 与 `pytest tests -k watch -q` 不新增红；三类读数各一条查询样例。

**优先级理由**

没有读数就无法在生产验证，列为 Should。

**FR-1: 反思定时任务接入唤醒通道**
**判据**：`pytest tests/plan/test_reflection_job.py -q` 全绿（含注入 waker 被调用、waker 失败 overdue+1）；生产日志出现反思唤醒记录。

**功能描述**：盘后/周六定时任务在材料包组好后，经既有唤醒通道叫醒 agent。

**详细说明**：
- **使用场景**：交易日 15:35、周六 10:00，投资脑对当日/本周计划做反思。
- **操作流程**：扫到期计划 → 组四输入材料包 → waker 唤醒（材料包随行）→ 推进 review_due_at；失败 overdue+1 且继续下一张。
- **预期结果**：agent 侧确实收到唤醒；日志可查唤醒/失败数。
- **边界条件**：非交易日不触发；同周期不重复唤醒；waker 失败不阻塞组包落库。

**验收标准**：
1. 注入 fake waker → 每张到期计划调用一次，review_due_at 前移；
2. waker 抛异常 → 该计划 overdue+1，其余继续；
3. `pytest tests/plan/test_reflection_job.py -q` 全绿。

### 功能点 FR-2：减仓批次收敛

**FR-2: 减仓批次收敛**
**判据**：`pytest tests/plan/test_plan_batch_convergence.py -q` 全绿；`psql -d quant_investment -c "select detail from quant.trading_plan_events where kind='fill' order by id desc limit 3"` 可见批次进度。

**功能描述**：部分成交只退役对应减仓批次并留痕，计划保持持仓；全批完成且清仓才关闭。

**详细说明**：
- **使用场景**：计划「+8% 卖 1/3、+15% 卖完」，第一档成交一部分。
- **操作流程**：回执带 plan_id → 按累计卖出比例匹配批次 → 退役该批 reduce 规则 + 写 fill 事件（detail.batch）→ 计划保持 holding；剩余 0 → closing→closed。
- **预期结果**：可查「第 1 批已卖、第 2 批待触发」；同批不重复喊。
- **边界条件**：跨批成交按顺序退役；找不到批次记 degraded 不臆造；纯止损清仓行为不变。

**验收标准**：
1. 卖 1/3 → 第 1 批退役、事件留痕、计划 holding；
2. 卖完 → 全批退役且 closed；
3. 回执重放 → 规则/事件不重复；
4. `pytest tests/plan/test_plan_batch_convergence.py -q` 全绿。

### 功能点 FR-3：消息→离场链

**FR-3: 消息→离场链**
**判据**：`pytest tests/plan/test_news_exit_linkage.py -q` 全绿；`psql -d quant_investment -c "select id,source,level,status from quant.watch_todos where source='news' order by id desc limit 3"` 可见 news 待办。

**功能描述**：持仓标的消息 critical 命中 → P1 待办 + 唤醒 agent 判断是否破坏交易逻辑。

**详细说明**：
- **使用场景**：持仓股突发减持/监管处罚/行业政策利空。
- **操作流程**：消息扫描命中 critical 且在持仓或激活计划内 → 建 P1 待办（payload 带标题/来源/词/持仓/plan_id）+ 唤醒 → agent 评估：破坏→patch/close 提前离场；不破坏→close(ignored)+next_condition。
- **预期结果**：消息风险进入与止损同一条待办闭环，有终态可追溯。
- **边界条件**：非持仓只通知；源不可用不建单；同消息 24h 去重。

**验收标准**：
1. critical + 持仓 → 生成 P1 待办且 waker 被调用；
2. 重复扫描 24h 内只 1 条；
3. 无持仓不建待办、通知照发；
4. `pytest tests/plan/test_news_exit_linkage.py -q` 全绿。

### 功能点 FR-4：回归与可观测

**FR-4: 回归与可观测**
**判据**：`pytest tests/plan -q` 与 `pytest tests -k watch -q` 不新增红；三条读数各一条查询样例。

**功能描述**：三条链路都有可查读数且不破坏既有套件。

**详细说明**：
- **使用场景**：上线后验证「反思真唤醒了、批次真收敛了、消息真建单了」。
- **操作流程**：跑两个套件；查任务日志、plan events、watch_todos。
- **预期结果**：任一链路断掉都能从日志/表看出。
- **边界条件**：读数不可用标 degraded，不用 0 冒充。

**验收标准**：
1. 两个套件无新增红；
2. 三条读数各给一条真实查询样例。

## 失败与并发路径

- **waker 不可用**：该计划 overdue+1，其余继续；不重试轰炸（下周期再试）。
- **重复唤醒**：唤醒成功后 review_due_at 前移，同周期不被重复选中。
- **成交回执乱序/重复**：按 trade_id 幂等；跨批成交按累计比例顺序退役；找不到批次记 degraded。
- **消息重复扫描**：news_id+symbol 24h 去重；并发扫描用唯一约束兜底（冲突跳过）。
- **规则退役失败**：记录错误、保留待办未收敛，SLA 继续催（不静默当已执行）。

## 边界（不做什么）

- **不自动下单**：三条链路只到指令/待办/唤醒，执行仍由 agent 终判（延续 D-1）；
- **不改消息分级**：复用既有 critical/soft 词表；
- **不做实时资金流/板块新指标**：本轮只接线；
- **不改 core_plan**：批次生成不在范围；
- **不做 UI**：sides 仅 backend。
