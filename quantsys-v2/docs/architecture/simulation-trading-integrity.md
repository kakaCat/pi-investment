# 模拟交易链路的三条真话原则（QuantSys V2）

**来源**：[REQ-261004154902-a7cd](../requirements/REQ-261004154902-a7cd/requirement.md)（2026-10-04）

## 一句话

模拟交易链路里**只允许一种成功**：真的干了、没出错、且不是被跳过；
任何"看起来成功"的路径（异常被吞、内层失败被当成功、账本凭空多钱）都必须当场暴露。

## 为什么会有这一页（2026-10-04 的取证）

V13 策略在用户眼里「经常罢工、不交易、不发信息」，取证发现的**不是策略本身的问题**，
而是四条"永远报成功"的通道：

| 症状 | 真正的原因 |
|---|---|
| 调仓后从没收到过通知 | 通知方法被误缩进在 `if __name__ == '__main__':` 块里 → 每次调仓走到最后一步必抛 `AttributeError`，**而钱已经下单了**，异常被吞 |
| 调仓失败但看板显示成功 | 日检丢弃了调仓的返回值；调度层又只看顶层键 → 内外两层都报成功 |
| 长假里开火、复市首日不动 | 交易日判定用的是"近 7 日有无 K 线"启发式，把 10-05/06/07 判成交易日、10-08 判成休市 |
| 通知一律发不出去 | 渠道选择把「支持」当「存活」用：agent 渠道恒报支持 → 候选渠道只剩 agent，而 8080 早已下线 → 调仓/风控类通知 **100% 丢弃** |

## 原则一：结果契约只有一个判定入口

- 唯一实现：`application/observability/run_outcome.py` 的 `RunOutcome`。
- 三态：`success` / `skipped` / `failed`；判定规则是「**执行完成 且 无错 且 原因不在跳过集合**」。
- **失败一律不计为已执行**（`executed=False`）：禁止出现"失败了但说我执行过"的旧形状。
- 谁要判断一条链路成没成，就问它；不要在各处自己拼 `success` 键。

## 原则二：失败必须有人看见，且只能有一个出口

- 唯一出口：`application/observability/failure_sink.py` 的 `report_failure(...)`
  （内部走既有通知门面，**自身绝不抛异常**——报错的动作不能把业务带崩）。
- 调度任务失败、挂单超期作废、撮合内部异常、超卖拦截取数失败——全部经它外发。
- **通知不应答也要有记录**：发信返回值必须被消费；"没发出去"要和"失败"一样进账。
- **不许把告警做成噪音**：同一失败不重复发（agent-os 关闭是既定架构，不是异常，
  见 [ADR-004](../adr/004-scheduling-ownership.md)）；判据上线一律先 `report` 清点再切告警。

## 原则三：账本只有一个真源，且必须自洽

- 真源是**交易流水净额**（`quant.simulation_trades`）：`Σ买入 - Σ卖出 >= 本次卖出量`。
  卖出前硬校验，不足即拒绝（原因可识别）。持仓表只应由流水派生，不能反过来当依据。
- 只读对账器：`tools/reconcile_sim_account.py --account <账户>`
  输出逐标的净额、现金重放差额与逐项解释、超卖清单；退出码 `0` 自洽 / `2` 有矛盾 / `3` 工具自身出错。
- **现金自洽 ≠ 账本正确**：两者必须分开报（本项目实测出现过"现金只差 1 分，
  但 4 只标的累计卖出多于买入、凭空多出 ¥49,424.96"的情形）。
- 历史脏数据**只登记不修改**：`config/known_dirty_simulation_data.json` 声明式排除，
  被排除项仍要打印（排除 ≠ 隐藏），删掉清单即回到旧口径。

## 配套的两个"防假绿灯"门禁（本仓通用，不限本链路）

| 门禁 | 命令 | 防的是什么 |
|---|---|---|
| 用例返回值扫描 | `venv/bin/python tools/check_fake_green_tests.py --new-only` | 用例体里 `return True/False` 让 pytest 报 passed（结构性假绿灯）；基线 37 处只许降不许升 |
| 调度/漏跑盘点 | `venv/bin/python tools/check_should_have_run.py` | 任务"该跑没跑"却无人知道；退出码 0/2/3 |
| 链路一眼看 | `venv/bin/python tools/check_v13_chain_health.py` | 调度/交易/通知三面实况；一条命令三张表 |
| 配置单源 | `venv/bin/python tools/check_strategy_config_effective.py` | "声明 ≠ 生效"（日志说 8 只、实际 5 只） |

> 这四条的共同点：**把"我觉得没问题"换成一个会返回非零退出码的判据**。
> 新增判据时请照这个形状做（可注入依赖、退出码语义明确、自身出错要响亮）。

## 已知残留（不要当成已修复）

1. `StrategyExecutor.execute_all` 的顶层 `success` 键仍是旧口径（逐条目已不说谎）。
2. `simulation_positions` 与 `simulation_trades` 的**双源问题未消除**，只做了"不再新增虚增"。
3. 分层纯净性门禁有 1 处历史违规（属另一需求的未跟踪文件），基线未调。
4. 探针的调度活性判据默认 `observe`（只记账不外发），切告警的时机留给人。
5. 真实渠道外发未做端到端验证（测试期按纪律零外发）。
