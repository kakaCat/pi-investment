# Watch 规则完整指南

## 概述

Watch 规则是盯盘引擎的核心配置，支持价格预警、涨跌幅监控、持仓止损止盈、量能异动、瞬时涨速等场景。规则触发后系统自动通知（飞书/Agent），无需人工盯盘。

---

## 支持的条件类型

### 1. 单一条件（简单字符串格式）

#### 1.1 价格突破 (price_break)
- **格式**：`price>阈值` 或 `price<阈值`
- **语义**：`price>100` = 价格上破 100，`price<90` = 价格下破 90
- **示例**：
  - `price>2000` — 茅台突破 2000 元
  - `price<18.5` — 中远海能跌破 18.5 支撑位

#### 1.2 涨跌幅 (pct_change)
- **格式**：`change_pct>阈值` 或 `change_pct<阈值`
- **语义**：相对昨收的涨跌幅（%）
- **示例**：
  - `change_pct>5` — 涨幅超过 5%
  - `change_pct<-3` — 跌幅超过 3%

#### 1.3 盈亏比例 (pnl_pct)
- **格式**：`pnl_pct>阈值` 或 `pnl_pct<阈值`
- **语义**：相对成本价的盈亏比（%），需配 `cost_price` 参数或自动取持仓成本
- **示例**：
  - `pnl_pct<-8` — 持仓亏损达 -8%（止损）
  - `pnl_pct>10` — 持仓盈利达 +10%（止盈）

#### 1.4 量能倍数 (volume_surge)
- **格式**：`volume_surge>倍数`
- **语义**：当前成交量 ≥ 同期 20 日均量的 N 倍（根据已过交易时间比例调整基线）
- **示例**：
  - `volume_surge>4` — 成交量放大 4 倍（异动监控）
  - `volume_surge>1.5` — 成交量放大 1.5 倍（温和放量）

#### 1.5 瞬时涨速 (velocity)
- **格式**：`velocity>波动幅度/窗口分钟数`
- **语义**：窗口内价格波动的绝对值（%）
- **示例**：
  - `velocity>2/15` — 15 分钟内波动 ≥ 2%（急拉/急跌）
  - `velocity>3/30` — 30 分钟内波动 ≥ 3%

### 2. 复合条件（JSON 格式，Phase 2）

#### 2.1 复合条件结构

```json
{
  "type": "combined",
  "params": {
    "operator": "AND",  // "AND" 或 "OR"
    "conditions": [
      { "type": "条件类型1", "params": {...} },
      { "type": "条件类型2", "params": {...} }
    ]
  }
}
```

#### 2.2 Operator 语义

- **AND（双重确认）**：所有子条件同时满足才触发
  - 用途：减少假信号，提高可靠性
  - 示例：放量突破（价格突破 **且** 成交量放大）

- **OR（多路触发）**：任一子条件满足即触发
  - 用途：多个退出条件，任一达到都要处理
  - 示例：止损或止盈（跌幅达 -8% **或** 涨幅达 +15%）

#### 2.3 嵌套深度限制

- **最大嵌套深度**：3 层
- **原因**：防止性能问题与可读性下降
- **示例**：
  - ✅ 合法：combined(AND) → [price_break, volume_surge]
  - ✅ 合法：combined(AND) → [combined(OR) → [...], price_break]（2 层）
  - ❌ 非法：4 层嵌套（超过限制）

## 完整示例

### 示例 1：放量突破（AND）

**场景**：中远海能 19.85 是关键压力位，单纯突破可能是假突破，需要放量确认。

```json
{
  "type": "combined",
  "params": {
    "operator": "AND",
    "conditions": [
      {
        "type": "price_break",
        "params": {
          "direction": "above",
          "price": 19.85
        }
      },
      {
        "type": "volume_surge",
        "params": {
          "multiple": 1.5
        }
      }
    ]
  }
}
```

**触发条件**：价格 ≥ 19.85 **且** 成交量 ≥ 1.5 倍同期均量  
**消息示例**：`AND 组合：现价 19.88 ≥ 阈值 19.85（上破） 且 成交量为同期均量 1.72x（阈值 1.5x）`

---

### 示例 2：止损或止盈（OR）

**场景**：大盘蓝筹持仓，止损 -8% 或 止盈 +15%，任一触发都要处理。

```json
{
  "type": "combined",
  "params": {
    "operator": "OR",
    "conditions": [
      {
        "type": "pct_change",
        "params": {
          "direction": "below",
          "pct": -8.0
        }
      },
      {
        "type": "pct_change",
        "params": {
          "direction": "above",
          "pct": 15.0
        }
      }
    ]
  }
}
```

**触发条件**：涨跌幅 ≤ -8% **或** 涨跌幅 ≥ +15%  
**消息示例**：`OR 组合：涨跌幅 -8.23%（阈值 below -8.0%） 或 涨跌幅 3.45%（阈值 above 15.0%）`

## 性能考虑

### 评估成本

- **单一条件**：O(1)，轻量级
- **复合条件**：O(N)，N = 子条件数量
- **嵌套复合条件**：递归评估，成本 = 所有叶子条件之和

### 自适应频率升档

Watch Engine 使用 `distance_ratio`（距离触发的归一化距离）自适应调整评估频率：
- 距离远（> 0.2）：30 秒周期（正常模式）
- 距离近（≤ 0.2）：10 秒周期（快速模式）
- 已触发（= 0）：立即通知，冷却期 5 分钟

复合条件的 distance：
- **AND**：取所有子条件的 **最大** distance（瓶颈）
- **OR**：取所有子条件的 **最小** distance（最容易达到的）

## 最佳实践

### 1. 选择合适的 Operator

- **AND**：用于"双重确认"，减少假信号
  - 适用：放量突破、技术面 + 基本面共振
- **OR**：用于"多路退出"，确保及时响应
  - 适用：止损或止盈、多个风险信号

### 2. 避免过深嵌套

- ✅ **推荐**：2 层以内（如 combined → combined → 单一条件）
- ❌ **不推荐**：3 层及以上（影响可读性与性能）
- **替代方案**：拆分为多条规则，或简化条件逻辑

### 3. 合理设置阈值

- **价格突破**：选择关键技术位（支撑/压力/整数关口）
- **涨跌幅**：根据标的波动特性调整（大盘蓝筹 3-5%，小盘成长 5-10%）
- **止损**：大盘蓝筹 -8%，成长股 -10%，小盘/题材 -12%
- **放量倍数**：温和放量 1.5x，显著放量 2-3x，异动 4x+

### 4. 归属账户规范

- **持仓相关规则**（止损/止盈/盈亏监控）：必须指定 `account`（如 `agent_virtual`）
  - 规则显示在对应账户的盯盘中心
  - `pnl_pct` 未传 `cost_price` 时自动取该账户持仓成本
- **候选观察规则**（价格预警/量能异动）：`account` 可选（不传=通用观察，各账户看板均可见）

## 技术细节

### 后端实现

- **文件**：`quantsys-v2/application/services/watch_engine/conditions.py`
- **核心函数**：
  - `validate_condition(cond, depth=0)`：递归校验条件结构，depth 防止无限递归
  - `evaluate(cond, quote, ctx, now)`：递归评估条件，返回 `EvalResult`
  - `_eval_combined(params, quote, ctx, now)`：复合条件评估器
- **常量**：`MAX_NESTING_DEPTH = 3`

### 前端工具

- **包**：`@pi-investment/intelligence`
- **工具**：`watch_manage`
- **参数 `condition`**：
  - 简单条件：字符串格式（如 `"price>100"`）
  - 复合条件：JSON 字符串（`JSON.stringify({type: 'combined', ...})`）
- **validate**：前端基础校验（JSON 解析 + 结构检查），后端完整校验（递归 + 深度限制）
