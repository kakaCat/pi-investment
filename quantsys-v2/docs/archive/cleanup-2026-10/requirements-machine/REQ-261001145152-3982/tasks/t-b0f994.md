## 汇报 1（2026-10-01T09:09:36.137Z，窗口 session-7fc133ad-e896-4aa2-9cb5-443ac7c5af22）

研发段：**探针做出来了、正反例都验过**（健康放行、服务不可达与数据过期都会触发告警并 exit 2）；但实测撞到一个更根本的问题——**告警根本发不出去**：这台环境没配飞书渠道，唯一渠道指向已停的 Agent OS，所以"服务死了会告警"目前仍不成立，必须先修告警出口。

### 完成项

- 新增 tools/health_probe.py：外部探针，做两件不依赖被监控进程的事——① socket 连 5001/8080 判存活；② 直连 PG 查 max(trade_date) 判新鲜度（复用服务自身的 _last_trading_day 口径，import 失败则退化为工作日回退）
- 退出码 fail-loud：0 健康 / 2 异常（已尝试告警）/ 3 探针自身出错——避免"exit 0 但什么都没查"的老问题
- 新增 deployment/launchd/com.pi-investment.health-probe.plist（**未安装**，StartInterval=300 与"5 分钟内告警"口径一致）；plutil -lint 通过
- 正例：健康状态 exit 0 且不发告警（实测 kline_latest=09-30、factor_latest=09-30、lag_days=1）
- 负例①：--api-port 5999（未监听）→ 构造出正确告警并 exit 2
- 负例②（卡片点名口径）：--max-lag-days 0 → 因今日 10-01 休市 lag=1 → 立即判过期并构造告警
- 实现中修正自己两处契约错误（首版会直接 TypeError）：门面不能裸构造（改走 NotificationFactory.get_instance()）；send_alert 签名是 (alert_type, symbol, message, data, mention) 而非 (title, message, level)，改用 send_text
- **如实报出阻塞**：告警出口当前不可用——Feishu 渠道仅在 settings.external.feishu_webhook_url 存在时注册（notification_factory.py:164），而 .env 里没有任何 FEISHU_* 键；唯一渠道 agent→Agent OS(8080) 不可达 ⇒ 真实发送返回 `{"attempted": true, "ok": false}` 且日志 `所有渠道发送失败`。故卡片验收里的"收到飞书告警"**在当前环境无法达成**，需先配 FEISHU webhook 或让 Agent OS 在线
- 附带发现：既有 launchd 模板里写的是 /Users/yunpeng/... （另一台机器的路径），在本机不可能生效
