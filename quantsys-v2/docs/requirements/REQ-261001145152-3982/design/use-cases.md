## UC-1 人类排期 <!-- serves: FR-6 -->

- **用例角色**：项目所有者（人类），时间有限，要的是"先做哪三件"。
- **前置条件**：报告与清单已落盘（本设计两文件）。
- **交互流程**：
  1. 读 TL;DR 四层图 → 知道 P0 是"服务停了 18 天"而不是"代码乱"；
  2. 读总览表 → 10 个维度的实测值与判定色块；
  3. 读清单 TL;DR 的"如果只能做三件" → `P0-1` → `P1-1` → `P2-1`；
  4. 抽查 2~3 条复现命令（TC-1/TC-3/TC-4）确认报告可信；
  5. 在拆分阶段裁定批次范围（可只批 P0+P1）。
- **异常流**：
  - 若抽查命令输出与报告不符（如环境已变）→ **以实测为准**，要求报告条目返工，而非按报告硬做；
  - 若认为 P0 的"救活服务"不属本需求范围 → 拆成独立需求，本需求只保留代码侧条目；
  - 若只想先清垃圾（P3-3 的 5.2G）→ 批次可乱序执行（P3 与 P2 无依赖）。
- **后置条件**：一份被批准的批次范围 + 明确的第一批条目。
- **完成标志**：`reqboard_submit(kind=plan)` 的计划被批准（拆分阶段）。

## UC-2 Agent 领任务实施 <!-- serves: FR-3, FR-6 -->

- **用例角色**：后续窗口的 agent，领到一张条目卡（如 `P1-3 删重复实现`）。
- **前置条件**：计划已批准并落库为任务卡；`depends_on` 的前置条目已完成（如 `P1-3` 依赖 `P1-1` 的测试基线）。
- **交互流程**：
  1. 读卡上的 `acceptance`（来自本清单的 `verify` 字段，已是可执行命令）；
  2. 先跑**删除前基线**：`python -m pytest tests/test_pipeline.py tests/test_integration.py -q`；
  3. 执行删除（`infrastructure/quantlib/adapters/` 6 模块 + `core/{base_calculator,exceptions}.py` + 13 个 `.bak`）；
  4. 跑**同一命令**比对结果；
  5. 跑卡上 `verify` 的其他断言（如 `grep` 零引用）；
  6. `reqboard_task_report` 汇报：改了哪些文件、命令输出摘要。
- **异常流**：
  - 删除后测试**变红** → 说明该文件并非零引用（静态扫描误判）→ **立刻恢复**（`git checkout --`）并在卡上留痕，改用"逐个人工确认"路径；
  - 发现 `core/pipeline.py` 这类"逐字重复但有测试依赖"的例外 → 跳过该文件，把例外写进汇报（本清单已预先标注）；
  - 环境缺依赖导致命令跑不起来 → 先做 `P1-1`，不要在无基线的情况下动 P1-4/P2-*。
- **后置条件**：可删行数下降、测试基线不退化、`grep` 断言通过。
- **完成标志**：卡上全部 `verify` 命令通过 + 汇报落盘。

## UC-3 新会话 / 新人接手 <!-- serves: FR-1, FR-5 -->

- **用例角色**：新窗口 agent 或新协作者，按 `CLAUDE.md` 开工。
- **前置条件**：无（这正是问题所在——现有文档会把他带偏）。
- **交互流程**：
  1. 按 CLAUDE.md 找入口 → `api/server.py` **不存在**；
  2. 按 CLAUDE.md 装依赖 → `pip install -r requirements.txt` **根目录无此文件**；
  3. 按 CLAUDE.md 读数据访问规范 → `DATA_ACCESS_GUIDE.md` **不存在**；
  4. 按 CLAUDE.md 重启服务 → `launchctl kickstart ... com.pi-investment.v2-api` **plist 不存在**；
  5. 查 `infrastructure/repositories/` → **空**（真实位置是 `adapters/outbound/repositories/`）。
- **异常流**：
  - 每一步都"文档说 A、实际是 B"→ 按 audit-report §5.6 的 8 条矛盾表改用真实路径；
  - 若在新窗口跑 `pytest` 想确认环境 → 遇到 119 个 collection error → 按 TC-3 归因（缺 3 个包），**不要**以为是自己的环境问题。
- **后置条件**：新人/新会话用正确路径完成一次取数或一次测试运行。
- **完成标志**：`P3-4`（修 CLAUDE.md 8 条矛盾）完成，且 §5.6 的 8 条命令逐条复核通过。
