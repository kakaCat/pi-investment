# REQ-261006163444-8e4f · 数据质量告警去伪：D级计数按当日行数重复计数 + 检查域混入退市股

**需求ID**: REQ-261006163444-8e4f
**类型**: feature（立项弹框作答所得；**实质是告警口径缺陷修复**——范围见 D-2/D-3/D-4）
**作用域**: `quantsys-v2/`（`infrastructure/jobs/data_quality_check_job.py` 为主，`adapters/outbound/repositories/kline_quality_repository.py`、`application/services/data_quality_service.py`、`application/services/data_gap_detector.py` 为口径面，`tests/`）
**侧**: backend（无前端产出，不涉及原型）
**档位**: expert（立项弹框作答所得）

## TL;DR

**现象**：2026-10-06 13:54:21 飞书收到「数据质量告警（3 项）」——D级 806 只 / 评分 86.28 < 95 / 回填失败率 71.4%。

**结论：三项没有一项代表「数据变差了」。** 三个数字分别是三处口径缺陷的产物：

| 告警项 | 表面值 | 真值 | 机制 |
|---|---|---|---|
| D级股票数量过多 | 806 只 | **404 只**（域内仅 3 只） | `count_by_grade_on` 数**行数**不数标的；当天跑了两次（00:00 自动 + 13:48 手动）→ 403×2 = 806。**只跑一次就是 403 < 500，本不该告警** |
| 数据质量评分偏低 | 86.28 | 域内 **90.84** | 检查域 = `daily_klines` 全部 distinct symbol（5686），混入 351 只窗口内 0 数据 + 49 只中途停更的标的一起算均值 |
| 回填失败率过高 | 71.4% | 5/7（分母无效） | 回填目标取自被截断的 50 条明细；7 只里 5 只已退市（000013/000602/000606/000939/002288），数据源永远取不到；且按缺失天数降序排 → **死标的排最前** |

**阈值 95 在现口径下数学上不可达**：评分上限 = `0.6×覆盖率 + 40`；全库覆盖率 91.70% 时上限恰为 **95.02**（旧口径实测 95.01 正是此值）。异常检测修好后真实异常开始扣分，均值必然跌破 95。

**本需求要做的（按 D-2/D-3/D-4）**：① 检查域**分域**（可交易域 / 观察中 / 存量），三项指标只在可交易域内算并据此告警；
② 告警计数改 **distinct 标的**；③ 阈值随口径重定；④ 加**掉出域变化**告警防"采集漏批被新口径静默豁免"；
⑤ 回填范围与失败率样本有效化；⑥ 修 `original_count` 取错键（恒 0）。

## L1 一句话目标 + 可证伪判定标准

**目标**：让「数据质量告警」只对**真正在交易的那批标的**说话——读数真实、样本有效、掉出必亮相；
不再用退市股和重复运行刷出红灯。

**可证伪判定标准**（跑什么、看到什么算过，逐条对应下方 FR）：

1. **分域判据可复算**：`select count(distinct symbol) from quant.daily_klines where trade_date = (select max(trade_date) from quant.daily_klines)` = **5280**；
   且观察中（1–4 个交易日无数据）= **3 只**、存量（≥5 个交易日无数据）= **403 只**，三层合计 = **5686**（以 2026-10-06 数据为准，允许随真实行情漂移 ±）。
2. **计数去重**：同一天连续跑两次检查后，`count_by_grade_on('D')` 返回 **distinct 标的数**（今天口径 806 → 404），
   与 `select count(distinct symbol) from public.kline_data_quality where created_at::date=current_date and grade='D'` 相等。
3. **告警只在域内触发**：单跑一次后告警正文里 D级 = **3 只**、评分 ≈ **90.84**，
   **不出现**「D级股票数量过多」与「数据质量评分偏低」两条；平均覆盖率按域内报（≈98.54%）。
4. **掉出域必亮相**：构造"上期在域、本期不在"的样本（如剔除 3 只标的的末日 K 线）→
   告警正文出现「本期掉出可交易域 3 只」及名单；连续 ≥5 个交易日无数据的转入存量后**不再逐日重复出现**。
5. **回填样本有效**：回填目标 100% 落在可交易域（可用 SQL 核）；分母 < 10 时**不判**失败率；
   非可交易域 0 次回填尝试（今日基线：5 次无效尝试 + 374 条 `All data providers failed` 噪音 → 应为 0）。
6. **审计列修好**：新写入行的 `original_count` = 窗口交易日数（非 0）；今日基线该列**全部为 0**。
7. **既有回归不破**：`tests/test_data_quality_job_guardrails.py` 全过；`count_by_grade_on` 的既有调用形态
   （不传新参数）行为不变。

## 边界

### 做什么

1. **分域**：把检查域拆成三层，以**数据事实**为准（D-3）——
   **可交易域** = 最后一个交易日（DB 全市场 `max(trade_date)`）当日有 K 线的标的；
   **观察中** = 连续 1–4 个交易日无数据；**存量** = 连续 ≥5 个交易日无数据（含已标退市/停牌）。
2. **三项指标改口径**：D级数量 / 评分均值 / 覆盖率均值**只在可交易域内**统计并据此告警（D-2）。
3. **计数改 distinct 标的**：`count_by_grade_on` 由"按 `created_at` 日期数行"改为"数 distinct symbol"，
   消除"同日多跑一次即翻倍"。
4. **阈值随口径重定**：D级 > 20 只（域内现值 3）、评分均值 < 88.0（域内现值 90.84）、
   覆盖率均值改为**信息项**（域内现值 98.54%，不单独告警）；回填失败率仍 50%，但**分母 n ≥ 10** 才判。
5. **掉出域变化告警**（防漏采，D-4）：报告「本期掉出可交易域 N 只」；新掉出（观察中）名单进告警正文（warning 级）；
   连续 ≥5 个交易日方转存量，转存量后不再逐日重复。
6. **回填范围与样本**：回填目标只在可交易域内选取（存量/观察中**不尝试**回填）；
   失败率分母只数域内目标；跳过数另列信息项。
7. **修 `original_count` 取键**：改取 `total_trading_days`（现取不存在的 `expected_days` → 恒 0）。
8. **回归锁 + 实跑复验**：新增用例覆盖分域/去重/阈值分支/掉出名单/回填门槛/审计列；
   实跑一次产出告警正文与 run 结果作为证据。

### 不做什么

1. **不修那 239 只「无数据但未打标」标的的 `is_delisted` / `is_suspended` 标记**（D-4 明确排除，用户选 A 未选 B）：
   逐只核对数据源补标属独立工作量，进后续线 1；本需求用 FR-3 的掉出域检测替代"靠标记定义域"。
2. **不改评分公式**（异常率/重复率权重、`threshold=3.0`、等级分数线 A+/A/B/C/D 的 99.5/95/90/80）——
   异常率项的口径属 REQ-261006133733-1fdf 的范围。
3. **不改检查窗口与排班**：`MAX_CHECK_DAYS=90` 钳制、`0 0 * * *`、`policy=holidays` 均不动。
4. **不回填历史行**：`kline_data_quality` 里已写入的 `original_count=0` 不追改（只在阅读旧数据时说明）。
5. **不新增告警渠道**：仍走 `NotificationFacade`（飞书 + agent），只改内容与触发条件。
6. **不动 `min(50)` 明细截断本身**（它是服务层返回上限）；只把**告警统计与回填范围**与它解耦——
   统计口径改为基于全量 `gaps`，而不是被截断的 `stocks_with_issues[:50]`。

### 边界理由

- **为什么必须分域而不是只改阈值**：死标的 400 只永久占据 D 级配额（500 阈值的 80%），且把平均覆盖率从 98.54% 拉到 91.70%、
  把评分从 90.84 拉到 86.28——不改域，任何阈值都只是把红灯调暗，读数依旧误导。
- **为什么排除补标记（B 选项）**：补标要逐只联网核对 239 个标的（可能长跑），且**标记只覆盖死标的 46%**，
  即使补完也不足以独立定义域；而"最后交易日有无 K 线"这一数据事实零污染、覆盖 100%。
- **为什么要掉出域告警**：新口径会把"无数据"的标的移出分母——若那其实是**采集管道漏了一批**，
  就会被静默豁免。FR-3 保证任何"新掉出"都亮相，把"新口径掩盖事故"的风险堵死（R3）。
- **为什么回填要限域**：对退市标的回填是**必败**动作（今日 5/7 失败、374 条噪音、白烧 93 秒），
  且它的失败率被当成数据源健康度指标——这是把"标的已死"误读成"数据源不可用"。

## 产品定义

### 一句话

让数据质量告警**说真话**：分母是真正在交易的标的，样本量够得着结论，掉队的标的一个都不会悄悄消失。

### 为什么现在做

1. **告警已经不可信**：三项全部误报/失真，其中 D级 806 是纯粹的重复计数——这会训练人忽略真实数据缺口。
2. **阈值数学上不可达**：95.0 与现口径上限 95.02 只差 0.02 分，等价于"永久红灯"。
3. **异常检测修复后必然恶化**：REQ-261006133733-1fdf 让异常率项真实扣分，均值从 95.01 掉到 86.28——
   不重定口径，这条告警会每天红。
4. **回填被浪费在必败目标上**：按缺失天数降序 → 退市股排最前 → 额度与墙钟预算被吃光，真需要补的标的排不上。
5. **改面可控**：集中在告警检查函数 + 一个仓储计数方法 + 回填目标选取，无表结构变更。

### 成功长什么样

- 告警正文形如：「数据质量告警（1 项）· 检查域：可交易 5280 / 观察中 3 / 存量 403 · D级 3 只 · 评分 90.84 · 覆盖率 98.54%」；
- 域内数据健康时**不告警**；域内真的退化（D级 > 20 或评分 < 88）才告警；
- 「本期掉出可交易域 N 只」永远有数，新掉出名单可见；
- 回填只对活标的开火，失败率分母 ≥ 10 才有判定，退市标的产生 0 条 `All data providers failed`。

## 用户与角色

- **项目所有者（人类）**：判断标准是"告警不再天天红、红了就真有事、退市股不占配额"。
- **窗口 AI Agent（本需求实施者）**：改动集中在 `_check_quality_alerts` 与回填目标选取 + 一个仓储计数方法 + 用例。
- **后续维护者 / 新会话**：需要一条明确规则——**告警指标的"分母"必须是可交易域，且分母口径变更必须同步重定阈值**；
  另需知道 `is_delisted` / `is_suspended` 当前**不可信**（覆盖率 46%），不得作为域判据。

## 功能点（G2 条款）

**FR-1: 检查域分域（可交易域 / 观察中 / 存量）**
以「最后一个交易日（`select max(trade_date) from quant.daily_klines`）当日是否有 K 线」判定可交易域；
未在域内的按"连续无数据交易日数"分为**观察中（1–4 日）**与**存量（≥5 日，含已标退市/停牌）**。
三层的计数与存量名单写入 run 结果与告警正文。
判据：域内计数 = 5280（2026-10-06 数据）、观察中 = 3、存量 = 403，三层合计 5686，可由 SQL 独立复算。

**FR-2: 三项指标改按可交易域统计，且计数按 distinct 标的**
① D级数量、评分均值、覆盖率均值只在可交易域内计算，并据此判定告警；
② `count_by_grade_on` 改为数 distinct symbol（同日多次运行不再翻倍）；
③ 统计口径基于**全量**缺口结果，不再受 `stocks_with_issues[:50]` 截断影响。
判据：同日两跑后 `count_by_grade_on('D')` = 404（今日行数口径为 806）= `count(distinct symbol)`。

**FR-3: 掉出域变化必须亮相（防"采集漏批被静默豁免"）**
每次检查报告「本期掉出可交易域 N 只」（上期在域、本期不在）；新掉出（观察中）名单进告警正文，warning 级，
**不得报 error**；连续 ≥5 个交易日无数据转存量后**不再逐日重复出现**。
判据：构造剔除 3 只标的末日 K 线的样本 → 正文出现该 3 只；存量标的次日不重复出现在正文。

**FR-4: 阈值随口径重定 + 回填样本有效化**
① 阈值：D级 > **20 只**、评分均值 < **88.0**、覆盖率均值改信息项；回填失败率仍 50% 但**分母 n ≥ 10** 才判；
② 回填目标**只在可交易域内**选取（存量/观察中不尝试），跳过数另列信息项，不计入失败率；
③ 阈值标定依据随文档登记（域内现值 D级 **3** 只 / 评分 **90.84**），并**登记上线后重标定条款**：
本仓 `kline_data_quality` 只有 2 次全市场运行（E13），阈值属"锚定当前域分布"的临时值，
须在累计 **≥10 个交易日**的域内分布后重新标定一次（重标定结果回写本文档与本 FR）。
判据：域内现值 3 只 / 90.84 → 单跑后两条告警不出现；回填目标经 SQL 核对 100% 在域内，非域内尝试 0 次。

**FR-5: 修 `original_count` 取键（现恒 0）**
`_persist_quality_audit` 改取 `gap_info['total_trading_days']`（现取不存在的 `expected_days`）。
历史行不追改，仅在文档与注释里说明"2026-10-06 之前的 `original_count` 恒 0、不可用"。
判据：单跑后抽样新写入行 `original_count` = 窗口交易日数（> 0）。

**FR-6: 回归锁与实跑复验**
新增用例至少覆盖：分域判据（含边界 4/5 日）、distinct 计数（同日两跑不翻倍）、阈值三分支、
掉出域名单与"不重复"、回填分母门槛、`original_count` 非 0、`count_by_grade_on` 向后兼容；
并实跑一次质量检查，产出告警正文与 run 结果两份证据。
判据：`./venv/bin/python -m pytest <新增用例> tests/test_data_quality_job_guardrails.py -q` 全过。
