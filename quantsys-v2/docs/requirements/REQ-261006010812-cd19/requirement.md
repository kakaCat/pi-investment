## L1 一句话目标 + 可证伪判定标准

**目标**：把「a7cd 的设计文档说了什么」与「这台机器上真在跑什么」逐条对上，
判定分四档 —— **已实现且一致 / 已实现但语义偏离 / 未实现 / 无法判定**，并把每条判定的证据钉到 `路径:行号` 或一条可复跑命令上。

**判定标准（可跑）**：
1. 报告里**不存在**没有证据的判定：任意抽查 5 条判定，其引用的 `文件:行号` 打开后内容与判定相符，或所引命令原样复跑得到所述结论；
2. `design.md` §12 的 **7 条验收命令逐条有真实退出码 + 输出摘要**（写明「实跑」或「不可跑 + 原因」，不得写「预期」）；
3. 验收命令里引用的**每一个工具/测试路径**都在盘上存在性已核（存在 / 缺失 + 缺失影响）；
4. 缺口清单 ≥3 条，每条带证据与风险等级；改进项清单每条带可证伪判据（跑什么 / 看到什么算过）。

## 产品定义

本需求的产品是**一份可被第三方复核的审计报告**，不是代码、不是修复。
对下游（项目所有者、后续接手 V13 的人、agent 投资脑）而言，它的价值在于：
- 读完能知道 a7cd 的哪几条设计**真的落地了**、哪几条只是文档；
- 读完能知道**照这份设计继续干**有没有坑（例如它写的回滚路径、它引用的验收命令）；
- 读完能知道 V13 链路上**还剩什么没被这份设计管住**。

## 功能点（G2 条款）

- **FR-1: 设计文档自洽性审计** —— 对 6 份设计文档做内部一致性检查：同一事实在不同文档/章节取值是否一致、
  文档间引用是否有效、§13 的「未定决策」是否闭环，逐条给「文档:行 ↔ 冲突对象:行」证据。
- **FR-2: 设计与实现一致性审计（逐条落点）** —— 把 `design.md` §1~§11 的每个落点（新增模块 / 接口契约 / 数据行改动 /
  开关 / 回滚路径）映射到实际代码·库表·配置，判定 ∈ {已实现且一致 / 已实现但语义偏离 / 未实现 / 无法判定}，每条带证据。
- **FR-3: 验收判据可复跑审计** —— 逐条实跑 `design.md` §12 与 `test-cases.md` §6 的验收命令，
  记录真实退出码与输出摘要；对不可跑项（工具缺失 / 需人执行的 T16）标注原因并给出替代判据。
- **FR-4: 设计未覆盖缺口审计** —— 找出该设计**没管住**但仍在风险中的 V13 相关链路，
  逐条给出证据、影响面与风险等级（不修，只列）。
- **FR-5: 审计报告产物** —— 产出 `audit-report.md`，结构含：结论摘要表 / 逐条一致性矩阵 / 验收命令复跑表 /
  缺口清单 / 改进项清单；每条判定必须可回溯到证据。
- **FR-6: 可证伪改进项清单** —— 每条改进项写清：问题 / 证据 / 建议动作 / **可证伪判据**（跑什么、看到什么算过）/ 优先级；
  禁止只给结论不给判据。

## 接口与数据契约（feature 档必填）

- **产物路径**：`docs/requirements/REQ-261006010812-cd19/audit-report.md`（单份报告，不拆多文件）。
- **报告结构契约（五个一级节，缺一即不合格）**：
  1. `## 结论摘要` —— ≤10 行：被审设计的整体判定 + 最严重的 3 条；
  2. `## 一致性矩阵` —— 表：设计条目（`design.md:行`）| 判定（四档）| 证据（`路径:行` 或命令）| 说明；
  3. `## 验收命令复跑` —— 表：命令 | 实跑/不可跑 | 退出码 | 输出摘要；
  4. `## 缺口清单` —— 表：缺口 | 证据 | 影响面 | 风险等级；
  5. `## 改进项` —— 表：问题 | 证据 | 建议动作 | 可证伪判据 | 优先级。
- **只读契约**：审计过程不修改被审对象（a7cd 文档、生产代码、生产库）；发现文档与实现不符时，**报告为准、原件不动**。
- **可复跑契约**：报告里出现的每条命令，第三方在 `quantsys-v2/` 下原样执行应得到相同性质的结论（数值可随时间变化，
  结论方向不得随复跑者变化）。
