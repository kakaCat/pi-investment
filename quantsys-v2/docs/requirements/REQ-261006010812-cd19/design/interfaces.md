# 接口与判定契约（REQ-261006010812-cd19）

> 审计的"接口"只有一个：**审计报告**。本文件把它定死到字段级，使第三方能按契约复核。

## 1. 报告文件契约（serves: FR-5）

- **serves: FR-5**
- 路径：`docs/requirements/REQ-261006010812-cd19/audit-report.md`（单份，不拆）。
- 头部 front-matter：`req` / `kind: audit-report` / `title` / `verdict_summary`（整体判定，四档之一）。
- **五个一级节（`##`，缺一即不合格）**：

| # | 节名 | 表/内容 | 行数约束 |
|---|---|---|---|
| 1 | `## 结论摘要` | 整体判定 + 最严重 3 条（各一行，带证据指针） | ≤10 行 |
| 2 | `## 一致性矩阵` | 表：`设计条目(design.md:行)` / `判定` / `证据` / `说明` | ≥1 行/落点 |
| 3 | `## 验收命令复跑` | 表：`命令` / `实跑?` / `退出码` / `输出摘要` | 覆盖 §12 全部 7 条 |
| 4 | `## 缺口清单` | 表：`缺口` / `证据` / `影响面` / `风险等级` | ≥3 行 |
| 5 | `## 改进项` | 表：`问题` / `证据` / `建议动作` / `可证伪判据` / `优先级` | ≥5 行 |

- 二级节可自由增补（如 `## 逐条取证附录`），但**五个一级节必须存在且非空**。

## 2. 判定枚举与判据（serves: FR-2）

- **serves: FR-2**
- 四档**互斥且穷尽**，判定词必须逐字使用：

| 判定 | 判据（满足才可下此判定） |
|---|---|
| `已实现且一致` | 面 B 有落点；实现语义与设计声明**逐字/逐值**相符；涉及数据的另附面 C 或面 D 证据 |
| `已实现但语义偏离` | 面 B 有落点，但字段名/取值/默认值/错误语义/开关名至少一项与设计不符 —— 证据列须写两侧取值 |
| `未实现` | 面 B 按给定搜索口径零命中，且面 E 显示产物未在版本内（或产物不存在）；证据列须写搜索命令与命中数 |
| `无法判定` | 缺证据；证据列须写「缺哪一面、缺什么、为何本次拿不到（引 D-3 边界或时间/环境限制）」 |

- 禁止判定词：`基本一致`/`大致符合`/`疑似`/`应该没问题`（出现即视为不合格，按 `test-cases.md` §1 自检拒收）。

## 3. 证据强度分级（serves: FR-2, FR-3）

- **serves: FR-2, FR-3**
- 每条证据标一个强度等级，**弱证据不得单独支撑强结论**：

| 级 | 形态 | 能支撑到 |
|---|---|---|
| `L1` | 可复跑命令（pytest / 只读检查器 / SQL）——须给命令与真实退出码/行数 | 四档全部 |
| `L2` | 静态定位 `路径:行号` + 原文片段 | `已实现且一致`/`语义偏离`/`未实现` |
| `L3` | 库表/日志快照（须记库名、时间戳、查询语句） | 数据面事实 |
| `L4` | 代码推演（未实跑） | 只可支撑 `无法判定` 的缺口说明，**不得**支撑"已实现" |

- 例：`L4` 写「读代码推断探活会在 ≤2 周期告警」→ 必须标 `无法判定`（缺 L1 实证，因杀进程被 D-3 禁止）。

## 4. 证据记录行契约（serves: FR-2, FR-3）

- **serves: FR-2, FR-3**
- 矩阵每行的「证据」列格式（便于机器抽查）：

```
[L2] application/services/should_have_run.py:41-58 | grep -c 命中 3
[L3] psql quant_investment @2026-10-06T09:5x | select cron_expression from quant.scheduler_tasks where id=249
[L1] venv/bin/python tools/check_should_have_run.py -> exit 0
```

- 一行可带多条证据（`;` 分隔）；**每条证据必须自证其来源**（文件:行 / 命令 / 库名+时间）。
- 行数引用尽量写区间；单点引用写单行号。

## 5. 改进项字段契约（serves: FR-6）

- **serves: FR-6**
- 每条改进项五列必填：
  1. `问题`：一句陈述，含被审设计条目指针（`design.md:行`）；
  2. `证据`：同 §4 格式，≥1 条；
  3. `建议动作`：可执行的最小动作（如「补 `tools/check_trading_day_judgment.py` 或在设计里改口径」）；
  4. `可证伪判据`：**跑什么 + 看到什么算过**（例：`venv/bin/python tools/check_trading_day_judgment.py --dates 2026-10-05,2026-10-06,2026-10-07,2026-10-08` 退出码 0 且输出 False/False/False/True）；
  5. `优先级`：`P0`（阻塞可信性）/`P1`（显著风险）/`P2`（整洁性）。
- **不写"以后优化"式条目**：无判据的改进项一律删掉或降级为"观察项"（另起二级节，不进五列表）。

## 6. 命令复跑记录契约（serves: FR-3）

- **serves: FR-3**
- `实跑?` 列取值仅两种：`实跑` / `不可跑`。
- `不可跑` 必须同行写原因（`文件不存在` / `需生产进程动作（D-3 禁止）` / `需人工维护窗口`），
  并**另起一行**给替代判据（如用纯函数复刻替代实跑，标注为 `L4`）。
- `退出码` 列：实跑填真实数字（含非 0）；不可跑填 `-`。
- `输出摘要` 列：≤80 字，含关键计数（如 `passed 36`、`exit 2 漏跑 1`）；**不得**写"预期通过"。
