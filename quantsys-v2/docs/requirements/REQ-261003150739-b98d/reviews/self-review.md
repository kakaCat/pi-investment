## 3. 遗留与已知限制（不假装全覆盖）

1. **只覆盖模块级 `requests.post/get`**：`requests.Session(...).post` 与其它 HTTP 客户端不经包装器
   （当前通知链不使用 Session）。要覆盖 Session 需另加一道包装——本轮不做。
2. **fail 模式是"新用例必须先打桩"的硬约束**：将来若有测试真的要"真发一次"，
   必须显式声明（设计里预留了 `notify_egress_expected` marker 的位置），
   但**当前 0 处使用**——本轮没有需要它的用例。
3. **未做"通知域端到端真投递"的验收**：本需求的目标就是让测试不外发，
   故生产投递能力用"生产代码零改动 + 既有 135 条通知相关用例全过"来间接保证，
   没有真发一条到飞书/agent 去验证（那正是我们要避免的行为）。
