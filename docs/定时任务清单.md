## 📋 任务分类

### 1️⃣ FastAPI 进程内定时任务（quantsys-v2）

> 位置：`quantsys-v2/adapters/inbound/fastapi_app/daily_jobs_bootstrap.py`
> 执行器：FastAPI 应用内的 BackgroundScheduler

| 任务名称 | 执行时间 | 频率 | 功能说明 | 优先级 |
|---------|---------|------|---------|--------|
| **data_quality** | 17:15 | 周一~五 | 数据质量检查（检查最近30天数据的缺失、重复、异常值）<br>可选自动补充缺失数据 | P2 ⚠️ |
| **freshness_guard** | 17:20 | 周一~五 | K线/因子新鲜度巡检<br>检查最新日期是否滞后 → 飞书告警 | P1 ✅ |
| **evening_pipeline** | 20:30 | 周一~五 | **主力数据同步任务**<br>1. 检查K线新鲜度（幂等保护）<br>2. 分批同步K线（P0+P1+500只最旧，约800只）<br>3. 全市场因子计算 | P0 🔥 |
| **chip_distribution** | 21:10 | 周一~五 | 筹码分布更新<br>使用当日新K线数据 | P1 ✅ |
| **financial_statements** | 20:00 | 周六 | 季度财报更新 | P2 |

**特点**：
- ✅ 支持幂等（避免重复执行）
- ✅ 任务状态持久化到数据库
- ✅ 失败自动告警

## ⚠️ 发现的问题

### 1. **data_quality 任务功能重复**

**问题**：
- `data_quality` (17:15) 检查数据质量 + 可选补充
- `evening_pipeline` (20:30) 已经包含数据同步和补缺
- 功能重叠，增加系统负载

**建议**：
- ❌ 删除 `data_quality` 任务
- ✅ 保留 `freshness_guard` 提供快速告警
- ✅ 依赖 `evening_pipeline` 的多数据源 fallback 保证质量

### 2. **test-cron 任务可删除**

**问题**：
- `/tmp/test-cron.sh` 是测试任务
- 每天 08:00 执行，无实际作用

**建议**：
```bash
crontab -e
# 删除该行：0 8 * * * /tmp/test-cron.sh
```

## 📝 任务执行记录

查看任务执行历史：

```sql
-- 查看最近 7 天的任务执行记录
SELECT 
  job_id,
  run_date,
  status,
  started_at,
  finished_at,
  EXTRACT(EPOCH FROM (finished_at - started_at)) AS duration_seconds
FROM quant.inprocess_job_runs
WHERE run_date >= CURRENT_DATE - INTERVAL '7 days'
ORDER BY started_at DESC;
```

查看失败任务：

```sql
SELECT *
FROM quant.inprocess_job_runs
WHERE status = 'failed'
ORDER BY started_at DESC
LIMIT 10;
```

## 🚨 告警配置

所有任务失败时会通过飞书通知：

- ✅ 任务执行失败 → 飞书告警
- ✅ 数据新鲜度滞后 → 飞书告警
- ✅ 数据源探活失败 → 跳过执行并告警

监控地址：
- 任务状态 API: `http://localhost:8099/api/jobs/inprocess/status`
- 飞书群：（配置在 `application/services/feishu_service.py`）
