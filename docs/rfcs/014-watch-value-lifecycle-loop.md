# RFC 014 · 盯盘闭环设计（v3）

- **状态**：设计定稿 v3（2026-09-11，经用户 8 轮澄清）
- **需求**：REQ-f08def ｜ **作者/窗口**：investor / w-c8cae280
- **上游**：[RFC 013 处置状态机](./013-watch-trigger-disposition-state-machine.md)（Phase 1 已上线并线上验证）
- **本版修掉的 v2 问题**：
  1. **硬冲突**：元触发（一直响/一直不响）永远过不了价格触发的五道门 → 本版给元触发独立轻门
  2. **安全回归**：v2 丢失"宪法动作不得被任何门槛挡住" → 本版恢复为铁律⑤
  3. **目标错位**：v2 用"成本效率"当北极星 → 本版主指标改为**风险调整后收益**
  4. **机制缺口**：补齐"市场状态摘要 / 每日介入预算 / 成本记账"三项
  5. **概念混淆**："判不动"不再一律计噪声（那会诱导乱动）
  6. **结构**：改为直线结构，数据模型合并为一张表，实施顺序与设计一一对应

## 0. 目标与约束（第一性）

**唯一目标：挣高额利润。**

| 项 | 内容 |
|---|---|
| **目标函数** | 风险调整后收益（净值增长 ÷ 最大回撤；辅以胜率 × 盈亏比） |
| **硬约束 1** | 交易宪法（止损铁律、仓位上限、时段、T+1）——**不受任何经济性判断豁免** |
| **硬约束 2** | 成本与利润一致：介入成本（token + 错误风险）必须显著小于期望收益 |
| **推论** | **少而准**。眼睛常睁（感知零成本），脑子少动（介入才有成本） |

> 用户的定调：「所有都让 agent 介入，token 消耗承受不起，会导致利润和成本不一致。」
> 补充事实：在当前账户规模下，**直接 token 成本 ≈ 0.0x 元/次**，而**一次错误动作 ≈ 数百元**。
> 所以砍掉不必要介入的理由是**减少犯错机会 + 保住信噪比**，不是省 token。

## 1. 定位：盯盘是「紧盯市场情况」的工具

**盯盘是 agent 的眼睛，不是只服务持仓的监控器。** 持仓管理只是它的一个用途。

### 1.1 观察对象分四层（scope）

| scope | 看什么 | 典型规则 |
|---|---|---|
| **market** | 指数关键位、涨停家数与连板高度、量能、情绪分 | 指数跌破/站上关键位、涨停家数骤降、情绪转极端 |
| **sector** | 板块资金与轮动、板块强度 | 板块资金异动、板块强度排名突变 |
| **symbol** | 个股趋势/结构/关键位/量价异动（**无论是否持有**） | 趋势观察、突破破位、放量异动、回踩确认 |
| **position** | 买卖节点 | 止损/止盈/减仓/加仓/做T |

### 1.2 关键区分：感知层 vs 介入层（本设计的枢纽概念）

| | 感知层（永远开着） | 介入层（有成本） |
|---|---|---|
| 做什么 | 记录、归档、汇总 | 唤醒 agent、判断、动作 |
| 成本 | **零 LLM** | token + 错误风险 + 注意力 |
| 产出 | 触发记录 + **市场状态摘要** | 规则重配置（可含交易动作） |
| 占比 | 绝大多数触发 | 极少数（见 §3） |

> **盯盘响了但不用做事，是常态而非异常。** 处置状态里的 auto_observed 是主力状态。

### 1.3 感知的产物：市场状态摘要（v2 缺的机制）

市场级/标的级感知不能逐条推给 agent（等于没有感知）。定义固定产物：

| 产物 | 节拍 | 内容 | 成本 |
|---|---|---|---|
| **盘中市场状态** | 交易时段每 30 分钟（仅当有变化） | 指数位置与涨跌、板块资金 Top/Bottom、涨停家数与最高板、量能比、情绪分、我方持仓异动 | 与价格触发**共用同一次唤醒**，不额外增加 |
| **日终感知汇总** | 收盘后 1 次 | 当日全部 auto_observed 摘要 + 待复核规则 + 明日关注位 | ≤1 次 |
| **周度市场复盘** | 每周 1 次 | 规则价值账本 + 卫生审计 + 上周判断对错归因 | ≤1 次 |

## 2. 模型

### 2.1 五条铁律（v2 只有四条，第 5 条为恢复的安全约束）

1. **触发 ≠ 执行**——买卖节点只唤醒 agent，**最终判断必须 agent 做**
2. **每条规则必须挂在某个意图上**——无主规则＝烂账（2026-09-11 清掉的那批正是）
3. **回路没有终点**——清仓后回到「发现价值」
4. **规则不能无限期盯下去**——到期必须被 agent 看一次；反复触发或长期静默都要回到 agent
5. **宪法动作不受任何门槛豁免**——止损铁律、仓位上限、交易时段、T+1 必须执行；
   **不得以"金额太小""要请示用户""等汇总"为由拖延**

### 2.2 规则族（intent）

| intent | 用途 | 触发后 agent 要回答 |
|---|---|---|
| trend_observe | 趋势/结构观察（无交易意图） | 趋势变了吗？继续 / 升级为买入跟踪 / 取消盯盘 |
| entry | 等买点 | 买不买、买多少？（买了同时给出卖出规则） |
| add_position | 加仓 | 加不加、加多少？ |
| t_trade | 做T（围绕底仓区间高抛低吸） | 做不做、区间怎么定？ |
| exit_stop | 止损 | 执行还是调整？（**宪法：触发即须执行，无豁免**） |
| exit_take_profit | 止盈 | 减多少 / 是否全部 |
| exit_reduce | 减仓 | 减多少 |

### 2.3 生命周期

    ①发现价值 ─→ ②跟踪价值 ─→ ③买点触发 ─→ ④agent 判 ─→ ⑤买入
                     │                                   └─ 同时给出：卖出规则 / 加仓规则 / 做T规则
                     └─ 判"没价值" → 取消盯盘（回①）
                                                        ⑥持仓：卖出规则族持续盯
                                                        ⑦卖点触发 → ⑧agent 判 → ⑨减/清
                                                        ⑩卖完 → 取消卖出规则族
                                                        ⑪回①：agent 再判断还有没有值得跟踪的价值

卖出侧同理：卖点触发 → agent 判 → 改规则继续盯 / 执行卖出 / 卖完收摊或转观察。

### 2.4 检查点输出 = 一次「规则重配置」（可含动作）

改规则继续跟踪 ｜ 买入+挂卖出规则 ｜ 买入+加仓规则 ｜ 买入+做T规则 ｜ 减仓 ｜ 清仓+收摊 ｜
清仓+转观察 ｜ **判不动 + NEXT 条件**（缺 NEXT 视为无效处置）

## 3. 判据一：agent 何时介入

### 3.1 三类触发，判据不同（v2 的硬冲突在这里解决）

| 触发类别 | 适用判据 | 说明 |
|---|---|---|
| **A. 价格触发（计划节点）** | 五道门（见 3.2） | 买卖节点类必须终判 |
| **B. 异常触发** | 异常度门（偏离预期 ≥ 阈值）+ 增量门 | 剧烈异动、放量、资金反转 |
| **C. 元触发（规则的健康度）** | **轻门：仅③增量门 + ⑤经济门**（**不适用金额门、节点门**） | 一直响/一直不响/阶段滞留/快到期 |

> v2 的错：把元触发也塞进五道门 → 一直不响的规则没有节点也没有金额影响 → 永远过不了门，
> 第 4 条铁律无法执行。

### 3.2 价格触发的五道门（必须同时过）

| 门 | 内容 | 默认阈值（可调） |
|---|---|---|
| ① 意图门 | 规则有交易意图，且我有仓位或明确买入意向 | **trend_observe 类不介入**（只归档） |
| ② 金额门 | 该动作影响 ≥ 账户 X% | **1%（≈1,050 元）** |
| ③ 增量门 | 同标的同议题冷却窗内未被介入 | **4 小时 / 标的** |
| ④ 节点门 | 计划内买卖节点（或命中异常判据） | — |
| ⑤ 经济门 | 期望收益 × 命中率 > k × 介入成本 | **k = 3** |

**宪法豁免**：exit_stop / 仓位超限 / 时段类动作**无条件介入**，不参与经济性判断。

### 3.3 每日介入预算与优先级（v2 缺的机制）

逐条过门还不够——额度有限时必须选择。

| 机制 | 规则 |
|---|---|
| 每日预算 | **≤8 次 LLM 唤醒**（含价格触发、异常、元触发、市场状态摘要） |
| 排序 | 按**期望收益**（潜在盈亏影响 × 命中率）降序取 top-k |
| 落选处理 | 未入选的触发进日终汇总，**不丢账**（仍落库、仍有 disposition） |
| 预算耗尽 | 仅**宪法级动作**可突破预算 |

### 3.4 成本记账（v2 缺的机制）

每次介入必须记账，否则无法验证"利润与成本一致"：

| 记什么 | 用途 |
|---|---|
| tokens 消耗 / 估算成本 | 单位唤醒产出、成本收益比 |
| 本次介入产生的结果（动作/判不动/交人） | 归因 |
| 涉及的触发 id 列表 | 回溯 |

## 4. 判据二：盯盘何时退出

### 4.1 规则的价值账本

| 字段 | 含义 |
|---|---|
| valuable_actions | 带来**有价值动作**的次数（买/卖/有效调整） |
| valuable_reviews | **有价值的判不动**次数（有理由 + 有 NEXT 条件）——**不计噪声** |
| interventions | 被介入次数 |
| noise_triggers | **真噪声**：无理由的机械归档、重复触发被合并的次数 |
| tokens_cost | 该规则累计介入成本 |
| last_value_at | 最近一次产生有价值动作/复核的时间 |

> v2 的错：把"判不动"一律计噪声 → 会诱导 agent 为了指标好看而乱动，与"挣利润"冲突。

### 4.2 退出判据（退役＝disable + 归档，不物理删）

| # | 判据 | 触发者 |
|---|---|---|
| 1 | **价值证伪**（建规则的论据被推翻） | agent |
| 2 | **交易完成**（买入完成→entry 规则退；清仓完成→exit 族退） | 系统（与成交联动） |
| 3 | **边际价值归零**（valuable_actions＝0 且 龄≥14 天 或 触发≥10 次） | 周度审计提请 |
| 4 | **成本 > 收益**（tokens_cost 与规则贡献收益之比超阈） | 周度审计提请 |
| 5 | **信息枯竭**（长期停牌/退市/无波动） | 系统 |
| 6 | **被替代**（被更完整的规则吸收，如今日 601600 六条→一条三档缓冲带） | agent |

**退出后**：转 trend_observe 继续观察，或彻底收摊（回到①发现价值）。

## 5. 层级与通道

### 5.1 层级 = agent 的状态（双向可达）

| 状态 | 含义 | 唤醒成本 |
|---|---|---|
| **L0** | 纯信息 | 0 |
| **L1** | 观察态（趋势观察、日常跟踪） | 日终汇总 ≤1 |
| **L2** | 行动态（买卖节点，agent 终判） | 摘要批量 |
| **L3** | 交接态（超授权/涉资金/不可逆 → 交人） | 生成决策请求 |

双向：L1→L3、L2→L3 成立；**L3→L2 / L3→L1 同样成立**（用户答完回到执行或继续观察）。

### 5.2 通道（飞书只通知，不承载决策）

- **飞书**：单向事实广播，**一律不含"等你确认"语义**
- **决策请求**：交互会话的 ask_user_question（用户 2026-09-11 选定）
- L3 待决策项入**待决策队列**；**非交互场景（定时唤醒）不得替用户决策**

---

## 6. 指标

| 层级 | 指标 | 说明 |
|---|---|---|
| **主指标** | **净值增长 ÷ 最大回撤**（辅：胜率 × 盈亏比） | 唯一目标：挣高额利润 |
| 二级约束 | 单位唤醒产出 = 有价值动作 ÷ 唤醒次数 | 成本效率（约束，非目标） |
| 二级约束 | 噪声比 = 真噪声 ÷ 总触发 | 信噪比 |
| 健康度 | 触发→处置率、规则平均寿命、规则存活率 | 系统是否在转 |

## 7. 数据模型（一张完整表）

### 7.1 watch_rules 增列

| 列 | 含义 |
|---|---|
| intent | trend_observe / entry / add_position / t_trade / exit_stop / exit_take_profit / exit_reduce |
| lifecycle_stage | discovered / tracking / entry_triggered / holding / exit_triggered / closed |
| scope | market / sector / symbol / position |
| target | 观察目标（指数代码、板块名、指标名；position 类为空即用 symbol） |
| linked_account | 关联账户 |
| created_from | 溯源：哪次触发/判断生成（无源规则＝可疑） |
| next_action_hint | 触发后 agent 该做什么 |
| last_reviewed_at / review_interval_days / review_due_at | 元触发：复核周期 |
| burst_count_window | 窗口内触发计数（频次超限判定） |
| valuable_actions / valuable_reviews / interventions / noise_triggers / tokens_cost / last_value_at | 价值账本 |

### 7.2 watch_triggers

沿用 Phase 1 的 disposition 状态机；增列 rule_intent（冗余，便于按意图聚合）。

### 7.3 interventions（新表，成本记账）

触发 id / 规则 id / 时刻 / 唤醒类型（价格·异常·元·市场摘要）/ tokens / 估算成本 /
产出（动作 / 判不动+NEXT / 交人）/ 决策审计 id。

### 7.4 API

规则重配置（批量 create / update / retire，强制审计）｜介入记账写入｜价值账本查询｜
市场状态摘要读取。

## 8. 工程缺口：市场级盯盘（要做「紧盯市场」必须补）

现 WatchEngine 只支持个股：tick() 走 quote_service.get_realtime_quote(rule.symbol)。

| 缺口 | 内容 |
|---|---|
| 标的类型 | rules 增加 scope / target |
| 取数通道 | 指数行情、板块行情、情绪/量能/涨停家数需 tick 级取数（现有工具准实时、非 tick） |
| 判定器 | 指数/板块/指标类条件求值（现 conditions 只认个股 quote） |
| 汇总形态 | 市场状态摘要（见 §1.3） |

## 9. 实施顺序（与设计一一对应）

| 阶段 | 内容 | 验收（对应指标） |
|---|---|---|
| **P1** | intent / lifecycle_stage / scope / target 字段 + 摘要载荷带「意图与预案」 | agent 拿到触发就知道要回答什么问题 |
| **P2** | 规则重配置批量 API + 审计 | 每次重配置可回溯到触发与理由 |
| **P3** | **介入判据落地**：五道门 + 元触发轻门 + 每日预算排序 + 宪法豁免 | 单位唤醒产出上升；噪声比下降 |
| **P4** | **成本记账**（interventions 表 + tokens） | 可算出每次介入的真实成本 |
| **P5** | 与成交联动（买入→生成卖出族；清仓→收摊） | 规则生命周期不再靠人维护 |
| **P6** | 市场级盯盘（scope 取数 + 判定器 + 市场状态摘要） | agent 无需手工拼凑即可感知市场 |
| **P7** | 价值账本 + 退出判据自动化（周度审计提请） | 规则平均寿命可测；僵尸自动浮现 |
| **P8** | 飞书消息可读性设计（用户指定：闭环完成后专题） | 通知是给人看的事实，不是给人做的题 |
