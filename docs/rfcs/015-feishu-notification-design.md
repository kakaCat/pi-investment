## 1. 第一性原则（用户已明确的三条）

1. **飞书只做单向通知，不承载决策**——消息里**不得**出现"请回复 1/2""等你确认"这类语义。
   需要决策的一律走交互会话的 `ask_user_question`。
2. **通知是给用户看的事实，不是给用户做的题目**——读完就知道"发生了什么、我做了什么"，
   不需要用户动手（如需动手，另走决策通道）。
3. **不该发的一条都不发**——`deduped`（去重合并）、`auto_observed` 的纯观察类默认不进飞书；
   **发了就说明"值得你知道"**。

## 2. 什么该发 / 什么不该发（与处置状态机对齐）

| 处置态 | 飞书 | 理由 |
|---|---|---|
| `deduped` | ❌ 不发 | 同一次跌穿的重复通知，发了就是噪声（实测 10 条触发 → 8 条是这类） |
| `auto_observed` | ❌ 默认不发（进日终汇总） | 观察类命中=只是"看了一眼"，不构成事实变化 |
| `escalated` | ✅ 发（**批量摘要**，不逐条） | agent 要处置，用户应知情 |
| `handled` | ✅ 发（**动作 + 结果**） | 有动作就有事实，必须让你知道 |
| `ignored` | ⚠️ 合并发（日终一条） | "判不动"是决策，但不需要即时打扰 |
| `meta_review` | ⚠️ 合并进日终/周度 | 规则健康度，不急 |
| 宪法级动作（止损/仓位超限） | ✅ **立即发，最高优先级** | 铁律动作必须即时可见 |

## 3. 分层与形态（与 L0–L3 对应）

| 层 | 触发时机 | 形态 | 示例标题 |
|---|---|---|---|
| **L0** | 纯信息事件 | 单条 | `[信息] 沪深300 跌破 4500` |
| **L1** | 观察类（默认不发，聚合） | 日终汇总一条 | `[日终] 今日 12 条观察命中（3 个标的）` |
| **L2** | 买卖节点（agent 已判） | 单条或按标的合并 | `[动作] 英科医疗 止损触发 · 已减半` |
| **L3** | 需用户决策 | **不进飞书**，只发"有待决策项"事实 | `[待决策] 有 1 项等待你在会话中确认` |
| 熔断/风控 | 立即 | 最高优先级 | `[风控] 组合回撤 -8.2%，已触发熔断减仓` |

## 4. 消息骨架（固定五段，缺一不可）

```
【标题】一句话说清是什么        ← 谁都能看懂
📍 事实：价格/量能/资金/时间（带来源与时点）
🎯 我的判断：结论 + 依据（一句话）
✅ 我的动作：做了什么 / 或"仅观察，未动作"
⏭ 下一步：会在什么条件下再动（NEXT 条件）
```

> 关键：**"我的动作"与"下一步"必须显式**——否则用户读完仍不知道"这事完了没"。

## 5. 治理（防噪声）

| 机制 | 规则 |
|---|---|
| 按标的合并 | 同一标的同一时段多条 → 合并成一条（已实现去重，此处是"合并展示"） |
| 每日通知预算 | 默认 ≤10 条/天（宪法级/风控不计入） |
| 静默时段 | 非交易时段只发风控级；其余进次日汇总 |
| 分级路由 | 风控/宪法 → alerts 群；日常 → reports 群 |
| 长文折叠 | 明细超过 N 行 → 摘要 + "详见会话/看板" |

## 6. 待讨论的问题（本轮要定的）

1. **通知预算**：默认 **≤10 条/天**是否合适？（其余进日终/周度汇总）

3. **日终汇总的时点**：收盘后 15:15 还是并入现有 18:30 盘后例程？

5. **是否需要"用户可回复确认"的例外**：按第 1 条，我建议**一律不需要**（决策走会话）
