## 1. 为什么需要本 RFC（对 RFC 013 的自我修正）

RFC 013 把处置设计成**有终态的一次性状态机**——这是错的。用户评审指出：

> "没有把 L1/L2/L3 的闭环流程设计出来；agent 还可以改规则；**不是结束，是一个一直循环的能力**；
> 在哪些场景退出要设计。"

正确的模型是**永续控制回路**：

- **单条触发**确有终态（handled/ignored/expired）——013 只对到这一层
- **规则与回路没有终态**，它们是循环：触发 → 处置 → **归因** → **改规则** → 新触发
- 013 缺失三条边：①分层各自的回路与节拍 ②**反馈边（agent 反改规则）** ③**退出/暂停边**

### 现有设施缺口（实测，2026-09-11）

| 能力 | 现状 |
|---|---|
| 触发→处置 | ✅ Phase 1 已交付 |
| 规则生命周期（退役/TTL/复核） | ❌ **完全缺失**——只有手动 `DELETE /api/watch/rules/{id}`，无任何清理任务 |
| 规则字段修改 | ⚠️ 仅 `enabled` 可改（`update_fields` 白名单不含 conditions/action_hint/expires_at/account） |
| 规则卫生 | 53 条 / 33 启用；**6 条无过期时间**；**13 条 `escalation_policy` 为空**；1 条 `action_hint` 空；同标的重复最高 601600×6、600887×4 |
| 自动建规则入口 | `opportunity_to_watch_rule_service`（L1/observe + 默认 TTL），是回路的"创建边" |
| 治理节拍 | 无日终/周度的规则复核任务 |

## 2. 回路总览：三层嵌套循环

```
┌─ 宏循环（日 / 周）──────────────────────────────────────────────┐
│  归因 → 规则演化（调阈值 / 调分级 / 新建 / 合并 / 退役）→ 退出检查  │
│    ▲                                                    │        │
│    │ 证据（触发序列+处置结果+盈亏归因）                    ▼        │
│  ┌─ 中循环（日内）──────────────────────────────────────┐ │        │
│  │  触发簇汇总 → 判断（结构变没变）→ 动作 → 结果回填      │ │        │
│  │    ▲                                        │        │ │        │
│  │    │                                        ▼        │ │        │
│  │  ┌─ 微循环（实时 tick）──────────────────────────┐   │ │        │
│  │  │ 条件判定 → 去重 → 通知 / 落库（零 LLM 为主）  │   │ │        │
│  │  └──────────────────────────────────────────────┘   │ │        │
│  └─────────────────────────────────────────────────────┘ │        │
└─────────────────────────────────────────────────────────────┘
        ▲                                                     │
        └──────────── 规则变更（收紧自动 / 放松需人工）──────────┘
```

## 3. 分层闭环（L0 / L1 / L2 / L3）

### 3.0 关键修正（2026-09-11 用户确认）

原设计有两处根本错误，本版修正：

| 原设计（错） | 修正后 |
|---|---|
| L1/L2 是给 agent 的、L3 是"人机边界" | **四层都是 agent 的状态**。L3 = agent **判断需要用户介入**时自己进入的状态（见 3.4） |
| 层级是等级（只能向上） | **双向可达**：L1→L3、L2→L3 成立，**L3→L2、L3→L1 同样成立**。层级是状态不是等级，agent 在每个触发/决策点重新判定当前应处层级 |
| 飞书是"交人=等你答复"的通道 | **飞书只做单向通知，不承载决策**（见 3.5）。交接请求走交互通道 |

### 3.1 四层定义（agent 视角）

| 层 | agent 状态 | 处理动作 | LLM 成本 | 对用户 |
|---|---|---|---|---|
| **L0** | 信息态（无需决策） | 记录 + 通知 | 0 | 单向通知 |
| **L1** | 观察态（轻量判断） | 去重合并 + 机械归档 + **日终汇总判断"结构变没变"** | 日终 1 次 | 单向通知 |
| **L2** | 行动态（可自主处置） | 决策（不动/减/清/加）→ 走 R-001~R-009 → 执行/挂单 → 结果回填 | 摘要批量 | 事后通知 |
| **L3** | 交接态（判定需用户定） | 生成**决策请求**（证据包 + 建议 + 默认行为 + NEXT 条件） | 生成请求时 1 次 | **决策请求（非飞书）** |

### 3.2 双向转移矩阵（谁触发、什么条件、如何留痕）

| 迁移 | 触发条件 | 动作 | 留痕 |
|---|---|---|---|
| L0 → L1 | 周度价值复核：该信息有人看/有后续 | 升为观察规则 | 变更台账 |
| L0/L1 → 暂停 | 噪声（N 次触发零信息量）、无价值 | 静音/归档 | reason |
| **L1 → L2** | 结构由"观察区"进入"行动区"（趋势确认 / 破位加速 / 量能配合） | 切入行动处置流程 | 判定证据 |
| **L1 → L3** | 观察中发现**授权外或需用户定的事**（资金安排、账户级冲突、标的重大基本面变化、跨账户影响） | 生成决策请求 | 证据包 |
| **L2 → L3** | 行动前自检：超授权 / 超能力 / 不可逆 / 置信度不足 | 挂起该动作 + 生成决策请求 | 证据包 + 默认行为 |
| **L2 → L1** | 处置完成但区间仍在（持仓在、继续盯） | 回落观察态 | 处置结果 |
| **L3 → L2** | 用户给出决策，或条件成熟（如资金到位、跨账户冲突消解） | 回到行动态执行 | 决策引用 |
| **L3 → L1** | 用户决定"继续观察 / 暂不动作" | 回落观察态 + NEXT 条件 | 用户决策原文 |
| **L3 → L0** | 用户判定"仅记录即可" | 降为信息态 | — |
| L2 → L0/L1 | 连续 N 次 escalated 判"不动"→ 说明分级过高 | 降级 + 调参提案 | 归因证据 |

> 关键含义：**L3 不是终点，是中间态**。用户答完必须回到 L2 或 L1 继续循环——
> 不允许一条决策请求"答完就结束"，否则回路断在交接处。

### 3.3 层级判定：统一入口

agent 在每个触发/决策点跑一次判定（`judge_tier(context, trigger, authority)`），返回**目标层 + 理由 + 留痕**。

判定维度：**影响半径**（单标的/组合/账户/跨账户）、**可逆性**、**置信度**、**是否减少保护**、**是否超授权/超能力**、**时效性**（等得起吗）。

### 3.4 L3 交接态（由 agent 判定）

**进入条件**（agent 自判，命中任一）：
- 超授权（涉资金、跨账户、超出仓位/风险授权）
- 超能力（无对应工具，或工具链不可用）
- 不可逆且影响半径大（清仓、批量退役规则）
- 自评置信度不足（证据不足/数据降级/多源冲突）
- 减保护类变更（默认交人，除非满足 3.4.3 的四条件）

**交接产物（缺一不可）**：
1. 结论与建议（我建议怎么做、为什么）
2. 证据包（触发序列、价格量能、资金、规则上下文、归因）
3. 影响评估（最坏情况、影响半径）
4. **默认行为**：你不答我会怎样——保持原状 / 到期自动收敛；**绝不"没人管就自动执行"**
5. **NEXT 条件**：什么情况下我会重新提请（避免同一问题反复打扰）

**宪法元规则**：止损铁律、仓位上限、交易时段、T+1 等宪法要求动作的场景，
agent 只能决定"怎么做"，**不能决定"要不要做"**——不得以 L3 挂起推延宪法义务。

**反自利设计**：减保护类默认 L3；若 agent 判为自决，须同时满足
**①强证据 ②限单条规则 ③可逆 ④进观察期**；每周抽样复核，否决率超阈值 → 收回该域自决权（见 4.4）。

### 3.5 通知 vs 决策：两条通道必须分离（2026-09-11 用户明确）

> "飞书只是通知用户，不是让用户决策的。"

| 通道 | 用途 | 允许 | **禁止** |
|---|---|---|---|
| **飞书** | 单向通知（事实广播） | 发生了什么、当前状态、处置结果、下一步 | ❌ 要求用户回复/审批/选择；❌ 承载任何决策；❌ "请回复 1/2" 式交互 |
| **交互通道**（会话 ask_user_question / 看板待办 / 需求卡） | 决策请求 | 证据包 + 建议 + 默认行为 + 选项 | ❌ 用飞书消息替代决策请求 |

**推论（对设计的硬约束）**：
- 飞书消息**一律不含"等你确认"语义**——它不需要回复，因此不能有前置依赖
- L3 的交接必须落成**待决策项**（可在会话中被 ask_user_question 拉起，或在看板可见），
  飞书只同步一条"有一条待决策"的事实通知
- 通知去重目标不变：能机械收敛的（deduped/auto_observed）不发；**发了就说明"值得你知道"**
- 这一条同时是后续"飞书消息可读性设计"的总纲：**通知是给用户看的事实，不是给用户做的题目**

## 4. 反馈边：agent 改规则的能力与护栏

### 4.1 能力清单（回路输出）

| # | 能力 | 触发场景（回路信号） | 当前可实现性 |
|---|---|---|---|
| 1 | **调阈值** | 阈值被反复穿越但无结构变化（噪声）/ 阈值过远从不触发 | 需扩展 PATCH rules |
| 2 | **调分级**（L0↔L1↔L2） | L2 连续 N 次判"不动"→ 降 L1；L1 结构转强 → 升 L2 | 需扩展 PATCH rules |
| 3 | **改有效期** | 催化未到 → 续期；催化已过 → 缩短/退役 | `expires_at` 已存在，需开放修改 |
| 4 | **改条件类型/方向** | 下破改上破（结构反转）、加量能确认（假突破多） | 需扩展 PATCH rules |
| 5 | **新建规则** | 发现新的关键位/观察点 | ✅ 已有 create + 自动建规则服务 |
| 6 | **退役规则** | 见第 5 节退出场景 | 需新增（disable+归档，**不物理删除**） |
| 7 | **合并重复规则** | 同标的同向多规则（601600×6） | 需新增（合并为一条多档） |
| 8 | **改归属账户** | 规则跟账户走（清仓后换绑） | 需扩展 |
| 9 | 改池 / 调仓 | 战术层调整 | 已有工具；**调仓需人确认（R-001~R-009）** |

### 4.2 非对称护栏（本设计最关键的约束）

> 原则：**收紧保护可自动，放松保护必须人工确认。** 因为 agent 有"减少自己被唤醒次数"的自利倾向
> （放宽阈值 → 触发变少 → 显得清净，但风险敞口变大）。

| 变更方向 | 例子 | 授权 |
|---|---|---|
| **加保护** | 新建规则、收紧阈值、升 L2、缩短有效期、加量能确认 | agent 可自动执行 + 留痕 |
| **减保护** | 删/退役规则、降 L0/L1、放宽阈值、取消止损类条件、延长有效期 | **必须人工确认**（人工闸门）+ 证据包 |
| **等效** | 改条件类型但保护强度不变 | agent 可自动 + 留痕 |

**通用护栏**：①交易时段禁改（宪法）②单规则单日改动上限 1 次（防震荡）③每次改动写
`decision_audit` 并关联触发 id/归因证据 ④退役 = `enabled=false` + 归档标记，**不物理删除**
（保留历史可回溯）⑤变更后进入观察期，跟踪其触发频率与有效性变化。

### 4.3 回路学习的落地链条

```
触发 → 处置(handled/ignored) → 结果回填(价格/盈亏) → 归因(选股/择时/阈值/分级 哪一环错)
   → 提案(改什么/证据/预期) → [非对称护栏] → 执行 → 观察期跟踪 → 经验沉淀(experience)
```

### 4.4 授权自审（meta-loop：对"判断权"本身的审计）

自决权不是一次性授予，而是**自身也在回路里**：

- 每次自决写 `decision_audit`，含判据打分（影响半径 / 可逆性 / 置信度 / 是否减保护）
- **周度抽样复核**：随机抽 K 条自决（重点减保护类）由人复核
- **动态边界**：否决率 > 阈值 → 该域自决权收回（回落交人）；连续表现良好 → 可放权
- 指标：自决率、自决否决率、交人响应率、交人平均等待时长、单位唤醒产出

| 指标 | 意义 | 期望方向 |
|---|---|---|
| 自决率 | agent 独立处理比例 | 上升，但否决率不得同步上升 |
| 自决否决率 | 判断质量 | ≤ 阈值，超限收回权限 |
| 交人响应率 / 等待时长 | 打扰质量 | 只在该交人时交人；等待不应阻塞其他回路 |

### 4.5 L3 待决策队列（通道 A：会话内 ask_user_question）

| 环节 | 设计 |
|---|---|
| 入队 | agent 判定 L3 → 生成决策请求（证据包/建议/默认行为/NEXT 条件）→ 写入待决策队列 |
| 拉起 | **仅在交互会话中**用 `ask_user_question` 拉起（一次最多问 1–3 条，附选项与默认项） |
| 非交互场景 | 定时任务唤醒时**不得替用户决策**：只处理可自决项，L3 项留在队列，飞书发**事实通知**"有 N 条待决策" |
| 出队 | 用户答复 → 记录决策原文 → 回到 L2（执行）或 L1（继续观察）；超时 → 保持原状 + 重提请 |
| 防打扰 | 同一标的同一议题合并为一条；NEXT 条件未满足不重复提请 |

## 5. 退出场景矩阵（用户明确要求）

### 5.1 触发级退出（微循环，单条触发的收敛）

| 退出态 | 判定 | 处置者 | 留痕要求 |
|---|---|---|---|
| `handled` | 已执行动作 | agent/人 | 动作 + 结果回填 |
| `ignored` | 知悉但不动作 | agent/人 | **必须写 reason + NEXT 条件**（下次何时才动） |
| `expired` | 超期未处置（盘后清单兜底） | 系统 | 自动收敛 + 计入未处置统计 |
| `superseded` | 被同一标的更新的触发取代 | 系统 | 指向新触发 id |

### 5.2 规则级退出（宏循环，规则何时结束）

| 场景 | 判定条件 | 授权 | 动作 |
|---|---|---|---|
| 目标达成 | 止盈/清仓/建仓完成 | agent 自动 | 退役（转观察或删除条件） |
| **逻辑证伪** | 建规则时的论据被推翻（事件反转/基本面变坏/政策转向） | 需证据 | 退役 + 经验沉淀 |
| 结构破坏 | 价格结构失效（支撑/趋势破坏） | agent 自动 | 退役或改条件类型 |
| 账户清仓 | 持仓归零且无观察理由 | agent 自动 | 退役；有观察理由 → 降 L0/L1 |
| 长期未触发 | 超 TTL / 连续 N 日未触发 | 系统提案 | 进入周度复核清单（**人工确认后**退役） |
| 被合并 | 同标的同向重复规则 | agent 提案 | 合并为一条多档（保留最严阈值） |
| 事件过期 | 催化已发生/已失效（`expires_at`） | 系统 | 退役 |
| 噪声超标 | 触发频率高但无信息量（N 次触发 0 次有价值处置） | agent 提案 | 调参或降级 |
| 分级重判 | L2 连续 N 次判"不动" | agent 提案 | 降 L1（**需人工确认**，属减保护） |

### 5.3 标的级退出（何时停止盯这个标的）

池子剔除 / 账户清仓且无观察理由 / 连续 N 次触发零信息量 / 长期停牌或退市风险 →
**停盯 + 归档**（保留历史规则与触发，便于复盘）。

### 5.4 回路级暂停（不是退出，是可恢复的挂起）

| 场景 | 行为 |
|---|---|
| 非交易日 / 非交易时段 | 引擎不 tick（已有） |
| 数据源降级 / 数据冻结 | 只记录不行动（R-011/R-013 精神）：降级期触发的行动类降为"待复核" |
| 熔断期 | 只保留风控类规则（止损/减仓），暂停机会类 |
| 维护窗口 / 用户冻结 | 全局静默，触发只落库不通知 |

### 5.5 交接级退出（L3 停等）

等人工决策；超时 → 保持原状 + 进未处置清单 + 升级提醒；**绝不自动执行**。

## 6. 节拍与 Token 预算（与触发数解耦）

| 循环 | 节拍 | LLM 唤醒/日 |
|---|---|---|
| 微循环（tick） | 实时（60s / fast 10s） | **0** |
| L1 日终汇总 | 每日 1 次（仅当当日有 L1 触发） | ≤1 |
| L2 摘要 | 盘中定时（队列非空）+ 盘后 1 次 | ≤4 |
| 宏循环（规则演化） | 日终 1 次 + 周度复盘 1 次 | ≤2 |
| 退出检查 | 日终（机械可判，仅异常时唤醒） | ≈0 |
| **合计** | — | **≤8 次/日，与触发数无关** |

## 7. 失败模式与对策

| 失败模式 | 对策 |
|---|---|
| 规则震荡（反复改阈值） | 单规则单日改动上限 1 次 + 观察期 |
| 过度退役（丢历史） | 只 disable + 归档，不物理删除 |
| 假退出（催化未过就删） | 退出必须带证据包 + 事件日历校验 |
| agent 自利（放阈值减少唤醒） | 非对称护栏：减保护一律人工闸门 |
| 汇总漏项（未处置清单没人看） | 盘后清单必须闭环；连续 N 日有未处置 → 告警 |
| 回路空转（改了但没效果） | 变更后跟踪触发频率/有效性，无改善则回滚 |
