## 1. 设计哲学：挣谁的钱

零和市场里，利润只能来自**对手的错误**。本系统的每个模块都服务于同一个闭环：

```
感知市场状态 → 找到对手犯错的战场 → 在对的价格进场
→ 用仓位控制风险 → 纪律执行 → 复盘归因 → 把教训喂回决策
```

不预测市场，只在**赔率与胜率有利时下注**；不下注的时间也是盈利的一部分。

## 3. 模块定义

### M0 数据地基 〔其他 agent 实施，本设计的依赖项〕

| 项 | 内容 |
|---|---|
| 职责 | 行情/财务/因子/资金流数据的完整性、新鲜度、一致性 |
| 现状（8/20 实测） | 行情/财务/筹码可用；因子两代管线并存（大写冻结于 5/20，新管线历史仅 ~12 天）；资金流因子仅覆盖 110 股 |
| 需要的能力 | ①死因子过滤 ②新管线 ≥120 日历史回填 ③因子新鲜度门禁 ④资金流覆盖扩至全市场 |
| 验收 | factor_calculate 全部因子 ≤3 交易日；回填历史 ≥120 交易日 |

### M1 市场感知（Situation Awareness）

| 项 | 内容 |
|---|---|
| 职责 | 回答"现在是什么市"：趋势/震荡/恐慌/狂热（regime），每日主线在哪 |
| 现状 | `opportunity_scan` 内部已有 regime 判定（sideways + 权重自适应）；板块热点靠 web_search 人工式复盘（8/18 农业涨停潮判断正确）；`market_sentiment`/`sector_analysis` 存在但未实测 |
| 需要的能力 | ①**每日 regime 落库**（时间序列，而非一次性计算）②**每日主线识别自动化**（涨停聚类+资金流向+催化剂关联，替代人工搜索）③情绪时间序列（涨跌家数/新高新低/量能的历史曲线） |
| 验收 | 任意交易日可查当日 regime 与 Top3 主线及判定依据；与事后走势一致率有统计 |

### M2 标的工厂（Stock Selection）

| 项 | 内容 |
|---|---|
| 职责 | 回答"在哪个战场、打哪只"：把主线映射到标的，排雷 |
| 现状 | `opportunity_scan` 可用（评分+理由+regime 权重）；`pool_list` 刚修复（29 池）；`pool_battlefield`/`manipulation_detect`/`screening` 未实测 |
| 需要的能力 | ①**主线→标的映射器**（如 粮食安全→糖/种业/米业 的自动关联，8/18 靠人工完成）②排雷清单（操纵嫌疑/减持/商誉/ST）③池战场评分实测与调优 |
| 验收 | 每日主线 Top3 各有 ≥2 只候选标的且附入选理由；排雷规则有命中记录 |

### M3 信号与择时（Entry/Exit）

| 项 | 内容 |
|---|---|
| 职责 | 回答"什么时候买/卖"：买点体系 + 卖点体系 + 信号分级 |
| 现状 | 盯盘规则体系成熟（28 条，含止损/止盈/买点/量能异动，语义化 context）；`strategy_execute`(signal/backtest) 存在但 152 策略多未验证；买点判断靠人工技术分析（质量尚可） |
| 需要的能力 | ①**信号分级制**（A级=多维度共振→标准仓；B级→半仓；C级→观察不交易）②策略回测验证（RFC003-P2）③信号质量追踪（每个信号后续 5/10/20 日表现落库） |
| 验收 | 信号分级规则文档化；≥3 策略样本外夏普>1；信号后续表现可查询 |

### M4 仓位与风控（Risk & Position）

| 项 | 内容 |
|---|---|
| 职责 | 回答"买多少、何时必须减"：账户/标的/组合三层风控 |
| 现状 | `risk_metrics` 实测可用（账户：累计+2.87%、最大回撤-6.7%、夏普为负）；`risk_controller`/`risk_barra_decomposition` 未实测；高现金纪律（72%）靠人工判断维持 |
| 需要的能力 | ①**regime 仓位映射表**（恐慌期≤100%、震荡期≤60%、狂热期≤30%，替代人工感觉）②组合回撤熔断（账户回撤 >8% 强制减仓一半）③行业/相关性集中度上限 |
| 验收 | 仓位规则文档化并被每笔交易引用；熔断触发有演练记录 |

### M5 交易执行（Execution）

| 项 | 内容 |
|---|---|
| 职责 | 低摩擦、可对账地把决策变成持仓 |
| 现状 | `portfolio_trade`/`algo_execute`(TWAP/VWAP)/`trade_monitor`/`trade_verify` 工具齐备；歌尔股份 1300 股实盘（虚拟账户）在持 |
| 需要的能力 | ①滑点与成本建模（回测与实盘的成交价差追踪）②T+1 约束已在工具层 ③执行质量报告（成交价 vs 决策时价） |
| 验收 | 每笔成交有滑点记录；`trade_verify` 每日无异常 |

### M6 学习飞轮（Learning Loop）〔本系统的护城河〕

| 项 | 内容 |
|---|---|
| 职责 | 让系统越用越聪明：归因 + 经验沉淀 + 决策前强制检索 |
| 现状 | 记忆三件套可用（memory/experience/decision，已写入 id 79/80）；`evolution_leaderboard` 仅 1 条记录（fitness 0.1，形同未用）；**无归因分析能力**；经验未嵌入决策流程 |
| 需要的能力 | ①**归因分析**（盈亏拆解：选股/择时/板块/运气）②**决策前强制检索**（下单前自动查 memory/experience 中该标的与该场景的历史教训）③周报自动生成（胜率/盈亏比/夏普/回撤/最大单笔盈亏）④evolution 常态化运行 |
| 验收 | 每笔亏损交易有 experience 记录；决策日志中出现"已检索历史教训"引用；周报连续 4 周无中断 |

### M7 对手博弈情报（Opponent Intelligence）〔哲学核心，差异化所在〕

| 项 | 内容 |
|---|---|
| 职责 | 回答"对手在犯什么错"：散户恐慌/FOMO、机构建仓/出货、游资拉高/撤退 |
| 现状 | `opponent_behavior` **数据不可信**（8/18 涨停日返回 panic_bottom，模板嫌疑，S2）；`manipulation_detect` 未实测 |
| 需要的能力 | ①真实数据源接入（龙虎榜/北向/大单资金流/换手率异动）②散户情绪代理指标（恐慌抛售=放量长阴+超跌 quality 标的）③操纵周期识别（拉高出货→崩盘→抄底窗口） |
| 验收 | 对手分析结论与次日盘面可交叉验证；至少 1 次"恐慌错杀"实战捕捉记录 |

### M8 预测引擎（Prediction）〔后置，依赖 M0〕

| 项 | 内容 |
|---|---|
| 职责 | ML 涨跌概率参考（不主导决策，只作加权输入） |
| 现状 | `model_predict` 恒等输出 0.4659（S1，预测能力为零）；训练数据受 M0 历史不足制约 |
| 需要的能力 | ①恒等输出根因排查 ②M0 回填后 model_train/evaluate ③上线门禁（AUC>0.55 且 IR>0，不合格永不上线） |
| 验收 | `model_evaluate(recent_3m)` 达标；预测结果对两只不同股票有区分度 |

## 4. 建设顺序（依赖驱动）

```
第一波（并行）：
  M0 数据地基      → 其他 agent（RFC003-P1）
  M1 regime 落库   → 挣钱线可先做（不依赖 M0）
  M6 决策前检索+归因 → 挣钱线核心，立即提升决策质量
  M4 仓位映射表    → 纯规则，立即可做

第二波（M0 就绪后）：
  M2 主线映射器（依赖 M1）→ M3 信号分级+回测 → M7 真实博弈数据

第三波（历史数据 ≥120 日后）：
  M8 预测引擎重建

M5 穿插执行（已是工具就绪状态，补滑点建模即可）
```
