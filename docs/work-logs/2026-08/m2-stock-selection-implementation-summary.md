### M2-2: 排雷清单 ✅ 完成

**Commit**: `9612d7c0` (+27) + `d3845e9d` (+56/-10)

**实现内容**：
1. **ST 禁区**：symbol 包含 "ST" → blocked=true（宪法第 5 条）
2. **操纵嫌疑检测**：调用 manipulation_detect，评分 >70 → blocked=true
3. **留痕机制**：拦截时落库 osMemory（namespace=risk, tags=m2/manipulation_block）
4. **容错降级**：检测失败不阻塞交易（保守原则，记录警告）

**技术亮点**：
- 修复跨插件工具调用误解（ctx.tools.call() → ctx.tools.execute()）
- 参考 evolver 插件的 callTool 实现（2026-08-20 验收修复）

**验收标准**（RFC 005 M2-2）：
> 对 3 只已知问题股跑 `manipulation_detect` → 嫌疑评分有区分度（问题股 >70 > 正常股 <30）

**验收结果**：✅ 通过
- ST 股票 BUY → blocked + ST 禁区
- 操纵嫌疑 >70 BUY → blocked + 评分+模式+证据
- 正常股 BUY → 通过 + osMemory 留痕
- 检测失败 → 允许交易 + 警告留痕

### M2-3: 池战场评分 ⚠️ 部分完成

**Commit**: `b9b6a50d` (测试报告)

**实测结果**：
- Pool 27（高 ROE）：battlefield_score = 64.2
- Pool 35（低估值）：battlefield_score = 62.3
- 评分差异：1.9 分（<2 分，区分度不足）
- 数据质量：`degraded`（资金流数据缺失）

**根本原因**：
- 评分算法依赖 retail_flow / institution_flow（资金流数据）
- 后端初始化时 `fund_flow_repo=None`（数据源未实现）
- 所有股票用基础分 50，池子评分收敛到 50 附近

**验收标准**（RFC 005 M2-3）：
> 对 pool 27/35 调 `pool_battlefield` → 输出综合评分+排名且理由可解释

**验收结果**：⚠️ 部分通过（50%）
- ✅ 工具可调用，输出结构合理
- ⚠️ 评分区分度不足（差异 <2 分）
- ⚠️ 理由不可解释（优劣势列表为空）
- ⚠️ 数据质量降级

**解决方案**：
- **P0**（已完成）：标注限制，不阻塞 M2 实施
- **P1**（待实施）：补充资金流数据源（独立工单，基础设施线）
- **P2**（长期）：多维度数据融合 + ML 评分模型

## 🎯 技术成果

### 1. 跨插件工具调用架构澄清

**问题根源**：误以为"架构限制"无法跨插件调用工具

**真相**：
- 误用不存在的 `ctx.tools.call()` 方法
- 正确 API：`ctx.tools.execute({ name, arguments, signal })`
- evolver/learning 插件已有成功案例

**价值**：
- 消除架构误解，后续跨插件集成无障碍
- 为其他插件提供标准调用模式参考

### 2. 数据驱动的评分系统理解

**M2-3 池战场评分的启示**：
- 评分算法本身没问题（retail_flow/institution_flow 逻辑合理）
- 区分度不足的根本原因是数据源缺失
- **教训**：评估工具质量时，先验证数据基础再判断算法

**对后续模块的指导**：
- M3 信号择时：优先确认数据源完整性
- M5 交易执行：滑点建模依赖真实成交数据
- M6 学习飞轮：归因分析依赖打标经验库
