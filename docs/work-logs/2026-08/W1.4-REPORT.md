## 实现要点

### 1. MemoryProvider Port 设计

```typescript
interface MemoryProvider {
  prefetch(query, sessionId?, limit?, maxChars?): Promise<string>
  query(query, options?): Promise<MemorySearchResponse>
  syncTurn(userContent, assistantContent, sessionId?, metadata?): Promise<void>
  validate(entryId, success): Promise<void>
  writeExperience(params): Promise<{success, id?, message}>
  queryExperience(params): Promise<string>
  shutdown(): Promise<void>
}
```

### 2. 召回注入流程

```
用户消息 → buildSystemPromptForContext
         ↓
    provider.prefetch(userMessage, sessionId, 3, 2000)
         ↓
    混合检索 top-3（BM25 + 向量，W1.3 完成后生效）
         ↓
    格式化为文本（控制字符预算 ≤ 2000）
         ↓
    注入到系统提示词 Memory 层 "### Recalled Memory"
         ↓
    自动调用 validate 更新 last_recalled_at
```

### 3. Provenance 映射

```typescript
SessionContext.type → session_kind
- 'interactive' → 'user'
- 'cron_review' → 'cron'
- 'background_task' → 'wake'
- 'cron_evolution' → 'distiller'（已废弃，不再使用）
```

### 4. 防 Recall 循环

- `syncTurn` 写入时排除本轮被召回注入的内容
- 当前实现：简单过滤空内容
- 未来增强：根据 `recalledIds` 精确过滤

### 5. 降级策略

```
initMemoryProvider
  ↓
尝试 V2MemoryProvider
  ↓ (失败)
降级到 FileFallbackProvider
  ↓
保证系统可用
```

## 依赖关系

- **依赖 W1.2**: quantsys-v2 `/api/memory/*` API 已就绪
- **不阻塞 W1.3**: 向量检索未实现时，走关键词检索（降级）

## 已知限制

1. **systemPrompt 回调**: SDK createAgentSession 的 systemPrompt 参数是固定回调，无法传递用户消息。当前实现在初始化时调用 prefetch，仅对首轮消息生效。后续轮次需要在消息发送前手动更新 system prompt。

2. **召回触发时机**: 当前仅在 session 初始化时召回一次。完整实现需要每轮消息前调用 prefetch（需要修改 SDK 或在消息发送前手动注入）。

3. **防 Recall 循环**: 当前仅过滤空内容，未实现基于 recalledIds 的精确过滤。

## 后续优化方向

1. **每轮召回**: 在每次 `session.sendMessage` 前调用 prefetch 更新召回内容
2. **精确过滤**: 实现 recalledIds 追踪，防止召回内容被二次抽取
3. **召回策略**: 支持 scope 过滤（global/stock:X/strategy:Y）
4. **批量 validate**: 优化为批量更新 last_recalled_at 接口
