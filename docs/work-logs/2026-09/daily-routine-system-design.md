# 每日固定动作体系设计报告（D1 全周例程）

**版本**: v1.0
**日期**: 2026-09-01
**设计者**: investor (w-5b8aac2a)
**目标**: 让"炒股目标"不依赖临场发挥——每天、每周有固定节奏，把交易宪法和 10 条操作规则固化为可执行的动作序列。

---

## 一、设计原则

1. **以交易时段为骨架**：A 股 9:30-11:30 / 13:00-15:00 是唯一可执行买卖的窗口，所有动作围绕它排布——盘前准备、盘中执行、盘后复盘、夜间维护。
2. **规则绑定**：每条动作都对应宪法/规则条款（R-001~R-010），规则要求"每日必做"的（如 R-004 盘后复盘、R-007 熔断检查）必须有固定动作兜底。
3. **按日型差异化**：
   - **周一** = 周度开局（消化周末消息、周级仓位规划、上周教训应用）
   - **周二~周四** = 标准交易日（标准例程）
   - **周五** = 周度收官（周复盘、周报、周末持仓决策、防周末风险）
   - **周六** = 数据与策略维护日（补数据、回测、进化）
   - **周日** = 周度总结与规划日（学习蒸馏、验证门、下周计划）
4. **零交易合法**：固定动作 ≠ 每天必须交易。动作是"检查、确认、决策"，交易只在有信号时发生。
5. **自动化优先**：能交给 scheduler 定时触发的就用调度器；需要判断的（agent 模式）触发后唤醒 Agent 分析。

## 二、交易日（周二~周四）标准日——基线流程

### 时段总览

```
┌─────────────────────────────────────────────────────────────────┐
│  08:30-09:25  盘前准备（不可交易）                                 │
│  09:25-09:30  集合竞价观察（只观察不下单）                          │
│  09:30-11:30  上午盘中（可交易）                                   │
│  11:30-13:00  午间复盘（不可交易）                                 │
│  13:00-15:00  下午盘中（可交易）                                   │
│  15:00-16:30  盘后复盘（不可交易）                                 │
│  16:30-21:00  夜间维护（数据补录、系统维护）                       │
└─────────────────────────────────────────────────────────────────┘
```

## 三、周内差异日设计

### 周一（周度开局日）——在标准日基础上叠加

| 时间 | 叠加动作 | 工具 | 绑定规则 | 目的 |
|---|---|---|---|---|
| 08:30 | **周末消息消化** | web_search（周末重大政策/行业事件） | 宪法§5 | 周末 48h 信息空窗补齐 |
| 08:45 | **周级仓位规划** | regime_position_limit + rotation_proposal | R-006 | 本周权益仓位目标、行业配置 |
| 09:00 | **上周教训应用检查** | memory_search(experience, 上周) + genome_read(lessons) | 学习循环 | 上周亏过的场景本周是否还踩 |
| 13:00 | 周一午后方向确认 | sector_analysis | 主线 | 周一资金真实流向（早盘常失真） |
| 16:00 | **周一例会纪要** | feishu_notify(reports) | R-010 | 本周重点标的、关键位、风险清单 |

**周一特殊性**：
- 周末消息集中释放 → 开盘波动大，**早盘不追高、不抄底**（经验：恐慌市不接飞刀）
- 上周五收盘后到周一的跳空缺口是重要信号，观察缺口方向与回补
- 上周教训的"新鲜期"——马上应用防止遗忘

| 时间 | 叠加动作 | 工具 | 绑定规则 | 目的 |

| 14:30 | **周末持仓决策** | rotation_proposal + 决策 | R-006 | 决定持仓过周末还是轻仓（消息面不确定时减） |

## 五、职责分配与保障机制

### 角色分工
| 角色 | 负责 |
|---|---|
| **调度器（自动化）** | 定时唤醒：盘前/午间/盘后/夜间固定时点触发 |
| **Agent（本窗口）** | 被唤醒后执行判断型动作：晨会定调、信号分级、止盈止损决策、周报 |
| **盯盘引擎** | 实时价格触发（价格到位立即唤醒，不等定时） |
| **用户** | 仅做意图/偏好输入（如"止损 -5%"），不做状态输入（零手动输入协议） |

### 保障机制
1. **熔断兜底**：R-007 每日 16:30 强制检查，触发立即飞书高优告警——不可跳过
2. **对账兜底**：R-004 每日 16:00 trade_verify，异常列表明细
3. **数据兜底**：盘前 data_quality_report，数据缺漏时当日自动降级到"只观察不交易"
4. **失败告警**：任何定时任务连续 2 次失败，飞书告警 + 人工介入
5. **幂等保护**：regime_daily/mainline_scan 幂等，重复触发不重复落库

## 附录：交易日最小动作清单（速查卡）

**每天必做（雷打不动）**：
- 盘前：数据检查 → 情绪定调 → 持仓核对 → 晨会纪要
- 盘中：止损检查（每30min）→ 买卖确认链（quote→资金→regime→仓位→记忆→下单）
- 盘后：regime_daily → trade_verify（R-004）→ 熔断检查（R-007）→ 复盘纪要

**周差异**：
- 周一 +周末消息消化 +周级仓位规划 +上周教训应用
- 周五 +周末风险预检 +周末持仓决策 +周复盘 +周报
- 周六 +数据补录 +策略回测 +进化
- 周日 +蒸馏 +验证门 +下周计划

**纪律红线**：
- 9:30 前 / 11:30-13:00 / 15:00 后 不交易（宪法§1）
- 买入不检 R-001/R-008/R-009 不下单
- 浮亏触止损线必须卖（宪法§4）
- 无信号空仓等待 = 正确决策（宪法§6）

# 补充：特殊日子（事件驱动型）任务体系

> 固定 cron 覆盖不了**不固定的日子**——宏观数据发布、央行议息、财报披露、期货交割等。这些日子必须有**独立的事件驱动任务**：提前预警 → 当日采集 → 事后评估，三层闭环。

## 一、特殊日子分类总览

| 类别 | 日子规律 | 对持仓的影响 | 数据来源 |
|---|---|---|---|
| **国内宏观数据** | CPI/PPI 每月 9-11 日 9:30；PMI 每月末 9:30；国民经济运行（GDP/工业/固投/社零）每月 15-19 日 10:00 | 通胀→利率预期；GDP→经济周期；社零→消费板块 | 国家统计局发布日程表（每年 12 月底公布次年） |
| **央行货币政策** | LPR 每月 20 日 9:15（节假日顺延）；降准/降息不定期 | 利率中枢→估值分母；降准→流动性 | 中国货币网 LPR 报价 |
| **海外宏观/央行** | FOMC 每年 8 次会议（2026 具体日见下）；美国 CPI 每月中旬；非农每月第一周五 | 外资风险偏好；汇率；北向 | 美联储官网年度日历 |
| **公司财报** | 一季报 4/30 前、中报 8/31 前、三季报 10/31 前、年报 4/30 前；披露日预约制 | 业绩雷/超预期→个股剧烈波动 | 交易所预约披露表 |

## 三、事件驱动任务设计（三层闭环）

### 层1：事件预警（T-2/T-1 天）

**动作**：每日盘后检查未来 2 个交易日有无特殊事件，有则提前预警。

| 时间 | 动作 | 工具 | 目的 |
|---|---|---|---|
| 每日 16:45 | **事件日历检查** | 查事件表（维护中的日历）+ web_search | 未来 2 日事件清单 |
| 有事件时 | **预警通知** | feishu_notify(reports) | 提前告知：X 日将发布 CPI，注意消费板块波动 |
| T-1 盘后 | **事件预案** | 持仓影响评估（memory_write） | 该事件对持仓/候选标的的影响推演 |

### 层2：事件当日采集（发布时刻后）

| 事件 | 触发时刻 | 动作 | 工具 |
|---|---|---|---|
| CPI/PPI | 9:30 后（9:35） | 采集实际值 vs 预期 → 通胀方向判断 → 影响板块分析 | data_fetch_macro(cpi/ppi) + web_search |
| PMI | 月末 9:30 后 | 采集官方 PMI → 景气度判断（>50 扩张）→ 全市场定调 | data_fetch_macro(pmi) |
| GDP | 10:00 后 | 采集 GDP → 经济周期定位 → 周期/成长配置倾向 | data_fetch_macro(gdp) |
| LPR | 9:15 后（9:20） | 采集 LPR 是否调整 → 利率预期变化 → 银行/地产影响 | data_fetch_macro + web_search |
| FOMC | 次日盘前 8:30 | 采集决议/点阵图 → 外资态度/汇率/北向影响 → 盘前纪要 | web_search + data_fetch_north_flow |
| 财报披露日 | 披露后当日 | 采集持仓股业绩 → 与预期对比 → 雷/超预期分类 | data_fetch_financial + web_search |
| 交割日 | 开盘前/尾盘 | 提示交割日波动 → 盘中观察贴水 → 尾盘防异动 | 盘中观察（不主动交易） |

### 层3：事件事后评估（当日盘后）

| 时间 | 动作 | 工具 | 目的 |
|---|---|---|---|
| 事件日 15:30 | **事件复盘** | memory_write(experience) | 事件对市场的实际影响 vs 预案偏差 |
| 事件日盘后 | **教训沉淀** | experience_write（如适用） | 若事件导致持仓误判，记入经验库 |
| 周日 | **下周事件预告** | 周报中包含下周事件清单 | 提前一周可见 |

## 四、事件日历的维护机制

**核心问题**：特殊日子不固定，怎么保证任务知道哪天有事件？

**方案：事件日历表 + 每日检查任务**（不依赖固定 cron）

1. **建事件日历**（每年初/每季度维护）：
   - 每年 1 月初：导入当年 FOMC 官方日程、统计局全年发布日程（12月底公布）、LPR 固定日
   - 每季度：更新财报披露预约表（持仓+候选标的）
   - 不定期：两会、政治局会议、降准降息等以官方公告为准（web_search 兜底）

2. **每日检查任务**（固定 cron，逻辑查日历）：
   - `event-calendar-check` **每日 16:45**：查未来 2 日事件表 → 有事件则预警
   - 这样**固定任务 + 变动日历**组合，覆盖所有不固定的日子

3. **触发方式**：
   - 预警类：reports 频道（提前告知）
   - 重大事件（FOMC/降息/CPI 大超预期）：alerts 频道 high（影响持仓时立即提醒）
   - 事件当日自动唤醒 Agent 执行采集动作
