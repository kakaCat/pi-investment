## 二、规则生命周期状态机

```
created → active ──触发──→ active（冷却后继续）
              │
              ├─ 前提失效/偏离过大 ──→ paused（回收，可恢复）
              ├─ 使命完成（止盈/止损已执行）──→ archived（归档，保留历史）
              └─ 逻辑错误/重复/永久移出 ──→ deleted（删除）
```

**状态语义**：
- `active`：在监控（enabled=true）
- `paused`：回收（enabled=false，context 注明回收原因+恢复条件）
- `archived`：使命完成（enabled=false，context 补记结局，供复盘归因）
- `deleted`：物理删除（watch_triggers 外键 SET NULL，触发历史保留）

## 三、回收/归档/删除判定标准（量化）

### 自动巡检规则（每日盘后）

| 条件 | 动作 | 理由 |
|---|---|---|
| 持仓已清空且规则是持仓管理类 | **archived** | 使命终结 |
| 价格偏离阈值 >30%（僵尸位） | **paused**（context 记偏离度） | 不可能触发=噪音 |
| 14 天未触发 且 14 天未更新 context | **人工复核候选**（列入周报） | 可能过期 |
| context 里的前提条件过期（"待XX后"超 7 天未兑现） | **paused** | 前提失效 |
| 同标的重复规则（同条件类型+同方向） | 保留最新，其余 **deleted** | 去重 |
| 标的永久移出关注（基本面恶化/退市风险） | **deleted** | 无恢复价值 |

### 触发驱动治理（实时）

| 触发行为 | 治理动作 |
|---|---|
| 触发后结论连续 3 次"不操作/不买" | agent 评估：调整阈值 或 paused |
| 单条规则日触发 >10 次 | 自动加 cooldown（翻倍），仍超→paused |
| 触发时持仓状态与 context 不符（如已清仓） | 立即 archived + 告警 |

## 四、触发后通知决策树（direct vs agent vs agent+高优）

```
条件触发
   │
   ├─ 是持仓止损线（pnl_pct below / 跌破止损价）？
   │     └─ agent + 飞书高优（alerts）——时间不等人，止损铁律
   │
   ├─ 是持仓止盈/减仓评估？
   │     └─ agent（普通）——需要判断落袋比例
   │
   ├─ 是观察候选到价（买区/突破位）？
   │     ├─ 当日已触发过同标的 → direct（飞书即可，避免重复 LLM）
   │     └─ 首次触发 → agent（评估是否建仓）
   │
   └─ 是量能/波动异动（volume_surge/velocity）？
         └─ direct（信息性，放量本身不是决策）+ 仅当价格条件同触发才 agent
```

**成本纪律**：agent 模式触发 = 一次 LLM 调用。规则设计时就要问："这次触发需要动脑子吗？" 不需要动脑的（纯告知）用 direct。

## 五、触发次数与阈值进化（噪音治理闭环）

现状问题：阈值调整靠人肉记（#51 双环 2.5x→4x 是触发两天后手动改的）。

**设计：触发反馈闭环**
1. 每次触发落库时已带价格/结论
2. 盘后例程检查：规则 7 日内触发 ≥3 次且均未产生交易 → 列入"阈值优化候选"
3. Agent 在盘后复盘时评估：上提/下移阈值（贴近真实关键位），或改条件类型（价格→量价双条件）
4. 调整记录写入 context（变更历史可追溯）

## 六、巡检机制落地

**每日盘后（挂在 post-market-routine 后）**：
1. 规则-持仓一致性检查（持仓没了规则还挂着 → archived）
2. 偏离度检查（阈值 vs 现价偏离 >30% → paused 候选）
3. 触发频率检查（日触发 >10 → cooldown 翻倍）

**每周日（weekly-review 加一节）**：
1. 14 天未触发未更新清单 → 人工复核
2. 触发≥3 次未产生交易的规则 → 阈值优化评估
3. 规则覆盖率检查：持仓股是否都有止损止盈规则（换仓补位纪律）
