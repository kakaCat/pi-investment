# NaN JSON 序列化错误修复

**日期**: 2026-05-16  
**问题**: Python 返回的 JSON 包含 `NaN` 值，导致 TypeScript 端 `JSON.parse()` 失败

---

## 🔍 问题分析

### 错误现象
```
[python-daemon] Failed to parse response: 
{"code": "000004", "name": "*ST国华", "price": NaN, "change": NaN}

SyntaxError: Unexpected token 'N', ..." "price": NaN, "chan"... is not valid JSON
```

### 根本原因

1. **Python 端**: 某些股票数据包含 `NaN` 值（如停牌股票）
2. **JSON 序列化**: Python 的 `json.dumps()` 默认允许 `NaN`，输出为 `NaN` 而非 `null`
3. **TypeScript 端**: JavaScript 的 `JSON.parse()` 不接受 `NaN`（不是标准 JSON）

### 为什么会有 NaN？

- 停牌股票：价格和涨跌幅为 `NaN`
- 数据缺失：某些指标未披露
- 计算错误：除以零等异常情况

---

## ✅ 修复方案

### 1. 添加 NaN 清理函数

**文件**: `python/akshare_bridge.py`

```python
import math

def clean_nan_values(obj):
    """
    递归清理对象中的 NaN 和 Infinity 值，转换为 None
    """
    if isinstance(obj, dict):
        return {k: clean_nan_values(v) for k, v in obj.items()}
    elif isinstance(obj, list):
        return [clean_nan_values(item) for item in obj]
    elif isinstance(obj, float):
        if math.isnan(obj) or math.isinf(obj):
            return None
        return obj
    else:
        return obj
```

### 2. 创建安全的 JSON 序列化函数

```python
def safe_json_dumps(obj, **kwargs):
    """
    安全的 JSON 序列化，自动处理 NaN/Infinity
    """
    # 先清理 NaN/Infinity
    cleaned_obj = clean_nan_values(obj)
    
    kwargs.setdefault('ensure_ascii', False)
    kwargs.setdefault('default', json_serializer)
    return json.dumps(cleaned_obj, **kwargs)
```

### 3. 替换所有 json.dumps() 调用

将所有 `json.dumps()` 替换为 `safe_json_dumps()`：

```python
# 修复前
print(json.dumps(response, ensure_ascii=False, default=str), flush=True)

# 修复后
print(safe_json_dumps(response), flush=True)
```

## ⚠️ 注意事项

### 1. 数据语义

`NaN` → `null` 的转换是安全的，因为：
- 前端可以统一处理 `null` 值
- 避免了 JSON 解析错误
- 保持了数据结构的完整性

### 2. 业务逻辑

前端需要处理 `null` 值：
```typescript
if (stock.price === null) {
  return "停牌";
}
```

### 3. 性能影响

`clean_nan_values()` 递归遍历整个对象，但：
- 数据量通常不大（< 1000 条记录）
- 性能影响可忽略（< 1ms）
- 避免了更严重的 JSON 解析失败
