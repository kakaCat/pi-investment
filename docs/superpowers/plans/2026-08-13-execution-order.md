# 全局执行顺序与批次图（召回重设计 + 三 Agent 拆分）

- 日期：2026-08-13（v2：改为 k3/执行模型严格交替）
- 适用计划：`2026-08-13-memory-recall-redesign.md`、`2026-08-13-agent-domain-split.md`
- **执行约束：k3 与执行模型不能并行，只能交替。** 同一批内、同属执行模型的多个任务可开多个并行会话；批次切换时上一批必须全部完成（或明确放弃）才进下一批。
- k3 批次 = 验收合并上一批 + 做 k3 专属任务；执行模型批次 = 派发该批任务并等全部回执。

## 批次明细

### 批次 1【执行模型】— 6 个任务并行（文件全不相交）

| 任务 | 计划 | 一句话内容 |
|---|---|---|
| P0-T1 | 召回 | v2 hybrid_search 加 cosine_floor 质量门 + pytest |
| P1-T1 | 召回 | agent-ts 领域层四文件（types/policy/quality-gate/XML，纯函数） |
| P1-T4 | 召回 | v2 审计 PG 表 + 4 条 API + pytest |
| P1-T5 | 召回 | 前端「召回审计」tab（契约已冻结；最终验收等批次 3 部署） |
| A0-T1 | 拆分 | 工具注册表四组拆分 + 等价性测试 |
| A0-T2 | 拆分 | 三 Agent RoleProfile 声明 + 测试 |

派发方式：每个任务 =【通用执行规则】+ 任务一节，一个会话一个任务；并行会话数按你的带宽定。
防冲突约定：**P0-T1 独占 `domain/memory/service.py`；P1-T4 禁碰 `service.py`/`hybrid_search.py`**。

### 批次 2【k3】— 验收 + 3 个专属任务

1. 逐任务验收批次 1（对契约核对 → 亲自跑验收命令 → 回查事实源）→ 全部合并进 main；
2. **P0-T2**：生产语料分数分布测量，定 floor 终值（输出给批次 3 的 P0-T3）；
3. **P1-T2**：RecallService 编排 + 端口接口（依赖 P1-T1 已合并）；
4. **A0-T3**：会话工厂 agentKind 装配——拆分计划总闸门（依赖 A0-T1+T2 已合并）。

出口标准：floor 终值确定；P1-T2、A0-T3 合入 main；全量测试对照基线无新增失败。

### 批次 3【执行模型】— 5 个任务并行

| 任务 | 计划 | 进入本批的依赖（批次 2 已满足） |
|---|---|---|
| P0-T3 | 召回 | P0-T1 已合并 + floor 终值（env 写入 + 重启 5001 + curl 实测） |
| P1-T3 | 召回 | P1-T2 端口已定义（审计适配器：v2 主写 + JSONL 降级） |
| A1-T1 | 拆分 | P1-T4 API + A0-T3（recall_audit 工具 + 记忆 Agent 会话接入） |
| A2-T1 | 拆分 | A0-T3（进化提示词五条款 + skill 读写工具；**提示词文案批次 4 k3 审**） |
| A3-T1 | 拆分 | A0-T3（Channel 层渠道微调） |

另：本批含 P1-T5 的最终验收（P1-T4 已部署后真机点页面）。

### 批次 4【k3】— 验收 + 接线四连

1. 逐任务验收批次 3（含 A2-T1 提示词五条款逐条核、A3-T1 快照 diff 仅 Channel 层）→ 合并；
2. **P2-T1**：SDK 扩展接线（input 暂存原文 + before_agent_start 注入）；
3. **P2-T2**：删 wrapper 注入代码，迁测试；
4. **P2-T3**：全通道验收（TUI/调度/wake 各有真实审计记录）；
5. **A2-T2**：weekly_evolution 迁移进化 Agent，干跑验证（提案落 evolution 域、代码库零改动）。

出口标准：生产 agent 重启后召回走新通道；`/provider pro` 与 skill 调用实测正常；审计表三类 flow 有记录。

### 批次 5【执行模型】— 1 个任务

| 任务 | 内容 |
|---|---|
| A1-T2 | 每日召回审计任务注册（cron `0 19 * * *`，agentKind=memory；prompt 文案批次 6 k3 审） |

### 批次 6【k3】— 收尾与观察期

1. 验收 A1-T2（文案逐条审）→ 合并；
2. 手动 trigger `daily_recall_audit` 一次，验证 PG 出现 `feedback_by='agent'` 标注；
3. 启动 P3/A4 观察期：一周后按标注集离线重放调 floor、三 Agent 分账统计；
4. 两份计划状态全部 ✅ 后归档。

## 交替纪律

- 批次内执行模型任务全部回执前，k3 不提前开工下一批 k3 任务的依赖部分（可先审已回执的单任务）。
- 打回（❌）不切换泳道：同一执行模型会话内返工，直到 👀。
- 任何批次发现契约本身有问题 → 停下改计划文档，再续跑（不许执行模型绕过契约）。
