## 1. 设计哲学

### 1.1 阀门模型

```
输入流（行情/信号/财报/新闻）
    → 阀门组（prompt · skill · 工具配置 · 策略yaml）
        → 决策（买 / 卖 / 持有 / 踏空 / 割肉）
            → 结果（账户盈利率）
```

- prompt/skill/工具是**阀门**：不直接产生结果，调制输入流如何转化为决策
- 好输入 + 好阀门配合 → 好结果（账户盈利率是北极星指标）
- 决策打分是阀门与结果之间的**归因机制**

### 1.2 三权分立

| 角色 | 承担者 | 权限 | 禁令 |
|---|---|---|---|
| 行政（执行） | **执行 agent** | 买卖决策（唯一交易者） | 不做任何系统修改 |
| 司法（裁判） | **裁判 agent** | 裁决/提案/验证（唯一裁判） | 不碰交易；自身阀门改动需人类批准 |
| 执法 + 档案 | **quantsys-v2** | 计算/存储/状态机/展示（纯服务，无判断权） | 不做任何"判"字辈决定 |

**核心原则：判断是智能行为，只能由 agent 承担；v2 是程序，只提供计算、存储、展示、机械执行服务。** v2 把数字算准、证据摆全；裁判 agent 解读数字、下达裁决；v2 再机械执行裁决（文件写回、git commit、状态流转）。

执行 agent 与裁判 agent 物理隔离（独立会话/独立提示词），只通过 v2 存储对话——防止"运动员兼裁判"的利益冲突。

### 1.3 双循环

- **执行循环（快，每日）**：目标=盈利。执行 + 记录，不学习、不行动于系统。
- **进化循环（慢，裁决驱动）**：目标=判断，不盈利。看打分时间线，裁决是否进化、进化什么。
- 两个循环只通过数据库对话：执行循环写 `agent_decisions`，进化循环读它；进化循环写 `agent_knowledge` 和新阀门版本，执行循环下次决策时消费。

### 1.4 盈利是时间线不是点

单次复盘看到的是噪声。"判断是否需要进化"是系统最难的部件：需要持续性证据（CUSUM 式累积偏移）而非单点触发；需要市场剥离（熊市 ≠ 阀门的错）；需要双向触发（劣化 OR 踏空持续）。

### 1.5 经验固化（正向通道）

来自人类交易者实践（trading journal / deliberate practice）：

- 盈利单必须复盘，且要区分**实力盈利 vs 运气盈利**（wicked learning environment：市场对两者给出相同反馈）
- 决策时的 reasoning 与实际驱动因素一致 → 实力，固化为经验；不一致 → 运气，不固化
- 单次盈利只是线索：同类经验重复 N 次才从 `testing` 升 `active`
- active 经验回喂决策上下文，同时成为阀门变更的**保护清单**（进化不得洗掉已验证优势）
- **证据链门禁（No Execution, No Memory，借自 GenericAgent）**：固化条目必须引用执行证据（哪次工具调用、哪条决策记录、哪条打分），没有证据链的一律不入库——对治 2026-08 自我进化审计发现的"蒸馏写入未验证经验"

## 3. 核心机制

### 3.1 决策打分（DecisionScorer，v2 计算服务）

四类决策全覆盖结果空间，T+20 交易日、基准（沪深300）调整、归一化 [-1,1]，分档大胜/小胜/小错/大错：

| 决策 | 打分 |
|---|---|
| 买入 | 持有收益 vs 基准 |
| 卖出 | 躲过下跌=正；割肉（卖完反弹）=负 |
| 信号未行动 | 踏空（信号后续涨）=负；正确观望=正 |
| 持有不动 | 浮动表现 |

- 踏空数据链：signals 表 → 对照 agent_decisions 找"有信号无决策" → daily_klines 算信号后走势
- 回写 `agent_decisions.evaluation_result` + 新增 `score` 列，激活现有 pending→evaluated 断头管道
- 每日调度自动跑（纯算术，v2 可做；分数只是待裁判解读的原料）

### 3.2 四层进化节奏

每层思考目标不同、**修改权限逐层下沉、自修改禁令**（任何层不能改自己的逻辑）、思考记录逐层上浮：

| 层级 | 节奏 | 思考目标 | 可修改对象 | 生效 |
|---|---|---|---|---|
| 日 | 每日 | 盈利 + 记录（复盘只积累不行动） | 仅买卖决策 | — |
| 周 | 每周 + CUSUM 报警事件 | 阀门要调吗（健康/观察/需进化） | 日层文本参数 | 全自动 |
| 月 | 每月 | 进化机制本身有效吗（裁决准确率） | 周层逻辑：判定器阈值/门配置/打分权重 | 全自动（状态机，影子期更长） |
| 年 | 每年 | 系统还适应市场生态吗 | 月层逻辑/指标定义/进化范围注册表 | **人类批准** |

层间对话唯一通道：`evolution_review` 表（层级/周期/输入摘要/推理过程/结论/动作）。周引用本周日复盘，月引用周裁决+日复盘，年引用全年记录。

### 3.3 裁判 agent 的裁决逻辑（周层为例）

1. 调 v2 服务取证据：分数时间线、CUSUM 统计量、基准走势、变更历史、agent 日志
2. 智能判断：噪声 vs 劣化（CUSUM 数字→裁判解读）；市场剥离；实力/运气鉴别；定位到哪层阀门
3. 三态裁决：`健康`（只记录）/ `观察`（延长积累）/ `需进化`（立案 + 生成提案）
4. 双向触发：劣化触发 + 踏空持续为负触发（赚着钱也可能需要进化）
5. 迟滞防振荡：连续越限才触发；进化生效后有观察静默期

### 3.4 变更状态机（v2 执法）

```
proposed → backtesting → shadow → promoted | rolled_back | rejected
```

- **严格单变量**：`text_param_change` 表部分唯一索引，`status IN ('backtesting','shadow')` 全局最多一条——一次只拧一个阀门，否则打分归因失效
- **提案纪律**：提案必须声明 `expected_effect`（预期影响哪个行为指标），说不清机理的提案进不了影子
- **分类型回测门**：strategy_yaml 走历史回测；prompt/skill 走 diff 静态审查（删风险规则直接拒）+ 裁判评审；tool_config 走沙盒调用验证。v2 跑出结果数字，**裁判看数字判通过与否**
- **影子判定**：影子期（默认 10 交易日）vs 基线期决策平均分对比，**按信号类别分组对比**（输入流不同期不同，同类别信号下的分才可比）。窗口满后裁判下令 promote/rollback，v2 执行文件写回 + git commit/revert + 重启生效
- **样本不足**：自动延长 5 日，最多两次，仍不足 rejected(无法评估)
- **回滚**：v2 从版本快照写回文件，教训写 `agent_knowledge`，同参数相似提案 30 天冷却（学习率衰减）

### 3.5 版本保存

- 文件仍是运行时真相源；v2 的 `text_param_version` 表存**全量内容快照**（before/after 全文），是版本的权威档案
- web 端直接渲染 diff；回滚不依赖 git；git 历史降级为第二副本

### 3.6 问题台账（保证发现问题→修改问题闭环）

`evolution_problem`：`open → proposed → fixing → verifying → closed_fixed（附验证证据）| closed_wontfix（必填理由）`

- 裁判每次"需进化"自动立案，关联证据链
- 问题不关闭永不消失：dashboard 按账龄排序，open 超 30 天升级告警
- 关闭必须附验证证据：修复后同类别信号的决策分确实改善（回头查打分表）
- 工具代码/agent 架构类问题：台账条目即开发任务书（问题+证据+建议方向），走开发流程修复后回 verifying

### 3.7 工具打分

v2 对每个 agent 工具建评分卡：调用次数/成功率/延迟/**下游决策引用分**（用了该工具输出的决策的分均值）。工具分持续垫底 → 裁判立案 → 配置问题走状态机，代码问题走台账。

### 3.8 日志能力

v2 记录两类 agent 的运行日志（裁判取证的原料）：

- `agent_run_log`：时间戳/agent 角色(executor|judge)/session/level/事件类型(tool_call|llm_error|decision|retry|...)/payload JSONB/关联 ID
- **报错一等公民**：LLM 错误（含 stopReason）、工具失败、重试链必须完整落库（教训：2026-07-25 LLM 401 被静默吞掉事故）
- agent-ts 侧 logger 批量上报 `POST /api/agent-logs`；裁判 agent 可调日志查询服务作为裁决证据

### 3.9 防断链

- 所有调度 job 写心跳；看门狗规则：shadow 超 2×窗口未判定 → 告警；proposed 积压 >7 天 → 告警；心跳缺失 → 告警
- cron 注册纳入验收清单：新 job 上线必须在 dashboard 可见"最近运行时间"


## 5. 四种能力杠杆 × 修改通道

| 杠杆 | 修改通道 | 生效 |

| 系统提示词 | 文本参数状态机（全自动） | 外置文件→改文件→重启 |
| skill | 文本参数状态机（全自动） | 同上 |
| 工具-配置 | 文本参数状态机（全自动） | 配置热改 |
| 工具-代码 | 问题台账 → 开发任务 → PR | 版本发布 |
| agent 架构 | 问题台账 → 年层提案 → **人类批准** → 开发实现 | 版本发布 |

前置工程：提示词从 `system-prompt-builder.ts` 硬编码外置为 `.pi-invest/bootstrap/prompts/*.md`，验收标准=外置前后 system prompt 逐字节一致（快照测试）。**外置时顺手做索引/细节分层**（借自 GenericAgent L0–L4：索引文件 ≤30 行硬约束，只留"场景关键词→文件"指针，细节按需 file_read）——MEMORY.md 60+ 条全量进上下文本身就是待进化的文本参数，结构质量决定裁判未来改动它的粒度，避免外置完再重构一次。

## 6. 子项目切分

每个子项目独立交付、独立可用，按依赖顺序实施：

| # | 子项目 | 内容 | 依赖 | 独立价值 |
|---|---|---|---|---|
| P0 | 可观测性地基 | agent 日志采集（`agent_run_log` + 上报管道）+ DecisionScorer 打分服务 + `agent_decisions.score` + 踏空捕获 | 无 | 决策评估从此闭环；报错不再被吞 |
| P1 | 裁判 agent 骨架 | 独立会话/提示词 + cron 唤醒（先日/周层）+ 调 v2 证据服务 + 裁决落 `evolution_review` | P0 | 有人看数据了；裁决开始积累 |
| P2 | 文本参数状态机 | 提示词外置 + registry/change/version 三表 + 单变量互斥 + 回测门 + 影子流转（裁判下令/v2执法）+ 自动生效/回滚 | P1 | 阀门可以安全地被修改 |
| P3 | 问题台账 + 工具打分 | `evolution_problem` 生命周期 + 验证关闭 + 工具评分卡 | P1（P2 后更完整） | 发现问题必被跟踪到修复 |
| P4 | 经验固化 | 大胜归因 + 实力/运气鉴别 + 重复确认升级 + 回喂 + 保护清单 | P0, P1 | 正向学习通道 |
| P5 | 展示层 | web 进化区 4 页：总览/参数档案/问题台账/工具排行榜 | P1-P4 的 API | 人类监督窗口 |
| P6 | 元层（月/年） | 月层机制评审 + 年层架构提案（人类闸门） | P1-P3 稳定运行后 | 进化机制自身可进化 |

实施顺序：P0 → P1 → P2 →（P3、P4 可并行）→ P5 → P6。

### 6.1 架构改进 Backlog（GenericAgent 调研衍生，2026-08-07）

以下来自 `docs/generic-agent-lessons-report.md`，属于"agent 架构杠杆"，走问题台账→开发任务通道，不进文本参数状态机。实现配方见本地克隆 `/Volumes/ORICO/doc/github/GenericAgent`：

1. **引擎侧纠偏注入**（对标 turn%13/31/175）：按轮次周期注入 checkpoint/换策略/写盘/上报提示，防长跑死循环——agent loop 一处改动
2. **no_tool 拦截器**：空响应重试 / 大代码块追问"执行还是展示" / 无验证痕迹拦截完成声明——对治"光说不练"和 LLM 静默失败
3. **大结果写盘+引用返回**：返回最大的 5 个工具先改，防上下文被数据灌爆
4. **多模型自动 fallback**（对标 MixinSession）：一家 401/超时自动切下家且保留历史——防 LLM 401 静默丢失复发
5. **Goal Mode（时间预算自驱循环）**：P6 元层候选机制，与四层节奏互补——周蒸馏管沉淀，Goal Mode 管饱和投入
6. **子 agent 文件协议兜底**（_intervene/_keyinfo）：wake channel 之外的可调试干预通道

## 7. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 打分窗口 20 日导致反馈慢 | 接受。慢反馈 > 错反馈；踏空/割肉类信号补充密度 |
| 影子期市场输入流与基线期不同 | 按信号类别分组对比；shadow_result 强制记录窗口市场走势 |
| 裁判 agent 自我美化 | 裁判阀门改动需人类批准；裁决记录全程留痕可审计 |
| 调度断链（历史教训） | 心跳 + 看门狗告警 + cron 注册验收清单 |
| 全自动改生产的风险 | 单变量 + 回测门 + 影子期 + 自动回滚 + 30 天冷却，五重防线 |
| LLM 错误被静默吞掉（历史事故） | agent_run_log 报错一等公民，裁判取证可见 |
| 奖励投机（agent 学会刷分，如少交易避免负分） | **踏空分是天然解药**：不行动也被打分，躲不掉；P0b 非可选而是防博弈关键部件；过程质量分 + 裁判审计兜底 |
| 劣进化（多轮进化后遗忘原始对齐约束） | 裁判阀门人类批准 + 经验保护清单 + **月层评审固定检查"核心风险规则是否仍完整"**（抗遗忘指标） |

## 8. 明确不做（YAGNI）

- 不做工具代码的自动修改（进化系统只立案，写代码走开发流）
- 不做梯度式 RL / 模型微调（样本量不支持，文本参数进化是合理替代）
- 不做 prompt 改动的历史案例重放（重放推理 ≠ 真实行为，制造假信心）
- P6 之前不做月/年层自动化
- v2 不做任何裁决逻辑（无判断权原则）

## 附录 A：学术框架对照（Self-Evolving Agents 综述，2026-08-07 用户提供）

本设计在 What/When/How/Where 框架中的位置：

- **三大进化特征**：自身交易经验驱动 ✓、状态机 promote 持久变更 ✓、裁判主动裁决 ✓——满足自进化定义
- **What**：覆盖 上下文（prompt/skill/记忆）+ 工具（配置层）+ 架构（走开发通道）三大组件；模型权重明确不碰（YAGNI，日级样本量不支持微调）
- **When**：四层节奏 = inter-test-time 批量进化；盯盘唤醒 = intra-test-time 适配（不留持久变更，分工正确）
- **How**：外部奖励（决策打分）+ 文本反馈（裁判反思）混合；策略排行榜带种群选择色彩
- **成熟度路线**：proto-evolution（P0-P5）→ strong self-evolution 的入口是 P6 元层（自主诊断缺陷 + 全栈重构提案）
- **评估体系**：静态=每日打分快照；短周期=影子期对比；长周期=月/年层评审（能力留存/泛化/抗遗忘）
- **进化形式**：f(Π, τ, r) = Π′ 中，Π′ 的变更面 = 文本参数 + 配置，f = 裁判 agent + 状态机
