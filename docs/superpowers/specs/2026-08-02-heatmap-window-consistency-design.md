# 热力图窗口口径一致性设计（阈值剔除）

- 日期：2026-08-02
- 状态：已批准
- 上游文档：[2026-07-31-stock-heatmap-design.md](2026-07-31-stock-heatmap-design.md)（容忍端点配对，spec §4.3 修订）
- 范围：**仅后端**（quantsys-v2），前端零改动

## 1. 背景与问题

热力图自 247769d 起采用「容忍端点配对」：每只股票用窗口 `[d0, dn]` 内**实际可得的**最早/最晚收盘计算涨跌，并通过 `start_date`/`end_date` 透传实际区间。这解决了回填稀疏期严格配对全剔除的问题，但引入两个口径缺陷：

- **P1 窗口不可比**：同一 treemap 上，7/28 起（3 天数据）的股票与 7/3 起（20 天数据）的股票颜色直接对比。3 日 +5% 与 20 日 +5% 颜色相同，含义完全不同——误导性可视化。
- **P3 数据陈旧**：63 只股票 `last_date ≤ 7/16`（陈旧约两周）仍参与展示与判断验证。

评估同时指出 P2（覆盖稀疏，20 日窗仅 3 行业 710 只）——那是底层回填问题，**不在本设计范围**。

### 1.1 生产数据实测（2026-08-02，quant.daily_klines，窗口 7/3→7/31）

| first_date | 股票数 | 含义 |
|---|---|---|
| 7/3（完整） | 1009 | 全窗口 |
| 7/8 | 4012 | 缺 3 天，基本可比 |
| 7/28 | 311 | 仅 3-4 天，不可比 |
| 7/30 | 1 | 不可比 |

| last_date | 股票数 | 含义 |
|---|---|---|
| 7/31（新鲜） | 3768 | — |
| 7/30 | 1502 | 差 1 天，可接受 |
| ≤ 7/16 | 63 | 陈旧两周，应剔除 |

结论：严格端点配对（要求 first_date = d0）会剔掉 81%，不可行；但 7/8 批与 7/28 批界限分明，50% 覆盖率阈值可精确切开：保留约 94%，仅剔约 6% + 陈旧 63 只。

### 1.2 被否决的备选方案

- **归一化 change_pct**（按实际天数外推全窗等效）：外推是虚构数字（3 日 +5% → 20 日等效 +37%），动量假设不成立；且 `verify_judgments` 工具消费同一端点，信号对错会按虚构收益判定，污染判断验证。
- **只剔陈旧**：改动最小但 P1 未解决。
- **前端标记/归一化**：用户决定本轮前端零改动，口径由后端保证。

## 2. 设计

### 2.1 Repository 层

`HeatmapRepository.get_range_closes` 返回值每只股票增加 `days` 字段（区间内实际 K 线条数）。行已全量查出，仅顺手计数，SQL 不变：

```python
{symbol: {'first_date', 'first_close', 'last_date', 'last_close', 'days'}}
```

### 2.2 Service 层

`HeatmapService._build_data` 在现有「区间内不足 2 个交易日剔除」之外，增加两条剔除规则；被剔股票计入 `excluded_count`（与现有剔除共用计数，不新增响应字段）。

**规则① 覆盖率**：

```
days >= max(2, ceil((window + 1) * 0.5))
```

`window + 1` 是窗口理论点数（d0→dn 含 window 个间隔、window+1 个交易日）。20 日窗需 ≥11 点：7/8 批（18 点）保留，7/28 批（4 点）剔除。

**规则② 新鲜度**：

```
last_date >= dn 往前 K 个交易日，K = max(1, window // 5)
```

20 日窗 K=4：last_date = 7/30（差 1 天）保留，≤ 7/24 剔除。window=1 时 K=1，防止「1 日涨跌」算在错误的两天上。参照交易日序列取 service 已有的 `get_trade_dates_up_to` 结果（dn 本身含在序列内，K 个间隔往前）。

### 2.3 边界与不变量

- **window=1**：规则① 退化为现有「≥2 点」规则，行为不变。
- **partial（验证窗未满）**：新鲜度相对于 `actual_end_date`（dn）而非今天，不受影响。
- **行业聚合**：`industries[].change_pct` 对剔除后的剩余股票加权，口径自然一致，无需改动。
- **API 响应结构不变**：无新字段；`excluded_count` 增大，前端既有提示「N 只股票停牌/缺数据未显示」自动生效，文案语义仍成立。
- **verify_judgments 受益**：agent 判断自校验走同一端点，自动获得一致口径。
- **前端零改动**。

## 3. 错误处理

- 交易日序列不足 K+1 天（极端：回填极早期）：新鲜度阈值取序列第 0 天，即规则② 实际不生效，仅靠规则①——宁可放宽不可全剔。
- `days` 计数依赖现有行遍历，无新查询、无性能回退。
