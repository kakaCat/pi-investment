# Memory MoA 设计思路详解

> **目的**: 解释当前设计的逻辑，然后对比你的想法

---

## 🤔 我的设计思路（当前方案）

### 核心逻辑：按**属性维度**划分空间

```
同一条记忆，可能同时属于多个空间
例如：一条"昨天的买入决策"
  ✅ 属于短期记忆（时间维度）
  ✅ 属于决策记忆（类型维度）
```

---

## 📊 4 个空间的定义

### Space 1: 短期记忆（时间维度）

**定义**: 最近 7 天的记忆

**为什么权重 1.5？**
- 最近的信息通常更相关（时效性）
- 符合"近因效应"（Recent Effect）
- 例如：查询"最近的交易"，短期记忆最重要

**SQL 查询**:
```sql
SELECT * FROM memories 
WHERE namespace_id = ? 
  AND created_at >= NOW() - INTERVAL '7 days'
  AND content LIKE '%查询关键词%'
ORDER BY created_at DESC
LIMIT 5;
```

**示例记忆**:
```
记忆 1: "今天上午买入 600519，理由是..."（2天前）
记忆 2: "昨天收盘后分析，市场..."（1天前）
记忆 3: "上周五的决策回顾..."（5天前）
```

---

### Space 2: 长期记忆（时间维度）

**定义**: 所有时间的记忆，按重要性排序

**为什么权重 1.0？**
- 标准权重，作为基准
- 覆盖历史所有经验
- 例如：查询"历史上类似情况"，长期记忆重要

**SQL 查询**:
```sql
SELECT * FROM memories 
WHERE namespace_id = ? 
  AND content LIKE '%查询关键词%'
ORDER BY importance DESC, created_at DESC
LIMIT 5;
```

**示例记忆**:
```
记忆 1: "2024年8月的牛市经验..."（6个月前，重要性 9）
记忆 2: "关于止损的教训..."（1年前，重要性 8）
记忆 3: "缠论顶分型判断..."（3个月前，重要性 7）
```

---

### Space 3: 决策记忆（类型维度）

**定义**: category = 'decision' 的记忆

**为什么权重 1.2？**
- 决策类记忆更具有**行动指导价值**
- 查询"之前怎么做的"，决策记忆最有参考意义
- 稍高于标准权重，但低于短期记忆

**SQL 查询**:
```sql
SELECT * FROM memories 
WHERE namespace_id = ? 
  AND category = 'decision'
  AND content LIKE '%查询关键词%'
ORDER BY confidence DESC, created_at DESC
LIMIT 5;
```

**示例记忆**:
```
记忆 1: "决策：买入 600519，理由..."（决策类型）
记忆 2: "决策：止损 002594，理由..."（决策类型）
记忆 3: "决策：观望，理由..."（决策类型）
```

---

### Space 4: 知识记忆（类型维度）

**定义**: category = 'knowledge' 且 importance >= 7

**为什么权重 1.0？**
- 知识类记忆是**背景知识**，不是直接答案
- 例如：查询"如何判断顶分型"，知识记忆提供理论基础
- 标准权重

**SQL 查询**:
```sql
SELECT * FROM memories 
WHERE namespace_id = ? 
  AND category = 'knowledge'
  AND importance >= 7
  AND content LIKE '%查询关键词%'
ORDER BY importance DESC
LIMIT 5;
```

**示例记忆**:
```
记忆 1: "缠论笔段的定义..."（知识类型，重要性 8）
记忆 2: "MACD 指标的含义..."（知识类型，重要性 7）
记忆 3: "K线形态分析方法..."（知识类型，重要性 9）
```

## 🔄 聚合过程示例

### 查询: "最近的买入决策"

**Step 1: 并行搜索 4 个空间**

| 空间 | 结果数 | Top 记忆 |
|---|---|---|
| 短期记忆 | 5 条 | "今天买入 600519"（3天前） |
| 长期记忆 | 5 条 | "上月买入 000001"（30天前） |
| 决策记忆 | 5 条 | "决策：买入 600519"（3天前） |
| 知识记忆 | 5 条 | "买入时机判断方法"（知识） |

**Step 2: 应用空间权重**

```
记忆 A: "今天买入 600519"
  - 在短期空间: score = 0.95 × 1.5 = 1.425
  - 在决策空间: score = 0.90 × 1.2 = 1.080
  - 最终 score = max(1.425, 1.080) = 1.425
```

**Step 3: 去重 + 排序**

```
记忆列表（去重后）:
1. "今天买入 600519" (score 1.425)
2. "昨天观望决策" (score 1.35)
3. "上周卖出 002594" (score 1.20)
4. "上月买入 000001" (score 0.95)
5. "买入时机判断方法" (score 0.80)
```

**Step 4: MMR 多样性重排**

```
最终结果（平衡相关性 + 多样性）:
1. "今天买入 600519" (最相关)
2. "昨天观望决策" (相关 + 不同动作)
3. "买入时机判断方法" (相关 + 知识背景)
4. "上周卖出 002594" (相关 + 不同标的)
5. "上月买入 000001" (相关 + 历史参考)
```

## 🤔 我理解的问题

### 你可能的疑问

**疑问 1**: 为什么是"属性维度"而不是"独立空间"？

**我的设计**:
```
同一条记忆可以在多个空间出现
例如："今天的买入决策"同时在短期空间和决策空间
```

**你可能想要的**:
```
不同空间是完全独立的，互不重叠
例如：MoA 中的不同模型是独立的
```

**疑问 2**: 为什么权重差异不大（1.0-1.5）？

**我的考虑**:
- 避免某个空间完全主导结果
- 短期记忆权重 1.5 vs 长期记忆 1.0，差异 50%

**你可能想要的**:
- 更大的权重差异？
- 或者完全不同的聚合方式？

## 💡 你的想法是什么？

### 可能的方向

#### 方向 A: 独立空间（像 MoA 中的不同模型）

```
Space 1: 专门负责"最近信息"的模型
  → 只查最近 7 天，不管类型

Space 2: 专门负责"决策建议"的模型
  → 只查决策类型，不管时间

Space 3: 专门负责"知识背景"的模型
  → 只查知识类型，不管时间

Space 4: 专门负责"情感记忆"的模型
  → 只查带情感标签的记忆
```

**特点**: 每个空间有**独立的职责**，类似 MoA 中每个模型有专长

---

#### 方向 B: 基于检索策略的空间

```
Space 1: BM25 全文搜索
  → 关键词匹配

Space 2: Vector 语义搜索
  → 语义相似度

Space 3: Graph 关系搜索
  → 基于记忆之间的关系

Space 4: Temporal 时序搜索
  → 基于时间模式
```

**特点**: 每个空间使用**不同的检索算法**

---

#### 方向 C: 基于 Agent 角色的空间

```
Space 1: fin-agent 的记忆空间
  → 交易决策、市场分析

Space 2: memory-agent 的记忆空间
  → 召回审计、知识蒸馏

Space 3: research-agent 的记忆空间
  → 研究报告、数据分析

Space 4: 共享记忆空间
  → 所有 agent 都能访问
```

**特点**: 按**Agent 身份**划分空间

---

#### 方向 D: 基于语义聚类的空间

```
Space 1: "交易决策"簇
  → 买入、卖出、止损相关

Space 2: "技术分析"簇
  → 指标、K线、形态相关

Space 3: "基本面"簇
  → 财报、行业、宏观相关

Space 4: "风险管理"簇
  → 仓位、止损、风控相关
```

**特点**: 按**语义主题**划分空间
