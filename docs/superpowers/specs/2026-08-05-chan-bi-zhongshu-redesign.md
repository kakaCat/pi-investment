# 缠论笔中枢重构设计

**日期**: 2026-08-05
**状态**: 已确认（用户逐节审定）
**前置**: `docs/superpowers/specs/2026-08-04-chan-memory-loop-design.md`（学习闭环已上线）

## 背景：旧实现的 4 个实质错误（实测确诊）

2026-08-04 学习闭环上线后，历史后验显示缠论信号无预测力（1买 0% 胜率、3买 17-40%）。
代码审查 + 12 只池内股票实测确诊：

1. **线段识别退化**：`_is_valid_segment` 只查"3 笔方向交替"，但笔天然交替 → 一整年笔序列连成 1-2 个"线段"（实测 12 股一年线段 0-3 个）
2. **中枢全灭**：中枢需 3 线段重叠 → 实测 12 股中枢全为 0 → 2买一年零触发、trend/背驰判断全部失真
3. **3买追顶**：任何上"线段"创新高即在线段最高点标记 3买（实测 bp.price == seg.high），标准定义是向上离开中枢后回抽不入中枢
4. **1买背驰失真**：比较对象是错误的"线段"，下跌中继误报（002129 报 1买后继续跌 8%）

## 目标

放弃线段层，以**笔中枢**为核心重构买卖点/背驰/走势判断，并对称实现卖点。
学习闭环（chan_scan/蒸馏/回喂）不变，用每周蒸馏胜率验证新算法真伪。

**用户确认的决策**:
- 买卖点一起做（1/2/3 卖对称实现）
- 背驰 = 围绕中枢的进入笔组 vs 离开笔组 MACD 面积比较；无中枢退化为最近两同向笔
- API segments 字段返回空数组（旧算法 deprecated）

## 新流水线

```
klines → KLineProcessor（包含处理，复用）→ BiIdentifier（分型+笔，复用）
  → BiZhongShuIdentifier（新）：连续 3+ 笔重叠 → 笔中枢
  → BiDivergenceDetector（新）：围绕中枢进出笔组 MACD 面积比较
  → BuyPointDetector（重写）：1/2/3买 + 1/2/3卖
  → BiTrendAnalyzer（新）：笔中枢数量与方向
```

## 笔中枢定义（BiZhongShu）

- **成立**：连续 3 笔（下-上-下 或 上-下-上）价格重叠：
  `ZG = min(三笔高点)`，`ZD = max(三笔低点)`，须 `ZG > ZD`
- **延续**：后续笔仍与 [ZD, ZG] 有重叠则并入；否则中枢结束
- 字段：`zg, zd, gg（极值高）, dd（极值低）, start_bi_idx, end_bi_idx, bi_count`
- 类型沿用 ZhongShu dataclass 或新增 BiZhongShu dataclass（见实现计划）

## 买卖点定义

| 类型 | 定义 | confidence / position_ratio |
|---|---|---|
| 1买 | 最后中枢后，离开下跌笔组 MACD 面积 < 进入下跌笔组 且价格新低（底背驰）；无中枢退化为最近两条同向下跌笔比较 | 0.9 / 1.0 |
| 2买 | 1买后首条上涨笔成立，其后回抽下跌笔低点 > 1买低点（不破前低） | 0.7 / 0.6 |
| 3买 | 向上离开中枢（上笔高点 > ZG）后，回抽下跌笔低点 > ZG（回抽不入中枢） | 0.5 / 0.3 |
| 1卖 | 与 1买对称（顶背驰：离开上涨笔组面积 < 进入笔组 且价格新高） | 0.9 / 1.0 |
| 2卖 | 1卖后首条下跌笔成立，回抽上涨笔高点 < 1卖高点（不破前高） | 0.7 / 0.6 |
| 3卖 | 向下离开中枢（下笔低点 < ZD）后，回拉上涨笔高点 < ZD（回拉不入中枢） | 0.5 / 0.3 |

**笔组**：同向笔及其间反向连接笔构成的连续跨度（用于 MACD 面积计算的 K 线区间）。
**背驰**：复用 `MACDCalculator.calculate_area(klines, start_idx, end_idx)`；
底背驰 = 离开笔组最低价 < 进入笔组最低价 且 |离开面积| < |进入面积|；顶背驰对称。

## 走势类型（BiTrendAnalyzer）

- ≥2 个中枢且依次上移（后中枢 ZD > 前中枢 ZG 方向向上）→ 上涨趋势；依次下移 → 下跌趋势
- 1 个中枢 → 盘整
- 0 个中枢 → 退化为首尾笔高低点比较（上抬=上涨/下压=下跌/其他=盘整）
- 返回值仍为 '上涨' / '下跌' / '盘整'

## 契约与兼容

- `POST /api/chan/analyze` 响应结构不变：
  - `segments: []`（旧 SegmentIdentifier 标记 deprecated，保留文件不删）
  - `zhongshus`：输出笔中枢（high=ZG, low=ZD, start_index/end_index=K线索引, type='笔中枢', segment_count→bi_count）
  - `buypoints`：新增 '1卖'/'2卖'/'3卖' 类型，结构不变
  - `trend_type` 取值不变
- ChanScanService 落库扩展：sell 类型 → `action='sell'`，`strategy_id='chan_1卖'/'chan_2卖'/'chan_3卖'`，confidence 同样 ×100
- 蒸馏器必须扩展支持 sell 信号：当前只统计 `action='buy'`，需纳入 `chan_*卖` 信号，判定规则与 verify_judgments 对称——sell & 跌 = 胜（future return < 0 计胜），胜率/均收益按 strategy_id 分别聚合
- 前端 buypoints 表格直接显示卖点，零改动；heatmap/verify_judgments 已支持 sell 信号判定

## 错误处理

- 笔数 < 5：zhongshus=[]，buypoints=[]，trend 退化判断
- MACD 数据不足（笔组跨度过短）：该背驰判 False，不产生 1买/1卖
- 同一位置多类型买卖点重叠：全部输出（由调用方按类型过滤），不互相抑制

## 测试策略

- 合成 K 线构造确定性场景（每个一场）：
  - 3 笔重叠 → 中枢成立；3 笔不重叠 → 不成立；中枢延续并入
  - 下跌+MACD 面积缩小+新低 → 1买；面积未缩小 → 无 1买
  - 6 类买卖点各构造一个触发场景 + 一个不触发场景
  - 趋势判断：双中枢上移=上涨/下移=下跌/单中枢=盘整
- 真实数据 sanity 测试（可选慢测试）：池内股票中枢数显著大于 0、2买/3买出现
- 回归：tests/chan 全部既有用例 + service 层契约测试

## 部署后验证（闭环自证）

1. 重跑历史回填（清掉旧 chan_* 信号重写）
2. 重跑蒸馏，对比新旧胜率
3. 观察 1 周定时扫描信号量（旧实现日均≈0，新实现应有合理信号流）

## 明确不做（YAGNI）

- 标准线段/特征序列法（方案 B，永久跳过除非笔中枢被数据证伪）
- 多级别联立/区间套
- 中枢扩展/延伸/新生/移动的细分类型（统一 '笔中枢'）
- 旧 SegmentIdentifier 删除（deprecated 标注即可）
