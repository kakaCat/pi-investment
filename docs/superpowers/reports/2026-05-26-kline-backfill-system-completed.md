## 📋 项目概述

实现了一个企业级的 K 线数据回填系统，用于检测和补充数据库中缺失的日线和分钟线数据。系统具备智能缺口检测、进度追踪、断点续传、重试机制等生产级特性。

### 核心特性

- ✅ **智能缺口检测**: 基于 A 股交易日历，自动跳过节假日和停牌日
- ✅ **断点续传**: 支持中断后从上次位置继续，不重复下载
- ✅ **批量处理**: 可配置批次大小，支持大规模数据回填
- ✅ **重试机制**: 指数退避重试（1s, 2s, 4s），最多 3 次
- ✅ **限流保护**: 0.1 秒请求间隔，避免 API 限流
- ✅ **原子写入**: 进度文件原子写入，防止崩溃导致数据损坏
- ✅ **完整文档**: 主文档 + 快速参考卡，50+ 个实用命令示例

## 🔧 使用示例

### 基础用法

```bash
# 1. 首次回填（2 年日线数据）
cd quant
python scripts/backfill_klines.py --data-type daily

# 2. 回填分钟线（1 年数据）
python scripts/backfill_klines.py --data-type minute

# 3. 回填特定股票
python scripts/backfill_klines.py --data-type daily --symbols 000001,600519

# 4. 自定义时间范围
python scripts/backfill_klines.py --data-type daily --target-days 365

# 5. 重置进度重新开始
python scripts/backfill_klines.py --data-type daily --reset-progress
```

### 日常维护

```bash
# 每日增量更新（crontab）
0 18 * * 1-5 cd /path/to/quant && python scripts/backfill_klines.py --data-type daily --target-days 7
```

## 🐛 已知问题和限制

### 限制

1. **分钟线仅支持 PostgreSQL**: SQLite 不支持分钟线数据（表结构限制）
2. **API 限流**: akshare 有请求频率限制，已通过 0.1s 延迟缓解
3. **停牌股票**: 停牌期间无数据，系统会跳过（符合预期）

### 已解决的问题

- ✅ O(n) 查询性能 → O(1) Set 查询
- ✅ 进度文件损坏风险 → 原子写入
- ✅ 数据库异常丢失进度 → DB 成功后才标记
- ✅ 硬编码路径 → 便携式路径处理
- ✅ 参数验证缺失 → 完整的输入验证
