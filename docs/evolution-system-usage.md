# Agent 自我进化系统 - 使用文档

**版本**: v1.0  
**最后更新**: 2026-05-14

---

## 概述

Agent 自我进化系统是一个基于控制论的负反馈控制系统，通过分析历史决策数据和盈利反馈，持续优化 Agent 的投资决策能力。

### 核心理念

系统采用经典的控制论反馈模型：

```
目标值（期望收益）
    ↓
减法器（比较器）：计算误差 = 目标 - 实际
    ↓
误差信号（目标差距）
    ↓
补偿器（控制器）：根据误差产生控制动作
    ↓
效应器（执行机构）：Agent 执行决策
    ↓
实际输出（盈利结果）
    ↓
反馈回路 ──────────┘
```

---

## 核心组件

### 1. 减法器（Comparator）

**作用**: 计算目标与实际的差距，并进行归因分析

**功能**:
- 计算性能差距（目标收益 - 实际收益）
- 判断目标是否合理（对比大盘、历史、波动率）
- 评估 Agent 能力（选股、决策质量、风控）
- 归因分析：区分目标问题 vs 能力问题

**输出**:
- 如果是目标问题 → 建议调整目标
- 如果是能力问题 → 触发补偿器优化

### 2. 补偿器（Compensator）

**作用**: 根据误差信号产生控制动作，调整 Agent 能力配置

**调整策略**:
- **小误差 (<2%)**: 微调参数、更新经验库
- **中误差 (2-5%)**: 新增/移除工具、更新经验库
- **大误差 (>5%)**: 重构策略、新增工具、更新算法

**调整内容**:
- ➕ 新增工具/数据源/算法
- ➖ 移除低效工具/失效算法
- 📝 更新经验库
- 🔧 调整参数（止损阈值、仓位比例等）

### 3. 经验库（Experience Base）

**作用**: 存储历史决策模式和结果，供 Agent 查询参考

**数据结构**:
```typescript
{
  scenario: "追涨买入",
  pattern: {
    conditions: ["当日涨幅>5%", "RSI>70"],
    action: "buy"
  },
  outcomes: {
    total_cases: 8,
    win_rate: 0.25,
    avg_return: -0.035
  },
  recommendation: "avoid",
  reason: "历史数据显示追涨买入胜率低，容易买在高点"
}
```

**Agent 查询方式**:
```typescript
query_experience({
  scenario: "当前市场情况描述",
  symbol: "600519",
  conditions: ["MACD金叉", "成交量放大"]
})
```

## 使用方式

### 自动触发（推荐）

系统每周日晚自动运行进化分析：

1. 收集本周数据（Session 日志、交易记录、持仓数据）
2. 计算本周表现（收益率、胜率、最大回撤等）
3. 减法器计算差距并归因
4. 生成进化报告和优化建议
5. 通知用户审核

**配置方式**:

在 `src/core/agent/bootstrap.ts` 中已配置定时任务：

```typescript
// 每周日 23:00 触发进化分析
cron.schedule('0 23 * * 0', async () => {
  await evolutionService.runWeeklyEvolution();
});
```

### 手动触发

如果需要立即运行进化分析：

```bash
# 通过 CLI 触发
npm run evolution:analyze

# 或在代码中调用
import { evolutionService } from './services/intelligence/evolution-service.js';
await evolutionService.runWeeklyEvolution();
```

### Agent 查询经验库

Agent 在决策时可以主动查询经验库：

**工具名称**: `query_experience`

**参数**:
```json
{
  "scenario": "MACD金叉且成交量放大，考虑买入",
  "symbol": "600519",
  "conditions": ["MACD金叉", "成交量放大>20%"]
}
```

**返回**:
```json
[
  {
    "scenario": "MACD金叉+成交量确认",
    "pattern": {
      "conditions": ["MACD柱>0", "成交量放大>20%"],
      "action": "buy"
    },
    "outcomes": {
      "total_cases": 12,
      "win_rate": 0.75,
      "avg_return": 0.058
    },
    "recommendation": "moderate",
    "reason": "历史数据显示该模式胜率较高",
    "confidence": 0.82
  }
]
```

## 数据结构

### 进化报告

**路径**: `.pi-invest/evolution/YYYY-MM.md`

**内容包含**:
1. 本月表现（收益率、胜率、回撤、夏普比率）
2. 减法器归因分析（目标合理性、能力评估）
3. Session 深度分析（成功模式、失败模式）
4. 工具效能评估（调用次数、胜率、ROI）
5. 补偿器调整方案（新增/移除工具、参数调整）
6. 预期效果和验证指标

### 经验库

**路径**: `.pi-invest/experience/experience-base.json`

**结构**:
```json
{
  "version": "1.0",
  "last_updated": "2026-05-31",
  "experiences": [
    {
      "id": "exp_001",
      "scenario": "追涨买入",
      "pattern": { ... },
      "outcomes": { ... },
      "recommendation": "avoid",
      "examples": [ ... ],
      "confidence": 0.88
    }
  ]
}
```

### 配置版本管理

**路径**: `src/core/agent/versions/`

每次应用优化建议后，系统会：
1. 保存当前配置为新版本（如 `system-prompt-v7.ts`）
2. 更新 `version-history.md` 记录变更
3. 在进化报告中标注配置版本

**回滚方式**:
```bash
# 查看版本历史
cat src/core/agent/version-history.md

# 回滚到指定版本
cp src/core/agent/versions/system-prompt-v6.ts src/core/agent/system-prompt.ts
```

## 工作流程

### 完整流程（8个步骤）

1. **目标设定**: 设定周/月收益目标
2. **Agent 运行**: 使用当前能力配置进行决策
3. **效应器输出**: Agent 输出买卖建议
4. **用户执行**: 用户审核后执行交易
5. **产生结果**: 记录到 trades.json 和 portfolio.json
6. **减法器计算**: 计算差距并归因分析
7. **数据分析**: Session 分析、模式挖掘、工具效能评估
8. **补偿器调整**: 根据分析结果调整能力配置

### 用户审核与应用

当进化报告生成后：

1. **查看报告**: 打开 `.pi-invest/evolution/YYYY-MM.md`
2. **审核建议**: 评估每条优化建议的合理性
3. **选择应用**: 决定应用哪些建议
4. **执行应用**:
   ```bash
   # 通过 CLI 应用建议
   npm run evolution:apply -- --suggestions=sug_001,sug_002,sug_003
   ```
5. **观察效果**: 下周/下月观察改进效果

### 应用建议的影响

应用建议后，系统会：
- 更新工具注册表（新增/移除工具）
- 更新经验库（新增经验条目）
- 调整系统提示词（参数、规则）
- 保存新版本配置
- 记录到进化报告

## 注意事项

### 1. 过度优化风险

**问题**: 频繁调整导致功能不稳定

**控制措施**:
- 差距 <2% 时只做微调
- 每次最多应用 3-5 条改进
- 观察期至少 1 周

### 2. 归因错误风险

**问题**: 误判目标问题为能力问题

**控制措施**:
- 双重检查机制（目标合理性 + 能力评估）
- 置信度评分
- 人工最终审核

### 3. 经验过拟合风险

**问题**: 历史经验不适用于新市场环境

**控制措施**:
- 经验置信度随时间衰减
- 定期清理过时经验（>6个月）
- 标注市场环境标签（牛市/熊市/震荡）

### 4. 工具依赖风险

**问题**: 移除关键工具导致能力下降

**控制措施**:
- 移除前评估影响范围
- 保留工具代码，只是禁用
- 可快速恢复

### 5. 数据质量

**问题**: Session 日志不完整或交易记录缺失

**控制措施**:
- 确保 observable-logger 正常运行
- 定期检查数据完整性
- 缺失数据时跳过该周期分析

## 成功指标

### 短期指标（每周）
- 收益率达标率 >80%
- 胜率提升趋势
- 最大回撤控制在目标内

### 中期指标（每月）
- 跑赢大盘
- 夏普比率 >1.5
- 工具效能持续优化

### 长期指标（每季度）
- 配置版本迭代 >3 次
- 经验库条目 >20 条
- 决策错误率 <15%

## 常见问题

### Q1: 如何设定合理的收益目标？

**建议**:
- 参考大盘收益 + 1.5% ~ 3% Alpha
- 参考历史平均收益
- 考虑市场波动率（目标不超过 3 倍波动率）

### Q2: 经验库会无限增长吗？

**不会**。系统会自动清理：
- 置信度 <0.3 的经验
- 超过 6 个月未更新的经验
- 案例数 <3 的经验

### Q3: 如何判断一条优化建议是否应该应用？

**评估标准**:
- 数据支持是否充分（案例数 >5）
- 逻辑是否合理
- 风险是否可控
- 是否与现有策略冲突

### Q4: 应用建议后效果不好怎么办？

**回滚步骤**:
1. 查看版本历史找到上一个版本号
2. 复制历史版本覆盖当前配置
3. 重启 Agent
4. 在进化报告中记录回滚原因

### Q5: 可以手动添加经验吗？

**可以**。编辑 `.pi-invest/experience/experience-base.json`：
```json
{
  "id": "exp_manual_001",
  "scenario": "手动添加的经验",
  "pattern": { ... },
  "outcomes": { ... },
  "confidence": 0.5,
  "last_updated": "2026-05-14"
}
```

注意：手动添加的经验建议设置较低的置信度（0.5），让系统通过实际案例逐步验证。
