# 参数校验改进说明

## 改进日期
2026-05-27

## 改进内容

### 1. 增强错误信息的可读性

所有参数校验错误信息现在都包含详细的原因说明，帮助用户理解为什么参数不合法以及如何修正。

### 2. 错误信息格式

```
<错误描述>。原因：<详细原因>
```

### 3. 改进的校验类型

#### 3.1 不支持的参数
**之前：**
```
不支持的参数: invalid_param
```

**现在：**
```
不支持的参数: invalid_param。原因：该命令不接受此参数，请检查参数名称是否正确。
```

#### 3.2 缺少必填参数
**之前：**
```
缺少必填参数: symbol
```

**现在：**
```
缺少必填参数: symbol。原因：该参数是命令执行的必要条件，不能为空。
```

#### 3.3 股票代码格式错误
**之前：**
```
symbol 必须是股票代码格式，例如 600519、000001、00700 或 AAPL
```

**现在：**
```
symbol 必须是股票代码格式，例如 600519、000001、00700 或 AAPL。原因：系统需要标准格式的股票代码才能查询数据。
```

#### 3.4 枚举值错误
**之前：**
```
signal_type 只能是 BUY 或 SELL
```

**现在：**
```
signal_type 只能是 BUY 或 SELL。原因：该参数只接受预定义的枚举值。
```

#### 3.5 数值范围错误
**之前：**
```
limit 必须是正数
```

**现在：**
```
limit 必须是正数。原因：参数值超出有效范围，可能导致计算错误或数据异常。
```

#### 3.6 类型错误

**数组类型：**
```
symbols 必须是数组。原因：该参数需要接收多个值，请使用数组格式，例如 ["600519", "000001"]。
```

**整数类型：**
```
limit 必须是整数。原因：该参数不接受小数或非数字值。
```

**数字类型：**
```
price 必须是数字。原因：该参数需要数值类型进行计算。
```

**布尔类型：**
```
has_data 必须是布尔值。原因：该参数只接受 true 或 false。
```

**字符串类型：**
```
symbol 必须是字符串。原因：该参数需要文本类型的值。
```

### 4. 特殊校验：backtest.run

`backtest.run` 命令需要至少提供 `symbol` 或 `symbols` 参数之一。

**错误信息：**
```
backtest.run 至少需要 symbol 或 symbols 参数之一。原因：回测需要指定股票代码才能获取历史数据并执行策略测试。
```

**正确示例：**
```json
// 单个股票回测
{
  "command": "backtest.run",
  "params": {
    "symbol": "600519",
    "days": 365
  }
}

// 多个股票回测
{
  "command": "backtest.run",
  "params": {
    "symbols": "600519,000001",
    "start": "2025-01-01",
    "end": "2026-05-27"
  }
}
```

   - `validateType()` 函数：为类型错误添加详细原因

2. **src/infrastructure/tools/core/quant-cli-tool.test.ts**
   - 添加新测试用例验证改进后的错误信息

## 用户体验改进

1. **更清晰的错误提示**：用户能立即理解参数为什么不合法
2. **更快的问题定位**：详细的原因说明帮助用户快速修正错误
3. **更好的学习体验**：新用户通过错误信息学习正确的参数格式

## 向后兼容性

所有改进都是增强型的，不会破坏现有的 API 契约。错误信息格式保持一致，只是添加了更多上下文信息。
