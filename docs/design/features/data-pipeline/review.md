# Data Pipeline 设计审查

## 审查日期
2026-03-29

## 设计完整性检查

### ✅ 已覆盖
1. **系统边界清晰** - Pipeline 独立，主系统只读
2. **架构合理** - Python CLI + SQLite，解耦良好
3. **Schema 向后兼容** - 增量添加字段，不破坏现有数据
4. **分阶段实现** - 5个 Phase，优先级明确
5. **集成方案完整** - CLI/Cron/Agent 三种调用方式

### ⚠️ 需要补充

#### 1. 错误处理和重试机制
**问题**: 网络请求失败、API 限流时如何处理？
**建议**:
- 添加重试逻辑（最多3次，指数退避）
- 记录失败的 symbol 到日志，支持断点续传

#### 2. 数据质量验证
**问题**: 如何确保拉取的数据有效？
**建议**:
- PE/PB 为 0 或异常值时标记为 NULL
- K线数据缺失超过30%时警告
- 财报数据为空时跳过，不覆盖旧值

#### 3. 性能优化
**问题**: 5000只股票 × 财报接口 = 可能需要数小时
**建议**:
- Phase 3 财报更新改为可选（`--with-financials` flag）
- 默认只更新基础字段 + 技术指标
- 财报数据每月更新一次即可

#### 4. 日志和监控
**问题**: 定时任务失败时如何发现？
**建议**:
- 输出结构化日志到 `.pi-invest/pipeline/logs/YYYY-MM-DD.log`
- 记录成功/失败数量、耗时
- 失败时写入 `.pi-invest/pipeline/errors.json`

#### 5. 数据库锁冲突
**问题**: Pipeline 写入时，主系统读取可能冲突
**建议**:
- SQLite 默认支持并发读，但写入时会锁表
- 建议 Pipeline 使用事务批量提交（每100条一次）
- 主系统读取时设置 `timeout=5` 避免阻塞

## 实现建议调整

### Phase 1 补充
- 添加 `--dry-run` 参数，只打印将要执行的操作
- 添加进度条（使用 tqdm）

### Phase 2 调整
- 技术指标计算前检查 K线数据是否存在
- 换手率字段可能不存在，需要容错

### Phase 3 调整
- 财报接口改为可选，默认跳过
- 添加 `--with-financials` flag 显式启用

### Phase 5 补充
- CronService 执行失败时发送通知（写入 agent 日志）
- Agent 自主发现改为主动询问用户是否更新

## 风险评估

### 高风险
- **akshare API 变更** - 接口字段名可能变化
  - 缓解: 添加字段映射配置，容错处理

### 中风险
- **数据库写入冲突** - 主系统读取时 Pipeline 写入
  - 缓解: 使用事务 + 超时设置

### 低风险
- **磁盘空间不足** - 5000只股票 × 2年K线 ≈ 500MB
  - 缓解: 可接受，无需特殊处理

## 总结

设计整体合理，建议在实现时补充：
1. 错误处理和重试
2. 数据质量验证
3. 结构化日志
4. 进度显示

优先级：Phase 1 → Phase 2 → Phase 4 → Phase 5 → Phase 3（财报可选）
