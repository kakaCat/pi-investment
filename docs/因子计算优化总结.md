## 问题背景

用户反馈：**因子计算慢**

## 问题诊断

### 数据规模
- 股票数量: 5,518只
- K线记录: 6,253条（优化前）→ 9,168条（优化中）
- 平均每只: 1.13条 → 1.66条

### 性能瓶颈（按严重程度排序）

#### 🔴 瓶颈1: 串行处理（最严重）
- **问题**: 5518只股票逐个处理
- **影响**: 即使每只100ms，总时间也需9分钟
- **权重**: ⭐⭐⭐⭐⭐

#### 🔴 瓶颈2: 数据库I/O频繁
- **问题**: 每只股票29次数据库操作（1 SELECT + 1 DELETE + 27 INSERT）
- **总计**: 159,522次数据库操作
- **权重**: ⭐⭐⭐⭐

#### 🟡 瓶颈3: 重复查询历史数据
- **问题**: 每次查询100天数据，实际只需最新数据
- **权重**: ⭐⭐⭐

#### 🟡 瓶颈4: 数据不足导致无效计算
- **问题**: 5499只股票因数据不足被跳过，但仍执行了查询
- **权重**: ⭐⭐

## 优化方案实施

### 方案A: 快速优化（已完成 ✅）

#### 优化措施
1. ✅ **多进程并行**（7进程）
2. ✅ **批量INSERT**（100行/批次）
3. ✅ **事务批处理**（减少commit）
4. ✅ **预先筛选**（只处理有效股票）

#### 实施文件
- 新脚本: `scripts/calculate_factors_parallel.py`
- 原脚本: `scripts/calculate_factors.py`（保留作为备份）

#### 核心代码改进

**1. 多进程并行**
```python
# 原始（串行）
for symbol in symbols:
    factors = calculate_factors_for_stock(db, symbol)
    save_factors(db, symbol, date, factors)

# 优化（并行）
with Pool(processes=7) as pool:
    results = pool.map(calculate_factors_for_stock, symbols)
    save_factors_batch(db, results)
```

**2. 批量INSERT**
```python
# 原始（逐条插入）
for factor_name, factor_value in factors.items():
    conn.execute("INSERT INTO factor_values VALUES (?, ?, ?, ?)", ...)

# 优化（批量插入）
insert_data = [(symbol, date, name, value) for ...]
conn.executemany("INSERT INTO factor_values VALUES (?, ?, ?, ?)", insert_data)
```

**3. 预先筛选**
```python
# 原始（处理所有股票）
symbols = db.get_all_symbols()  # 5518只

# 优化（只处理有效股票）
symbols = conn.execute("""
    SELECT symbol FROM (
        SELECT symbol, COUNT(*) as cnt 
        FROM daily_klines GROUP BY symbol
    ) WHERE cnt >= 60
""").fetchall()  # 只返回有效股票
```

**修复**:

conn.execute(
    "INSERT OR REPLACE INTO stocks (symbol, name, market, updated_at) VALUES (?, ?, ?, datetime('now'))",
