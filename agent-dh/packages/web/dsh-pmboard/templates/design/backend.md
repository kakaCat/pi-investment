## 数据流 <!-- serves: FR-x 需求名称 -->

**填写要求**：用文字+流程图描述关键业务流程，包含：

1. **触发事件**：什么事件触发这个流程（用户操作/定时任务/钩子）
2. **步骤编号**：每个步骤标上序号（步骤 1/2/3...），分支用 2.1/2.2
3. **具体调用**：写清楚调用哪个函数/服务，传什么参数
4. **分支处理**：成功路径、失败路径、边界情况都要写
5. **副作用**：每个步骤产生的副作用（文件系统/数据库/通知）

**示例格式**：

```
事件：用户点击"提交"按钮 → 前端发起 POST /api/xxx
  ↓
步骤 1：鉴权
  ↓ 调用 checkPermission(userId, resourceId)
  ├─ 成功 → 继续
  └─ 失败 → 返回 403 错误

步骤 2：参数校验
  ↓ 调用 validateParams(body)
  ├─ 通过 → 继续
  └─ 失败 → 返回 400 错误

步骤 3：业务逻辑
  ↓ 调用 S-2.processData(params)
  ├─ 成功 → 写入数据库
  └─ 失败 → 回滚事务

【副作用】：
- 数据库：xxx 表新增 1 行
- 文件系统：无
- 通知：发送 WebSocket 事件给前端
```

## 错误处理 <!-- serves: FR-x 需求名称 -->

| 错误类型 | HTTP 状态码 | 错误码 | 用户提示 | 重试策略 | 降级方案 |
|---|---|---|---|---|---|
| 参数缺失 | 400 | PARAM_MISSING | "缺少必填参数 xxx" | 不重试 | - |
| 权限不足 | 403 | PERMISSION_DENIED | "您无权操作该资源" | 不重试 | - |
| 资源不存在 | 404 | NOT_FOUND | "xxx 不存在" | 不重试 | - |
| 业务校验失败 | 422 | VALIDATION_FAILED | "xxx 不符合要求" | 不重试 | 前端展示详细错误 |
| 系统错误 | 500 | INTERNAL_ERROR | "系统繁忙，请稍后重试" | 重试 1 次 | 降级到只读模式 |

**错误降级原则**：

- 用户操作错误（400/403/422）：明确拒绝，不降级
- 系统故障（500/503）：降级但不阻塞核心流程
- 资源缺失（404）：告警但不当错误（可能是新功能）
