# 架构设计（REQ-example）

## TL;DR <!-- serves: FR-2 -->

把 17 类模板源文件在**构建期**内联成字符串常量进 dist；节点转移后置钩子按
「节点文件夹 + 类型」选骨架幂等落盘；必填节校验从提交拆分计划前移到提交需求文档。
选构建期内联而非运行时读文件，因为插件 files 白名单不含 templates/、浏览器端无 fs。

## 设计总览 <!-- serves: FR-2, FR-3 -->

```
  构建期                         运行时
┌────────────┐  inline   ┌──────────────────┐   节点转移   ┌──────────────┐
│ templates/ │ ────────► │ generated/       │ ◄─────────── │ transition   │
│ <stage>/*.md│  生成器   │ templates.ts     │   后置钩子    │ Requirement  │
└────────────┘           │ (字符串常量进dist) │              └──────┬───────┘
                         └────────┬─────────┘                     │
                                  │ getTemplate(stage, category)  │ 落盘(幂等)
                            ┌─────▼───────────────────────────────▼─────┐
                            │ docs/requirements/<REQ>/requirement.md 等 │
                            └───────────────────────────────────────────┘
```

| 组件 | 职责（一句话） | 改动文件 |
|---|---|---|
| 模板生成器 | 构建期把 md 源内联成 TS 常量 | scripts/inline-templates.mjs（新增） |
| 模板常量 | 运行时零 fs 取模板 | src/domain/prompt/generated/templates.ts（生成物） |
| 落盘钩子 | 节点转移后按类型落骨架，幂等 | src/application/internal/template-landing.ts（新增） |
| 校验前移 | submit kind=requirement 即跑必填节校验 | src/application/SubmitArtifact.ts（改） |

## 数据流 <!-- serves: FR-3, FR-5 -->

```
窗口agent     转移钩子           模板常量          需求目录
  │ 确认节点转移  │                 │                │
  │ ───────────► │ 查模板(stage+类别)│                │
  │             │ ──────────────► │                │
  │             │ 目标已存在?      │                │
  │             │ ──────────────► │ 是→跳过不覆盖   │
  │             │ 否→写骨架+登记产物│ ────────────► │
  │ submit文档   │                 │                │
  │ ───────────► │ 必填节校验(前移) │                │
  │ ◄─────────── │ 缺节→拒绝+清单  │                │
```

## 方案对比 <!-- serves: FR-2 -->

| 方案 | 思路 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A 构建期内联 | md → generated/templates.ts 进 dist | 运行时零 fs；files 白名单无关；浏览器端可经 host 接口下发 | 改模板要重跑生成器（用 check 门禁兜） | ✅ 选定 |
| B 运行时 fs 读 | dist 外放 templates/ 目录 | 改模板即生效 | files 白名单要加目录；浏览器端读不到；pnpm 硬链接副本会静默过期（2026-09-11 事故同款） | ❌ 否定：部署链路不可靠 |
| C 模板全文进提示词 | 不落地文件，全给 LLM | 实现最简 | token 预算爆炸；agent 仍要组织目录结构 | ❌ 否定：挤占上下文（R-3 风险） |

## 研发规范 <!-- serves: FR-2, FR-3 -->

| 类别 | 规范/约定 | 来源 | 本次如何遵守 |

## 设计模式 <!-- serves: FR-2, FR-3 -->

| 模式 | 用在哪个组件 | 解决什么问题 | 不用会怎样 |
|---|---|---|---|
| （未引入新模式） | — | — | — |
| 复用：构建期代码生成 | inline-templates → generated/templates.ts | 运行时零 fs、dist 自包含 | 照抄 inline-prompt-fragments 同款，新造轮子 |
| 复用：幂等后置钩子 | 落盘钩子挂转移事件 | 增益能力不绑架主流程 | 同步嵌进转移主流程会放大故障面 |

## 错误处理 <!-- serves: FR-3 -->

| 失败点 | 检测方式 | 处置（降级/报错） | 留痕（日志/审计） |
|---|---|---|---|
| 模板常量缺失（该节点+类型无模板） | getTemplate 返回 null | 降级：跳过落盘，不阻断转移 | 告警日志 + notes 产物登记 |
| 磁盘写失败 | writeFileSync 抛错 | 响亮报错，转移不回滚 | 错误进需求 comments |
| 生成器未重跑（源改/常量旧） | check-templates.mjs 比对哈希 | CI exit 1 拦构建 | CI 日志 |

## 非功能考量 <!-- serves: FR-3 -->

性能：落盘钩子同步路径 < 50ms；兼容：存量需求（无 artifacts）不触发落盘；
安全：骨架只写需求目录内路径，模板常量不含凭据。

## 部署与依赖 <!-- serves: FR-2 -->

| 新增依赖/配置/端口 | 用途 | 回滚影响 |
|---|---|---|
| 无新运行时依赖 | — | — |
