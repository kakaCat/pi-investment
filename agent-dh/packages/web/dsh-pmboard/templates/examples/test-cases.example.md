## 用例明细 <!-- serves: FR-3 -->

### TC-2 已有文档不会被覆盖（幂等性验证）

- **测试数据**：
  - 目标文件 `requirement.md` 预写内容："# 我手写的需求\n（共 42 行，含 FR-9 自定义节）"
  - 构造 3 次连续节点转移事件（brainstorming → design → decomposing）
  
- **步骤**（原子化）：
  1. 预写目标文件并记录 sha256 哈希值
  2. 触发转移钩子 3 次（模拟重复进入同一节点）
  3. 重算文件 sha256
  4. 查询 artifacts 登记表 (req_id, path) 行数
  
- **断言点**（三不原则：不模糊/不遗漏/不过度）：
  1. ✅ 三次触发后文件 sha256 与预写时**逐字节一致**（不是"内容差不多"，是哈希相等）
  2. ✅ artifacts 表中 (req_id, path) 登记行数 = 1（唯一约束兜底，重复登记被拦）
  3. ✅ 日志含 3 条 "skip: file exists"（每次跳过都留痕）
  4. ✅ comments 无新增记录（幂等跳过不产生业务事件）
  
- **清理**：
  - 删除测试需求目录 `docs/requirements/REQ-test-*`
  - artifacts 测试行走仓储 delete（测试库专用，生产库禁用 delete）

### TC-3 缺必填节被提交即校验章节拦截

- **测试数据**（边界值分析）：
  - 合规骨架逐节删法 ×3 变体：
    - 变体① 删「边界（不做什么）」整节
    - 变体② 把节名改成「边界与范围」
    - 变体③ 节名后加全角括号注「边界（不做什么，含补充）」
    
- **步骤**：
  1. 各变体分别 submit kind=requirement
  2. 记录返回的 success / validation_errors
  3. 对通过的变体：检查 artifacts 登记状态
  
- **断言点**：
  1. ✅ 变体① 被拒，validation_errors 含且仅含「边界（不做什么）」
  2. ✅ 变体② 被拒（改名即不合规，hasRootSection 精确匹配）
  3. ✅ 变体③ **通过**（括号注是合法形态——防止校验器比门禁更严，过度拦截）
  4. ✅ 被拒的变体 artifacts 无新增（拦截发生在落库前）
  
- **清理**：无（纯校验路径，无落盘副作用）

### TC-8 防注入：模板路径遍历攻击

- **测试数据**（等价类：非法路径）：
  - 路径遍历：`../../../etc/passwd`
  - 绝对路径：`/etc/passwd`
  - Windows 路径：`C:\\Windows\\System32\\config\\sam`
  - 空字节注入：`requirement\0.md`
  
- **步骤**：
  1. 构造恶意 template_key 发起 submit
  2. 记录返回状态与错误信息
  3. 检查日志是否有安全告警
  
- **断言点**（安全三层防御）：
  1. ✅ submit 被拒，返回 400 + "非法路径"（入口拦截）
  2. ✅ 未尝试读取目标路径（日志无 fs.readFile /etc/passwd）
  3. ✅ 安全日志记录攻击尝试（audit.log 含 "path_traversal_blocked"）
  
- **清理**：查看安全日志后清理测试记录
