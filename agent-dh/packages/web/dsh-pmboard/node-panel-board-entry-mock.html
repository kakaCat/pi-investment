会话流程节点：「去项目看板」入口放哪里

现状：点会话顶部（header 右侧）流程条的任一节点，只弹出下面这个内联面板（conversation-progress.ts 的 setDetailOpen(true)），没有任何一条通往「项目看板 → 该需求详情」的路。 下面 4 个方案是同一个面板的 4 种入口位置（橙虚线框 = 新按钮）。面板宽按 640px 呈现（真实为 min(720px, 100vw-130px)，最高 68vh）。

方案位置核心优势代价结论
①面板头 REQ 行右侧（× 左边）打开面板即可见，位置固定不随滚动；与「REQ 胶囊 + 标题」同排，语义就是「这条需求的更多入口」标题行右内边距要从 30px 提到 ~64px；窄屏标题被压短首推
②状态行（与「12 分钟前」同排）不用改标题行留白；与状态/时间绑定，读起来像「这条需求现在这样，去全景看」head 行 flex-wrap:wrap，窄屏会掉到第二行；挤占时间的位置感次选
③面板底部 sticky 操作条（主按钮）动线自然（读完详情再决定跳走）；主按钮最显眼，不会被折叠块埋掉多占一行高度；内容不足时底条悬在中间；面板本身是 68vh 滚动容器，实现要 sticky次选
④流程条尾部（面板关着也能点）路径最短、常驻可见；最贴合「会话右侧上面的节点」这句话加宽 header 里的流程条（已有 overflow-x:auto）；与「点节点=开详情」并列，需要视觉上区分可作为主入口
现状

点节点只开内联面板 —— 这条需求没有去项目看板的入口

现状说明 面板头部只有右上角一个 ×（绝对定位，行内留白 30px）；节点的点击语义被内联面板独占了。 缺口 想从「这个节点」走到「看板里的完整需求详情」（含 Token / 追溯 / 条款接收 / 验收单），只能先关面板、再去左侧栏点「项目看板」、再找需求——三步。
方案 ①

面板头 REQ 行右侧（× 左边）

首推
改哪里 node-panel.ts 的 renderHead() 在 .dsh-pm-np-req 行尾加按钮； styles/node-panel.ts 里把 .dsh-pm-np-req 的 padding-right 从 30px 提到 ~64px 给 × 让位。 为什么好
  • 面板是 68vh 滚动容器，按钮固定在头部 = 无论滚到哪都看得见
  • 「REQ-xxxx + 标题」这一行本来就是"这条需求是谁"，入口放同排最自然也最好找
注意
  • 窄屏标题被压短（本来就有 ellipsis，影响可控）
  • 文案建议短：项目看板 ↗，不要用长句
方案 ②

状态行右端（「12 分钟前」右侧）

改哪里 renderHead() 的 .dsh-pm-np-head 里，head-time 之后追加。 为什么可以
  • 不必动标题行的留白，改动最小
  • 与「进行中 + 一句话 + 时间」同排，读感是"现状 → 全景"
注意
  • 该行是 flex-wrap:wrap：面板窄 / 文案长时会换行到第二行，位置不稳
  • head-time 靠 margin-left:auto 靠右，按钮跟在它后面会贴着面板右缘
方案 ③

面板底部 sticky 操作条（主按钮）

改哪里 conversation-progress.ts 的 panelChildren 里追加一条（现在那里只 push 了 × 和面板主体）。 为什么可以
  • 动线最顺：看完节点详情 → 决定"我要看全的" → 底部一点
  • 主按钮形态最显眼，也是唯一能承载"主操作"重量的位置
注意
  • 面板只有几十字内容时，底条会贴着内容悬在中间（sticky 只在滚动时才贴底）
  • 比 ①② 多占一行高度，面板本就 68vh，空间紧张
方案 ④

流程条尾部（面板不打开也能点）

路径最短
改哪里 conversation-progress.ts 里 dsh-pm-cprog-inline 的 count 之后加一个 chip。 为什么好
  • 一步到位，不用先开面板；面板关着也常驻可见
  • 最贴合你的原话——入口就长在「会话右侧上面的节点」旁边
注意
  • 流程条会变宽（在 header 里，已有 overflow-x:auto 兜底）
  • 与"点节点 = 开详情"并列，需要靠分隔线 / 图标把两种点击语义分开

我的建议：④ 做常用入口（点一下就到位，不回退现有节点点击语义），① 作为面板内的固定入口（面板打开时的第二落点）。 若只想要一个：选 ①——改动最小、位置最稳、和 × 不抢（把行内右留白从 30px 提到 64px 即可）。
