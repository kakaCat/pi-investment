## 本仓覆盖条目（覆盖上文与本仓冲突之处；priority=floor，永不被裁）

- [ ] **覆盖 1 · 任务卡必须说人话**：本仓的任务卡要经得起「**非工程读者能否复述**」这一条判据。
      卡的标题与正文必须让不懂代码的人回答出两件事：**这条卡在解决什么**、**做完我会看到什么变化**。
      三要素（在做什么 / 解决什么问题 / 得到什么结果）缺一即被门禁拦下（task_card_incomplete）。
- [ ] **覆盖 2 · 工程细节下沉，不当主语**：改哪些表 / 文件 / 接口 / 测试命令，
      写进「实施方案」与「验收标准」两节；**不要拿它们当卡的标题或第一句**。
      反例：「判据 metric 化」「新增四张表与两表加列」「规则自愈」——读不出业务变化。
      正例：「盯盘噪音治理：让反复触发的规则收敛成一条修规则待办」。
- [ ] **覆盖 3 · 汇报时同样说人话**：完工记录（reqboard_task_report）的 summary 要写
      「这一步做完，什么变了」，而不是只列改了哪些文件。
