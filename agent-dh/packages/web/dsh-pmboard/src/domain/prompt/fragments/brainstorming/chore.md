# 类型档 · chore（需求分析）

- [ ] 圈定**最小改动**面：只改必须改的那一处，其余一律不碰。
- [ ] 明确"顺手能做的事"不纳入（另立项），不夹带业务逻辑变更。
- [ ] 判定标准可证伪：跑什么、看到什么算完成。
- [ ] 范围限于维护性动作（版本 / 常量 / 清理 / 接线），不新增能力。

## 条款定义行（G2 门禁可解析，FR-10）

需求文档里的每条功能点/条款必须写成 G2 clause 门禁认得的定义行，否则解析不到、条款接收状态全红：

- [ ] 行首 `**CH-N: 名称**`（可带 `- `/`* ` 列表符）；编号用 CH-1、CH-2…，不要用与批准闸门撞名的 G 系列编号。
- [ ] 根文档必填节（G2 missingCategoryDocs 逐节核对，缺一即拦）：边界、完成判据。

示范（照此独立成行写，门禁即认得；注意是列表项、不是 checklist 复选框）：

- **CH-1: 一句话写清这条做什么**
