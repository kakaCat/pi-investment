# 类型档 · bug（需求分析）

先复现再改——**根因不清不许动手**：

- [ ] 写清**复现步骤**与最小重现（环境 / 输入 / 预期 vs 实际），先确认这是缺陷而不是需求变更。
- [ ] 给出**根因假设**与验证方法；本节点只定位与划界，不写修复代码。
- [ ] **禁止顺手重构**：不把"顺便清理""顺便优化"写进范围。
- [ ] 明确"将来怎么证明修好了"——**回归测试**要覆盖这条复现路径。

## 条款定义行（G2 门禁可解析，FR-10）

需求文档里的每条功能点/条款必须写成 G2 clause 门禁认得的定义行，否则解析不到、条款接收状态全红：

- [ ] 行首 `**BUG-N: 名称**`（可带 `- `/`* ` 列表符）；编号用 BUG-1、BUG-2…，不要用与批准闸门撞名的 G 系列编号。
- [ ] 根文档必填节（G2 missingCategoryDocs 逐节核对，缺一即拦）：边界、复现步骤、根因、回归。
