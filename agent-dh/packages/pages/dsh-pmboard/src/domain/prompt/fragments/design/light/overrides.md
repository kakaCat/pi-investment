## 本仓覆盖条目（覆盖上文与本仓冲突之处；priority=floor，永不被裁）

- [ ] **覆盖 1 · 每节必须标注服务哪条功能点**：设计文档的**每个二级章节**都要带
      `serves: FR-4` 这样的标注（多值用逗号分隔，如 `serves: FR-2, FR-4`）。
      缺标注的章节即**孤儿章节**，提交计划会被门禁拒绝（design_orphan）。
      文档级标注写在 H1 标题或 front-matter 的 requirement_refs。
- [ ] **覆盖 2 · 语言强度按层（不是所有层都写"全业务"）**：

      | 层 | 语言 | 为什么 |
      |----|------|--------|
      | 需求 | **全业务** | 用户要认 |
      | **设计** | **技术为主** + 每节标 serves | 工程/agent 执行；硬套业务语言会让方案失真 |
      | 拆分 | **业务标题** + 技术细节下沉 | 用户看不懂的重灾区 |
      | 实施 | 技术为主 + 业务三要素 | 给 agent 执行 |
      | 验收 | **全业务** + 可执行操作 | 用户要独立复核 |

      判据：**这一层的读者是谁，就用谁的语言**。业务化 ≠ 把设计写成散文。
