# 需求ID添加时间戳信息

## 变更概述

将需求ID格式从 `REQ-xxxxxx` (6位随机hex) 升级为 `REQ-YYMMDDHHmmss-xxxx` (时间戳+4位随机hex)，提升可读性和可追溯性。

## 新格式说明

### 格式结构
```
REQ-YYMMDDHHmmss-xxxx
    └─┬──┘ └─┬┘ └─┬┘ └┬┘
      年月日  时分秒  随机
```

### 示例
- `REQ-260921144616-4e3d` → 2026年09月21日 14:46:16创建
- `REQ-250101090000-a3f2` → 2025年01月01日 09:00:00创建

### 优势
1. **时间可读性**：从ID直接看出创建时间
2. **自然排序**：按创建时间自动排序
3. **保证唯一性**：时间戳(精确到秒) + 4位hex，同一秒内可生成65536个不同ID
4. **紧凑性**：总长度21字符（vs 旧格式10字符），仍然简洁

## 技术实现

### 修改文件
1. `src/adapters/RandomIdFactory.ts` - 添加时间戳格式化函数
2. `src/shared/protocol.ts` - 更新 `newRequirementId()` 函数
3. `src/adapters/JsonLedgerRepository.ts` - 更新正则表达式支持新旧格式

### 向后兼容性

正则表达式同时支持新旧两种格式：
```typescript
/^REQ-(?:[0-9a-f]{6}|\d{12}-[0-9a-f]{4})$/
```

- 旧格式：`REQ-[0-9a-f]{6}` (如 `REQ-a3f2b1`)
- 新格式：`REQ-\d{12}-[0-9a-f]{4}` (如 `REQ-260921144616-4e3d`)

**现有数据不受影响**：旧格式的需求ID继续有效，系统可同时识别新旧两种格式。

## 影响范围

- **新需求**：从本次部署后创建的需求使用新格式
- **旧需求**：保持原有格式，继续正常工作
- **ID验证**：兼容新旧两种格式，无需迁移数据

## 部署说明

1. 构建项目：`pnpm run build`
2. 重启服务：新创建的需求将使用新格式
3. 无需数据迁移：旧数据继续有效

## 其他ID格式

**任务/执行/评论ID保持不变**：
- 任务ID: `t-xxxxxx` (6位hex)
- 执行ID: `e-xxxxxx` (6位hex)
- 评论ID: `c-xxxxxx` (6位hex)

仅需求ID添加时间戳，其他ID类型维持原格式以保持简洁。
