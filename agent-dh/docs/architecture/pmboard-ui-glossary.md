## 3. 项目看板页

### 3.1 头部（`views/board.ts`）

**项目看板**（大标题，与菜单按钮同名 ✅）｜ `rev N` ｜ 视图切换「**泳道 / 列表**」｜「刷新」｜「**任务**」（悬停：任务总览与甘特图）｜「**+ 需求**」（新建需求）

### 3.2 泳道视图（默认）

六列（`LANE_STATUSES`）：**立项 / 需求分析 / 设计 / 拆分 / 实施 / 验收**。
`done`（待归档）需求并入**验收**列置灰显示；`archived / canceled` 不进列。

**需求卡面**（`views/artifacts.ts` `renderReqCard`）从上到下：

| 元素 | 用词 |
|------|------|
| 首行 | `REQ-xxxxxx` + 类型徽标（功能/缺陷/文档/重构/调研/杂项）+ 各类 flag |
| flag 词汇 | **阻塞** / **暂停** / **N ready** / 计划：**待批准** / 验收：**待验收材料**、**待人工审核** / 归档：**待归档材料**、**待归档** / 自动链徽标 |
| 标题 | 需求标题 |
| 进度行 | 进度条 + `完成/总数` + 🪙 token 徽标（累计 Token） |
| 子卡进度 | 父卡 N 子卡 完成M（父卡按依赖并行；子卡在父卡内串行） |
| 产物 chips | ✓/✗ **需求文档 / 设计文档 / 拆分计划 / 验收材料**（✗=缺失，红） |
| 时间行 / 窗口 chip | 创建·更新时间；立项来源窗口 w-xxx（已归档会话划掉） |
| 确认按钮 | 有待确认产物时出现「确认」 |
| 卡面操作按钮 | 按状态：**→ 需求分析 / → 设计 / → 拆分 / → 实施 / → 验收**（主按钮）＋ **退回 / 退回重谈 / 取消**；悬停有解释 |

### 3.3 列表视图

排序键：**阶段 / 进度 / 最近更新 / 创建时间 / 名称**；分组标题「进行中 N」「已完成 N」；分页 10/20/50。

### 3.4 待归类区（看板底部，`buildTriage`）

标题「**待归类（N）**」＋提示「新会话自动捕获，确认后进入流水线」。⚠️ 与「创建即立项」口径的关系见 §8-2。
条目内容：会话 id（前 16 位）、`分 N`（捕获评分）、建议（**新建需求**（可编辑名称+分类下拉）/ **绑定需求** REQ-id / **绑定任务** t-id）、首条消息摘录、按钮「**确认 / 改绑 / 拒绝**」。

### 3.5 任务总览（头部「任务」按钮进入）

**任务五列小看板**：列名 = 任务状态（见 §7.2，待开始/开发中/联调中/测试中/待复核/已完成）；只进顶层卡，子卡折叠在父卡下，存量卡带「**手动**」标。另有**甘特图**（按状态分段着色 + 需求里程碑竖线 + 当前时刻线）。

## 5. 节点面板（点流程节点看到的内容，`stage-panel.ts`）

**固定骨架**：面板头（**状态一句话** + 相对时间）→ **追溯链**（需求文档 → 设计文档 → 拆分计划 → 任务卡 → 验收材料 → 归档材料；缺失红字「（缺失）」）。
  2026-09-22（REQ-260922182638-0777）两处改造：设计节点的多份文档显示**中文文档名**（架构文档/数据模型/接口文档/测试用例…，
  不再裸显 architecture.md，完整路径在按钮 tooltip）；任务卡**逐张列出且带任务名称**（「任务卡 · <任务名>」，名称经产物路径 ↔ 
  任务卡文档精确匹配，匹配不到降级「任务卡（t-xxx）」），不再折叠为「任务卡×N」→ ⚠ **有产物待人工确认**（警示，仅待确认时）→ **节点专属内容** → **动态**（最近 5 条：谁 · 多久前 · 做了什么）。

| 节点 | 面板头一句话 | 专属内容 |
|------|-------------|---------|
| 立项 | 已立项 | 需求标题（类型）、描述（无→「暂无描述」）、来源窗口 · 创建时间 |
| 需求分析 | N 条评论 | 评论列表（人/系统/w-xxx + 正文）；无→「暂无评论」 |
| 设计 | 待提交计划 / 计划待批准 / 计划已批准 / 计划被退回 | 📋 **本类型需要的文档**：根文档必填节清单 + 设计文档逐份状态（✅ 已交 / ⬜ 未交 / 🚫 已豁免：理由 / 〔条件·端侧〕徽标）；有旧版计划时附计划摘要 + N 个任务 + 批准/退回/提交状态 |
| 拆分 | 待拆分 / N 个任务 | 任务按依赖分层：**第 1 层 · 无依赖** / **第 N 层 · M 个可并行**，每任务 id + 标题；无→「尚未提交拆分计划…」 |
| 实施 | d/t 完成 · 剩 n 个 · 进行中 t-xxx | 任务分三组：**进行中 N 个 / 已完成 N 个 / 待开始 N 个**；每任务 = 状态字形（○◐✓✕）+ 标题 + `id · 执行者 · 时间` + 「任务卡」按钮；多窗口时一行「窗口分工：w-a 3 任务 · w-b 2 任务」 |
| 验收 | 待提交验收材料 / 待人工审核 / 验收通过 / 验收被退回返工 | 验收摘要 + **验收单 vN**（逐项：状态徽章 + 来源（需求级 / 任务 id）+ 验收标准 + 未裁决项给「通过 / 不通过」单选 + 意见框；返工续验标「返工续验：只含未过项」）+ **提交裁决**按钮 + 证据（N 条）+ 审核意见 |
| 归档 | 已归档 | 归档目录、索引条目、合并去向（可点开文档） |

## 6. 任务详情面板（点任务，`views/stage-panel.ts`）

按任务识别**节点类型**展示差异化内容：🔀 拆分 / ⚙️ 实施 / 🧪 测试 / 👀 评审 / 🔀 合并 / 📝 文档 / 🎨 UI / 分析。
其中**评审节点**内含：📊 **评审结果**（状态：待评审 / 已批准 / 已退回 + 通过项统计）→ ✅ **通过项** → ⚠️ **改进建议**（编号 + 文件:行 + 严重性：低/中/高 + 内容）→ 💬 **评审讨论**。
（「评审」在这里是**任务流水线的 phase 名**，与需求节点「需求分析」是两个概念；任务状态层面统一叫「待复核」。）

## 8. 已知不一致（待裁定/待修）

1. **「打开项目看板」vs「打开需求看板」**（会话流程条底部两个按钮）——没有"需求看板"这个页面，按钮②实际是"打开项目看板并定位到本需求"。待裁定新名。

  - **旧管线存量**（设计阶段确有 `plan` 产物，或"有 plan 但一份设计文档都没交"）→ 计划类文案
    （计划待批准 / 计划已批准 / 计划被退回）。
    判据**不再是"req.plan 存不存在"**——新管线需求的 PlanRecord 在拆分阶段才产生，用旧判据会让
    新需求永远显示计划文案（线上实测踩到，单测未覆盖该组合）。
  - **新管线**（设计阶段只写设计文档）→ 按逐份交付 / 人工确认取词：`设计文档 n/N 已交` →
    `待确认设计文档` → `设计已确认`。
- **节点文档行**（`node-panel.ts`）：已交的设计文档渲染为**可点行**（`data-action="open-doc"`，右侧栏打开）；
  未交保持 `⬜ …` 灰字占位；拆分节点在**未提交** `decomposition.md` 时也补一行
  `⬜ 拆分计划：decomposition.md（未交）`——与设计节点的必交清单同口径，避免"文档行凭空消失"。
- **面板头状态胶囊**：预览**未到达**的节点（行状态 `pending`）一律显示中性词「**未开始**」，
  不再借用该节点的完成态词（旧行为显示「已拆分 / 已设计」，在需求还没拆时是假话）；
  已到达（`done`）与当前（`current`）节点取词不变（`node-panel-process.ts` `STAGE_STATE_WORD`）。
