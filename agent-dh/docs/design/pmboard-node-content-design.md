# PM Board 节点内容差异化设计

## 问题描述

当前点击 DAG 图中的任何节点，都显示相同的任务详情页面（执行记录、评论、时间线等）。这种"一刀切"的展示方式不够直观，无法突出不同节点类型的核心信息。

例如：
- **拆分节点**应该展示拆分出的任务列表
- **实施节点**应该展示具体的代码改动和 DAG 图
- **测试节点**应该展示测试用例和覆盖率
- **验收节点**应该展示验收标准和验证结果

## 设计方案

### 一、节点类型识别

基于 `TaskRecord.phase` 字段，识别以下节点类型：

| Phase | 中文名称 | 核心职能 |
|-------|---------|---------|
| `doc` | 文档 | 需求文档、设计文档、API 文档 |
| `ui` | UI 设计 | 界面原型、视觉规范、交互流程 |
| `analysis` | 分析 | 技术调研、性能分析、可行性研究 |
| `implement` | 实施 | 编码、代码修改、功能实现 |
| `test` | 测试 | 测试用例、测试结果、覆盖率 |
| `review` | 评审 | 代码审查、设计评审、技术评审 |
| `merge` | 合并 | 分支合并、冲突解决、发布准备 |

特殊节点类型（基于 `title` 或 `phase` 推断）：
- **拆分节点**：`title` 包含"拆分"或"decompose"
- **计划节点**：`title` 包含"计划"或"plan"
- **集成节点**：`status === 'integrating'`

### 二、差异化内容设计

#### 1. 拆分节点（Decomposition Node）

**核心价值**：展示需求如何被分解为可执行任务

├─────────────────────────────────────────┤

│   • 预计工期 4.5 天                      │
├─────────────────────────────────────────┤
│ 📋 拆分清单                              │
│   [UI 轨道 - 2 任务]                     │
│     ├─ TASK-001 设计登录界面             │
│     └─ TASK-002 实现响应式布局           │
│                                         │
│   [后端轨道 - 3 任务]                    │
│     ├─ TASK-003 设计数据模型             │
│     ├─ TASK-004 实现 API 端点            │
│     └─ TASK-005 添加权限控制             │
│                                         │
│   [测试轨道 - 3 任务]                    │
│     ├─ TASK-006 单元测试                 │
│     ├─ TASK-007 集成测试                 │
│     └─ TASK-008 E2E 测试                 │
├─────────────────────────────────────────┤
│ 🌳 依赖关系 DAG                          │
│   [可视化的任务依赖图]                   │
├─────────────────────────────────────────┤
│ 📝 拆分依据                              │
│   • 遵循前后端分离原则                   │

│   • 测试依赖所有实现任务完成             │

**数据来源**：
- 从 `state.tasks.filter(t => t.requirementId === req.id)` 获取所有任务
- 按 `side` 分组（frontend/backend/fullstack）
- 展示 DAG 层级（L0/L1/L2...）
- 显示任务间的 `dependsOn` 关系

### 三、通用信息区

所有节点类型都应包含以下通用信息（折叠或底部展示）：

- **基本属性**：ID、状态、阶段、端侧
- **依赖关系**：依赖的任务、被依赖的任务
- **时间线**：创建时间、开始时间、完成时间、耗时
- **执行记录**：完整的执行历史（折叠）
- **评论区**：支持人工和 agent 评论

### 四、实现优先级

**P0（MVP）**：
1. 拆分节点 - 最重要，展示任务全貌
2. 实施节点 - 最常见，展示代码变更
3. 测试节点 - 质量保证，展示测试结果

**P1（增强）**：
4. 评审节点 - 代码审查反馈
5. 合并节点 - 分支合并状态

**P2（完善）**：
6. 文档节点 - 文档内容展示
7. UI 设计节点 - 界面原型展示
8. 分析节点 - 调研结果展示

### 五、数据结构扩展

为支持差异化展示，需要在 `TaskRecord` 的 `executions.evidence` 中存储结构化数据：

```typescript
interface Evidence {
  // 通用字段
  files?: Array<{ path: string; added: number; deleted: number }>
  
  // 测试节点专用
  testResults?: {
    total: number
    passed: number
    failed: number
    skipped: number
    failedCases?: Array<{
      name: string
      expected: string
      actual: string
      file: string
      line: number
    }>
    coverage?: {
      statements: number
      branches: number
      functions: number
      lines: number
    }
  }
  
  // 评审节点专用
  reviewComments?: Array<{
    file: string
    line: number
    severity: 'low' | 'medium' | 'high'
    message: string
    resolved: boolean
  }>
  
  // 合并节点专用
  mergeInfo?: {
    sourceBranch: string
    targetBranch: string
    commits: number
    conflicts?: Array<{
      file: string
      description: string
      resolution: string
    }>
    ciChecks?: Array<{
      name: string
      status: 'pass' | 'fail' | 'pending'
      details?: string
    }>
  }
  
  // 拆分节点专用
  decomposition?: {
    totalTasks: number
    tracks: number
    estimatedDays: number
    tasksByTrack: Record<string, string[]>
  }
}
```

### 六、UI 实现建议

1. **渐进式展示**：
   - 首屏展示核心信息（拆分清单、测试结果、代码变更等）
   - 通用信息折叠在底部（可展开）
   
2. **图标系统**：
   - 🔀 拆分节点
   - ⚙️ 实施节点
   - 🧪 测试节点
   - 👀 评审节点
   - 🔀 合并节点
   - 📝 文档节点
   - 🎨 UI 设计节点
   - 🔍 分析节点

3. **状态指示**：
   - ✅ 成功/通过
   - ⚠️ 警告/部分成功
   - ❌ 失败/阻塞
   - ⏳ 进行中
   - 📋 待办

4. **交互增强**：
   - 点击文件路径 → 跳转到 IDE 对应位置
   - 点击会话 ID → 跳转到会话详情
   - 点击任务 ID → 跳转到任务详情
   - 展开/折叠详细信息

## 实施计划

### Phase 1: 基础架构（1 天）

1. 扩展 `buildTaskDetail` 函数，添加节点类型识别逻辑
2. 创建 `renderNodeContent` 分发函数
3. 设计通用的内容区域布局

### Phase 2: 核心节点（2 天）

1. 实现拆分节点展示
2. 实现实施节点展示
3. 实现测试节点展示

### Phase 3: 增强节点（1 天）

4. 实现评审节点展示
5. 实现合并节点展示

### Phase 4: 完善节点（1 天）

6. 实现文档/UI/分析节点展示
7. 样式优化和交互完善

## 效果预期

- **信息密度提升**：每个节点展示最相关的信息，减少无关内容
- **认知负荷降低**：根据节点类型自动调整展示内容，用户无需过滤
- **工作效率提升**：快速定位问题（测试失败、代码冲突、评审意见）
- **全局视角增强**：拆分节点提供整体任务结构，帮助理解需求全貌
