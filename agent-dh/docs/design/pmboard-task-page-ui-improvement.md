# 任务页 UI 改进设计文档

> **状态**: 设计中（部分实现）  
> **日期**: 2026-09-14  
> **作者**: Claude (w-投资脑会话)  

## 1. 背景与问题

基于用户反馈，当前任务页存在以下问题：

1. **任务卡片信息过于密集** - 难以快速浏览和定位关键信息
2. **缺少筛选和排序功能** - 无法快速找到特定状态/阶段的任务
3. **任务详情页布局混乱** - 信息层级不清晰
4. **颜色和状态标识不够直观** - 状态区分度低，不易识别
5. **缺少进度可视化** - 整体进度难以一目了然

## 2. 设计目标

基于"页面主要是监控"的定位，改进方向：

- **一目了然**: 关键指标（进度、阻塞、状态）突出显示
- **快速定位**: 多维度筛选，快速找到需要关注的任务
- **清晰层级**: 信息分组合理，视觉层次清晰
- **直观状态**: 色彩明确，状态一眼可辨
- **进度可视**: 数字+图表双重展示，整体与细节兼顾

## 3. 核心改进点

### 3.1 统计卡片区（Dashboard Overview）

**设计理念**: 快速了解全局状态

```
┌─────────────────────────────────────────────────────────┐
│  [全部任务: 45] [进行中: 8] [测试中: 3] [评审中: 2]    │
│  [已完成: 28]   [阻塞: 4] ⚠️                            │
└─────────────────────────────────────────────────────────┘
```

**特点**:
- 大号数字突出显示
- 状态用颜色区分（进行中=蓝，完成=绿，阻塞=红）
- 可点击快速筛选
- Hover 效果提供视觉反馈

### 3.2 筛选工具栏

**设计理念**: 多维度快速筛选

```
┌─────────────────────────────────────────────────────────┐
│ 状态: [全部 ▾] 阶段: [全部 ▾] 端侧: [全部 ▾]         │
│ 需求: [全部 ▾] 排序: [最近更新 ▾] [分组|列表|时间线] │
└─────────────────────────────────────────────────────────┘
```

**筛选维度**:
- 状态: 待办/进行中/联调/测试/评审/完成
- 阶段: 文档/UI/分析/实施/测试/评审/合并
- 端侧: 前端/后端/全栈/文档
- 需求: 按需求ID筛选

**排序选项**:
- 最近更新
- 创建时间
- 状态
- 阶段

**视图切换**:
- 分组视图（按需求分组，默认）
- 列表视图（扁平列表）
- 时间线视图（甘特图为主）

### 3.3 任务组布局改进

**设计理念**: 清晰的信息层级

```
┌────────────────────────────────────────────────────────┐
│ REQ-xxx [状态] 需求标题                    [4 阻塞]     │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ ████████████░░░░░░░░░░ 12/20 完成          60%        │
│ [查看需求详情]                                          │
├────────────────────────────────────────────────────────┤
│ 📍 立项 09-01 → 头脑风暴 09-02 → 实施 09-05            │
├────────────────────────────────────────────────────────┤
│ 📊 甘特图          [展开/收起 ▾]                       │
│ [甘特图内容...]                                         │
├────────────────────────────────────────────────────────┤
│ 📋 任务看板                                             │
│ [待办] [进行中] [联调] [测试] [评审] [完成]            │
├────────────────────────────────────────────────────────┤
│ 📝 任务清单                                             │
│ [表格...]                                               │
└────────────────────────────────────────────────────────┘
```

**层次结构**:
1. 标题行: ID + 状态 + 标题 + 告警标记
2. 进度条: 可视化进度 + 数字 + 百分比
3. 里程碑条: 关键时间点
4. 甘特图: 可展开/收起
5. 任务看板: 五列小看板
6. 任务清单: 详细表格

### 3.4 色彩系统优化

**状态色彩语义化**:

| 状态 | 颜色 | 含义 |
|------|------|------|
| 待办 | 灰色 #6c757d | 未开始 |
| 进行中 | 蓝色 #4a7dff | 正在进行 |
| 联调 | 橙色 #ff9800 | 需要协作 |
| 测试 | 紫色 #9c27b0 | 质量验证 |
| 评审 | 青色 #00bcd4 | 待审批 |
| 完成 | 绿色 #28a745 | 已完成 |
| 阻塞 | 红色 #dc3545 | 需要关注 ⚠️ |

**视觉层级**:
- 主要信息: 深色文字 (#222)
- 次要信息: 灰色文字 (#666)
- 辅助信息: 浅灰 (#999)
- 分隔线: 浅灰边框 rgba(128,128,128,.1)

### 3.5 进度可视化

**多层次进度展示**:

1. **全局进度** (统计卡片)
   - 大号数字: 一眼看到完成数量
   - 百分比: 整体完成度

2. **需求进度** (任务组头部)
   - 进度条: 直观的填充条
   - 文字: 12/20 完成
   - 百分比: 60%

3. **甘特图** (时间维度)
   - 按状态分段着色
   - 时间轴对齐
   - 需求里程碑标记

4. **任务看板** (状态维度)
   - 五列状态分组
   - 每列显示数量
   - 卡片可点击查看详情

## 4. 技术实现

### 4.1 文件结构

```
packages/pages/dsh-pmboard/src/client/
├── view.ts              # 视图渲染（需增强）
├── styles.ts            # 样式定义（需增强）
├── board-mount.ts       # 交互逻辑（需增加筛选/排序）
└── types.ts             # 类型定义
```

### 4.2 主要改动

#### view.ts 改动

1. 新增 `buildTasksPageEnhanced()` 函数
   - 统计卡片渲染
   - 工具栏渲染
   - 增强的任务组渲染

2. 新增 `renderTaskGroup()` 函数
   - 优化布局结构
   - 添加可展开/收起功能
   - 章节化组织（甘特图、看板、清单）

3. 增强 `renderTaskTableEnhanced()` 函数
   - 改进表格样式
   - 优化列宽和间距
   - 添加 hover 效果

#### styles.ts 改动

新增样式类（约 9KB）:
- `.dsh-pm-task-stats` - 统计卡片区
- `.dsh-pm-toolbar` - 工具栏
- `.dsh-pm-view-switcher` - 视图切换器
- `.dsh-pm-progress-*` - 进度条系列
- `.dsh-pm-section-*` - 章节容器系列

#### board-mount.ts 改动

新增交互逻辑:
1. 筛选器事件监听
2. 排序逻辑实现
3. 视图切换处理
4. 章节展开/收起

### 4.3 数据流

```
BoardState (from store)
    ↓
buildTasksPageEnhanced()
    ↓ 
统计计算 + 分组 + 排序
    ↓
HTML 渲染
    ↓
board-mount 绑定交互
    ↓
用户操作 (筛选/排序/展开)
    ↓
重新渲染
```

## 6. 兼容性说明

- 保持与现有 RFC 014 设计一致
- 不改变数据结构
- 渐进式增强，不影响现有功能
- 支持降级（CSS不生效时仍可用）

## 7. 验收标准

1. **视觉效果**
   - ✓ 统计卡片正确显示各状态数量
   - ✓ 进度条准确反映完成比例
   - ✓ 颜色区分清晰，符合语义

2. **交互功能**
   - ✓ 筛选器正确过滤任务
   - ✓ 排序功能正常工作
   - ✓ 视图切换无卡顿

3. **性能指标**
   - ✓ 100个任务渲染 < 500ms
   - ✓ 筛选操作响应 < 100ms
   - ✓ 内存占用合理

4. **用户体验**
   - ✓ 关键信息一目了然
   - ✓ 操作流畅自然
   - ✓ 符合用户心智模型
