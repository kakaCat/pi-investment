本轮焦点按你的要求收窄到 卡片类型（不是尺寸）：先定"一张卡上到底有哪几种类型、每种长什么样"，再用真实队列数据把真 DAG 画出来验证类型系统够不够用。

① 卡片类型 = 三根轴，先定哪根是"类型"

队列数据里每张卡同时带三组身份字段，它们天然是三根正交的轴。现在线上只画出了 ID + 标题，三组字段全部可见，等于没分类。

轴字段取值（受控枚举）实测分布（616 卡）建议承担
轴 1 · 任务类型
建议 = 卡片类型		 phase 实施 / 测试 / 文档 / 评审 / UI / 分析 / 合并（7 类） 决定 ID 行徽标文案（+ 可选配色）。"这张卡是干什么的"，看 DAG 时最想知道的就是它。
轴 2 · 端侧 side backend / frontend / fullstack / doc（4 类） 次级标记（同一根 ID 行的小徽标）。回答"改哪一端"，对 DAG 流程判断帮助有限。
轴 3 · 角色 parentId / stageKind 独立卡 / 父卡（带子卡链）/ 子卡（dev·integrate·review·test） 决定卡形而非徽标：父卡的子卡链内嵌进度条，子卡默认不单独成节点。
（非类型）状态 status 待开始 / 开发中 / 联调中 / 测试中 / 待复核 / 已完成 已经占用了卡片底色（线上 6 态淡底），本轮不动。
为什么建议把 phase 定为"卡片类型"：实测 95.6% 的卡是实施+测试两类的组合，类型维度天然把 DAG 切成"写代码 / 验证"两段；而 side 只有 4 类且 77% 是 backend，作为主类型区分度太低。若你心里的"类型"其实是 side，请在下方裁定 1 里改选。

④ 一张卡上每个位置的语义（解剖图）

7 个位置，每个位置只承担一件事——这是"卡片类型确定"之后的落地口径。

  • ① 任务 ID — 等宽 10px 灰字，DAG 里的稳定标识；无任务卡文档时在右侧挂灰化 📄。
  • ② 类型徽标（本轮的"卡片类型"） — 10px 圆角小片，文案 = phase 中文；data-phase 供样式分色。
  • ③ 端侧徽标 — 更低一级的视觉权重（变体 ① 用纯文字无底）。
  • ④ 卡片底色 = 状态 — 六态淡底，与泳道卡片同一套色值，不另起一套。
  • ⑤ 标题 — 11.5px / 两行 clamp（等高是 DAG 可读的前提）。
  • ⑥ 子卡链进度（仅父卡） — 4 段小条：绿=已完成 蓝=进行中 灰=未开始，右侧 4/6 计数。
  • ⑦ 可开工标记（ready） — 绿点呼吸；直接消费队列的 ready[]，不是前端自己算的。

⑤ 真 DAG（用队列的 edges 画真连线）

卡片类型确定后，把它放进真图里验证。节点位置 = 队列 layers[]，连线 = 队列 edges[]（不再是"分层平铺看不出流程"）。悬停任一卡：橙色 = 它的上游、蓝色 = 下游；点击可钉住；边线按状态着色。

⑥ 待你裁定（4 条）

裁定后我按结果改 node-panel.ts（renderDag / renderSwimlane）+ styles/node-panel.ts，并把类型口径写进需求文档。

裁定 1 · "卡片类型"取哪根轴？ 建议：phase（7 类）

A. phase 作类型（实施/测试/文档/评审/UI/分析/合并），side 降为次级徽标 ← 我的建议
B. side 作类型（backend/frontend/fullstack/doc），phase 降为次级
C. 两根都要同级徽标（就是 /tmp/dag-card-demo.html 现在的样子）

裁定 2 · 类型要不要着色？ 建议：变体 ①（中性灰 + 文案）

A. 中性灰徽标：类型靠文案区分，饱和度全部留给状态底色 → 一屏不出现两套同色系语义 ← 我的建议
B. 七类彩徽标：识别更快，但要接受"实施=蓝"与"开发中=蓝"、"测试=橙"与"测试中=橙"、"合并=绿"与"已完成=绿"三处撞色

裁定 3 · 父卡的子卡链怎么进图？ 建议：内嵌进度条，子卡不单独成节点

A. 父卡一张卡 + 内嵌 4 段子卡进度，点开看子卡 ← 我的建议（实测 136 张子卡若全部成节点，图会立刻膨胀 3 倍）
B. 子卡单独成节点，父卡与子卡之间连边

裁定 4 · 状态底色（6 态）沿用线上不变？ 建议：沿用

A. 沿用现有六态淡底（与泳道卡片同一套） ← 我的建议，卡片类型只加"类型"这一层信息，不改已有语义
B. 借这次一起调状态色（那要另外配色表，会扩大改动面）
