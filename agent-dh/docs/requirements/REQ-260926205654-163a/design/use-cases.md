# 用例设计文档

**需求ID**: REQ-260926205654-163a

## UC-1: Agent 创建需求 «serves: FR-2»

**主要角色**：AI Agent

**前置条件**：Agent 识别到值得立项的工作

**触发条件**：调用 `reqboard_capture` 工具

**主流程**：
1. Agent 调用 `reqboard_capture` 并传入需求信息
2. 系统调用 `newRequirementId()` 生成编号
3. `newRequirementId` 调用 `formatTimestamp()` 获取时间戳
4. 拼接时间戳和随机hex生成完整编号
5. 返回编号给 Agent

**后置条件**：生成的编号格式为 `REQ-YYYYMMDDHHmm-xxxx`

## UC-2: 人工用户创建需求 «serves: FR-2»

**主要角色**：人工用户

**前置条件**：用户在看板上点击"创建需求"

**触发条件**：提交需求表单

**主流程**：
1. 用户填写需求信息并提交
2. 系统调用 `newRequirementId()` 生成编号
3. 返回编号并显示在看板上

**后置条件**：生成的编号格式为 `REQ-YYYYMMDDHHmm-xxxx`

## UC-3: 访问旧需求（兼容场景） «serves: FR-3»

**主要角色**：任意用户

**前置条件**：系统中存在旧格式编号的需求

**触发条件**：访问旧需求

**主流程**：
1. 用户通过编号访问需求（如 `REQ-260926205736-28e4`）
2. 系统按字符串匹配查找需求
3. 正常显示需求详情

**后置条件**：旧编号继续有效，功能正常
