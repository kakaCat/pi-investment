# REQ-640a55 数据模型（本轮无变更）

**结论：本轮没有数据模型变更，故本文件不设二级章节。**

逐类排除的理由：

1. **不新增、不改动任何表与字段。** 三处修复全在内存与文档层面：三要素判定是读 markdown 文本的纯函数，
   接线只新增函数调用点，编号判据只是正则与输入来源的修正。
2. **不改台账 schema。** `.dsh-data/dsh-reqboard.json` 的 `schemaVersion` 不动；
   `GateFailure['code']` 里新增的 `task_card_incomplete` 是 **TypeScript 类型联合成员**，
   不是持久化 schema（它早已声明、只是无人产出；本次只让它真被产出）。
3. **不改文件格式。** `docs/requirements/<REQ>/tasks/*.md` 的**章节契约**确实变了
   （新增三个必填节、一节改名），但那是**文档契约**而非数据结构：没有解析器、没有索引、
   没有迁移脚本读它，唯一的读者是门禁（按标题行匹配）与人。该契约的形态与理由写在
   `design/architecture.md` 与 `design/interfaces.md`。
4. **无迁移、无回填。** 存量卡不重写（见需求文档 §8 边界）；新门禁只在「离开拆分态」与「结单」
   两个时刻读文件，不改变任何已落库数据的含义。

> 后续若把任务卡章节结构做成可索引的数据（解析入库、看板卡片渲染依赖字段），本文件即为该变更的落点，
> 届时需补：字段清单、约束、迁移路径。
