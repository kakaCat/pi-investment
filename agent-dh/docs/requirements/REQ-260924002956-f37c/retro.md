# 复盘（REQ-260924002956-f37c）

## 根因

1. **拒绝不是请求级语义，只是第 1 问的一个选项 label**：四问一次性下发，宿主无"选此项终止"语义，UI 只能一路问完。
2. **rejected 判定发生在答案全部回收之后**：弹框问完才轮到 `mapCaptureAnswers` 发现 `rejected=true`，已有心无力。
3. **拒绝被当作"闸门作答"登记**：`GateAwareQuestions` 只要 `answers.length > 0` 就 `enqueue` G0，不区分肯定/拒绝。
4. **链上把"没需求"判成 negative 并发未通过文案**：G0 没有 `from`，回落到 `to='brainstorming'`，印出从未存在的节点状态。

## 修复方案

- 弹框拆两段：第 1 段问立项意愿+名称（含 ✖️ 不需要立项），命中拒绝立即收框
- 拒绝路径：写留痕 + 立即返回，不发起第 2 段，不登记 G0
- 肯定路径：第 2 段带 `gate: 'G0'`，四问一次问完 + 同调用内建单
- H4 无 `from` 的闸门负分支不再编"节点仍在 {to}"

## 防回归

- `tests/capture-tool.test.ts`：拒绝路径只发 1 段 ask
- `tests/gate-aware-questions.test.ts`：拒绝路径 G0 入队 0 次；肯定路径 G0 入队 1 次
- `tests/gate-handlers.test.ts`：无 from 闸门负分支不输出"节点仍在"；有 from 仍印

## 教训

- **弹框的"取消"语义要在题目组装层就显式化**，不能依赖答案回收后的后验判定
- **闸门登记要区分"肯定作答"与"拒绝作答"**，拒绝不是一次未通过的闸门
- **无 `from` 的闸门在负分支不要编现状**，避免印出从未存在的节点状态
