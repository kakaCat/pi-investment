## 1. 背景与问题

用户原话：

> 目前盯盘引擎我很不满意，你调研一下目前v2项目的盯盘引擎的实现
> 我感受不到 agent 处理盯盘信息……之前设计的盯盘信息升级方式，消息会升级到agent来处理，我感觉升级这个没设计好
> 我希望解决盯盘信息噪音，还有盯盘信息多分几个级别。飞书展示不同颜值，让我知道核心信息
> （v2 意见）P1 待决策可以账户不一样，agent 的账户给 agent 处理，用户的通知用户就可以；需求里没有说盯盘引擎的**业务流程闭环**；**确定 agent 参与了**，不能让盯盘信息一直停在 l1、l2 层不到 l3 agent 里
> （v3 意见）I1 不得滞留是目前噪音的主要原因，触发多次了，是不是需要 agent 来调整一下规则，延长时间或者修改规则

### 1.2 噪音的两个根（本需求要同时治）

1. **规则配置不当**：阈值贴着市价、反复穿越、冷却与阈值不匹配 → 同一条件一天响十几次。
2. **冷却状态会丢**：闩锁/冷却/价格历史全在进程内存，重启即清 → 冷却形同虚设。

结论：反复触发的正确处置对象是**规则本身**，不是「再叫一次 agent 去交易」。

## 2. 目标

让每条盯盘信息**有级别、有归属、有流转、有时效、有回执**，**保证一路走到 L3（agent）或到你本人**，并且**反复触发会被收成「修规则」而不是刷屏**：你一眼看到核心信息，且能确信 agent 真的参与了处理。

## 3. 需求

### R1 级别体系（4 档，决定「颜值」与时效）

| 档位 | 含义 | 飞书形态 | 可静默 | 是否 @ |
|------|------|----------|--------|--------|
| P0 立即处置 | 宪法级：止损/熔断/仓位超限/单笔超阈值 | 红卡 | 否 | 是 |
| P1 待决策 | 需要有人拍板：买卖节点、规则变更请求 | 橙卡（有 N 项等你确认） | 否 | 否 |
| P2 知悉 | 不需行动但要知道：接近触发位、板块异动、持仓状态变化 | 蓝卡，简短/可聚合 | 可 | 否 |
| P3 归档 | 纯记录：趋势观察命中、去重合并、反复触发的聚合、治理项 | 不单独推送，进日终汇总 | 可 | 否 |

判定依据（机器判定，不允许 agent 自由发挥）：规则显式声明的意图 + 是否持仓 + 是否宪法级。

### R2 业务流程闭环（端到端）

**三个维度正交**：级别（P0–P3）× 流转态（L1/L2/L3）× 账户（谁接手）。

**闭环八环**：触发 → 分级 → 路由（按账户定接收者）→ 投递（飞书/唤醒）→ 处置 → 回执 → 收敛（终态）→ 归档/退役（规则生命周期）。

| 流转态 | 含义 | 退出条件 |
|--------|------|----------|
| L1 通知 | 已投递，尚无归属/未认领 | 有人认领 或 SLA 到期晋升 |
| L2 待办 | 有 owner、有 SLA、已进队列，尚无处置结论 | 产出处置结论 或 SLA 到期晋升 L3 |
| L3 处置 | agent 或你本人必须给出结论并回执 | 终态（handled / ignored / expired） |

**硬不变式（5 条，全部可证伪）**：

- **I1 不得滞留**：任何触发不得停留在 L1/L2 超过 SLA；到期未收敛 → **强制晋升 L3（agent）或升级到你本人**。（回应「不能让盯盘信息一直停在 l1、l2 层」）
- **I2 处置对象可以是规则**（v3 新增）：闭环的终点是「有人处置」，处置动作类型包括——执行交易 / 拒绝并写明 NEXT / **修改规则（冷却、阈值、拆分合并、退役）**。反复触发的默认出路是**修规则**，不是反复叫交易。
- **I3 必有终态**：每条触发最终且只能收敛为 handled / ignored / expired 之一（含理由），不存在永久 pending。
- **I4 agent 必参与**：凡进入 L3 的待办，必须有可核验的处置结论（终态 + 理由 + 动作/拒绝理由与 NEXT 条件），并可回溯留痕。
- **I5 账户定接收者**：agent 自有账户 → agent 处置（可自主，走 R-001~R-009 与 decision_audit 留痕）；用户账户 → 通知你本人，agent 只出建议、不得下单。

### R3 账户路由（谁接手、谁见、谁回执）

| 账户 | 接收者 | agent 权限 | 回执对象 |
|------|--------|-----------|----------|
| agent_brain 等自有账户 | agent（L3） | 可自主处置含下单、可自主改规则 | 回执给你（知悉） |
| user_main_simulation 等用户账户 | 你本人（P0/P1 必达） | 只出建议；改规则/下单均需你确认 | 回执给你（含 agent 建议） |
| 无账户归属 | 视为数据缺陷：照常走闭环并优先补归属 | 补归属前不得下单 | 回执给你 |

### R4 每档飞书消息形态（「颜值」的具体化）

- **P0 红卡**：首行 `@你 ｜ 601600 中铝国际 触发止损线 26.88（现价 26.57）`；字段含 账户 / 规则# / 级别标签 / 触发条件 / 现价 / 预案 / 待办#；不可静默；带「处置结果」回执位。
- **P1 橙卡**：首行 `有 2 项等你拍板 ｜ 601888 中国中免 触及买点 53.5`；列 2-3 条摘要 + 每条账户与规则#；带处置入口；同账户合并成一张卡。
- **P2 蓝卡**：首行 `[知悉] 002916 深南电路 接近上破位 388.75`；一行一条，可按时段/标的聚合。
- **P3**：不单独推送，进日终汇总清单（含反复触发聚合）。
- **共性纪律**：首行必须一眼看到「标的 + 现价 + 该干什么」；每条可追溯到规则#与待办#；颜色/图标/是否 @ 由级别决定，不由文案决定。

### R5 升级链：升级 = 显式待办（不是一条消息）

- 触发落成待办：owner、level、flow_state、SLA、状态、终态。
- 自动升级只保留两类：**宪法级**（无条件、不受预算限制）与**异常波动**（急涨急跌超阈值，按 metric 取数、带节流）。
- **删除**现有 触发频率 / 量能异常 / 多规则共振 / 核心区域 四类自动升级。其中「触发频率」的语义**改写为规则自愈**（见 R6），不再等于「叫 agent 交易」。
- 规则可显式声明命中即交 agent 处置。
- 回执三段：① 升级即回执（已交 agent / 已通知你，SLA x 分钟，待办 #id）；② 处置后回执（结论 + 动作，或「不动 + NEXT 条件」）；③ 超时回执（超时未处理 → 回执并把待办升级给你）。
- 预算：P0 不受预算限制；P1/P2 按级别分别计日预算（替换现有 8 次/天一刀切）。

### R6 规则自愈闭环（v3 新增：反复触发 → 修规则）

**触发判定**：同一规则（或同标的同向）在窗口内触发次数超阈值——例：单日 ≥ N 次，或连续 M 日触发。具体阈值在技术设计阶段定量，必须先于实施给出可证伪默认值。

**处置两步（顺序固定）**：

1. **自动抑噪（即时，零 token）**：该规则立即降级为 P3 聚合（不再逐条推送），并按规则自动延长冷却；同标的同向窗内去重合并继续生效。
2. **生成「修规则」待办（交 agent / 你）**：处置动作候选——延长冷却、调整阈值/方向、拆分或合并规则、退役。修复后该规则恢复原级别。

**权限（与 I5 一致）**：自有账户规则 → agent 可自主修改并留痕（decision_audit + 规则变更记录）；用户账户规则 → 只提请，你确认后才改。

**治理前置**：规则体检（重叠、一直响、一直不响、阈值失真）产出的治理项统一进 P1 待决策，不再作为 meta_review 积压无人消费。

### R7 闭环时效（SLA）

| 档位 | SLA | 流转路径 |
|------|-----|----------|
| P0 | ≤ 5 分钟 | L1 → L3（直达 agent，或直达你） |
| P1 | ≤ 30 分钟 | L1 → L2 → L3 |
| P2 | 当日 | L1 → L2，当日未收敛则升 L3 |
| P3 | 无 SLA | L1 → 归档（仅规则体检/自愈可把它提请进 L3） |

### R8 噪声治理（判据层）

- 判据必须按 **metric 类型**取数（价格/涨跌幅/量比/指标值/事件/板块强度），根治「拿现价当量比」这类误读。
- 聚合：P2/P3 聚合推送；同标的同向窗内去重合并保留（仍落库，保证账不丢）。
- 反复触发的抑噪与修复见 R6。

### R9 表达能力扩展（分阶段，全部纳入本轮需求）

| 阶段 | 内容 | 数据底座（已核） |
|------|------|------------------|
| 一 | 指标类条件 | factor_values / 技术打分 / 因子框架 |
| 二 | 板块与市场联动 | sector_snapshot / 产业链表 / market_perception |
| 三 | 事件类条件 | event_calendar（7.2 万条）/ 事件域端口 |

每阶段独立验收、可回滚；数据源降级必须显式标注 degraded，不得用 0 或空冒充事实。

### R10 状态持久化（v3 新增，独立于「观测面」）

闩锁、冷却基准、价格历史、去重窗、触发事件统计必须**跨重启保持**（落库或可恢复快照），否则冷却形同虚设、重启即重复推送（实测单日 23 次 > 1800s 冷却理论上限 16 次即为此因）。

**边界**：本项不新建任何面板或指标出口——它是「冷却是真的」的必要修复，与用户裁定的「观测面不做」不冲突。

### R11 旧账与迁移

- 渐进修复：保留现有规则，先修判据与唤醒链，再逐条体检退役/修规则。
- 172 条积压一次性归类：能机器收敛的机器收敛，其余并入 P1 一次性交你裁决——按 I3 必须落到终态。
- 高频规则（#119/#92/#121/#57/#105 等）优先纳入自愈与修复。
- 持仓止损规则不中断（交易宪法第 4 条）。

## 4. 成功标准（可证伪）

1. **闭环必达**：任一交易日，P0 待办 100% 在 SLA 内落到终态；P1/P2 当日终态率 ≥ 95%；unresolved 积压不再单调增长。
2. **不滞留（I1）**：查询任意时间窗，不存在「创建超过 SLA 仍处于 L1/L2 且无晋升记录」的触发。
3. **agent 必参与（I4）**：所有 L3 待办 100% 有处置记录（终态 + 理由 + 动作或 NEXT）。
4. **反复触发得治（R6）**：单规则单日触发次数存在上限（设计给出具体值），超限即转聚合且不再逐条推送；「修规则」待办当日收敛率 100%；对 #119/#92/#121 这类规则，修好后同口径触发次数显著下降（前后对比可查）。
5. **冷却是真的（R10）**：重启前后同一规则的触发间隔仍受冷却约束——重启不得使冷却失效（可用重启前后触发时间戳验证）。
6. **判据可信**：不存在「disposition_reason 与 detail metric 不一致」的记录；规则 #162 场景回归——price_break 触发不得产出「量能异常」。
7. **账户路由（I5）**：用户账户的触发不出现 agent 自主下单或自主改规则；agent 自有账户的触发不出现「只通知不处置」。
8. **可见性**：任一待办可追溯「升级即回执 → 处置回执」两段；超时必有超时回执。
9. **噪声**：单位交易日 P0+P1 消息量有明确上限（技术设计定稿），P3 不再单独推送。
10. **能力**：每阶段新增条件类型上线，并有回放验证记录。

## 5. 非目标

- 不做盯盘控制台页面（用户裁定：靠现有接口与飞书消息）。R10 状态持久化不属于观测面。
- 不改交易宪法与止损口径；不改账户归属单一事实源（R-019）。
- 本节点不写技术设计（属 planning）。

## 6. 已裁决的矛盾（自查发现）

1. 「闭环必达」vs「不做观测面」→ 裁决：**最小保留引擎存活与影子模式超期告警**（线程死/未启动/影子模式挂超期 → 飞书），不新建面板。
2. 「反复触发自动延长冷却」vs「agent 才该决定规则」→ 裁决：**自动动作限定为抑噪（降级聚合 + 临时延长冷却），持久性的规则修改按账户授权执行**；用户账户规则只提请。自动动作必须留痕且可回滚。

## 7. 风险

- 真开唤醒会真实产生委托 → 授权按账户分级；实施期先影子核对一份摘要样本。
- 「不得滞留」的强制晋升会推高 agent 唤醒量 → 用 R6 抑噪 + 级别预算平衡，阈值在技术设计阶段定量。
- 自动延长冷却可能掩盖真信号 → 抑噪只改投递级别不改判定；真信号仍进 L3，且聚合摘要里可见。
