# REQ-c9f899 实施计划（planning 节点产物）

## 1. 目标

把 v2 盯盘引擎从「产生噪声、不产生决策」改造为**有级别、有归属、有流转、有时效、有回执**的闭环，并让反复触发被收敛成「修规则」而不是刷屏。落地需求文档 v3 的 5 条不变式（I1 不得滞留 / I2 处置对象可为规则 / I3 必有终态 / I4 agent 必参与 / I5 账户定接收者）。

## 3. 验收（可证伪，对应需求 §4）

1. 任一交易日：P0 待办 100% 在 SLA 内落终态；P1/P2 当日终态率 ≥95%；积压不单调增长。
2. 不存在「超过 SLA 仍处 L1/L2 且无晋升记录」的触发。
3. 所有 L3 待办 100% 有处置记录（终态+理由+动作/NEXT）。
4. 单规则单日触发存在上限，超限转聚合不再逐条推送；修规则待办当日收敛率 100%；#119/#92/#121 修复后触发次数显著下降。
5. 重启后冷却仍生效（触发间隔 ≥ cooldown）。
6. 不存在 reason 与 detail metric 不一致的记录；#162 场景回归：price_break 不得产出「量能异常」。
7. 用户账户规则不出现 agent 自主下单/自主改规则。
8. 任一待办可追溯「升级即回执 → 处置回执」；超时必有超时回执。

## 5. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 强制晋升推高唤醒量 | 自愈抑噪 + 级别预算平衡；灰度先只对 agent_brain |
| 自愈误伤规则 | 抑噪只改投递级别；持久修改按账户授权 + 全量审计可反向应用 |
| 新闭环异常 | 全部开关化；双写期可一键回旧路径 |
| metric 改造引入回归 | #162 场景故障注入 + watch 全量测试零新增失败 |
