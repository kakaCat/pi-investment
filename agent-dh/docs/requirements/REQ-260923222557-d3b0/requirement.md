# REQ-260923222557-d3b0: 节点提示词注入 Worktree 规范 + 弹框超时时间调整

**状态**: design  
**类型**: feature  
**创建时间**: 2026-09-23

## 边界

### 做什么
1. **在拆分完成节点注入提示词**：implementing 节点开始时，系统提示词中注入"应创建 worktree"的操作规范
2. **在子任务完成节点注入提示词**：子任务完成时，提示词中注入"应在 worktree 中 commit"的规范
3. **在验收完成节点注入提示词**：done 状态时，提示词中注入"应合并并删除 worktree"的规范
4. **调整所有节点弹框超时时间为 1 小时**：所有 reqboard 相关的确认弹框（reqboard_ask_confirm、ask_user_question）超时时间从 2 分钟调整为 1 小时
5. 规范内容包括：命令示例、目录规范、分支命名约定
6. **修复节点详情面板三处 UX 问题**（2026-09-23 本窗口实测发现）：设计节点头部胶囊停留在旧管线语义（恒显示「待提交计划」）；拆分节点缺「待交文档」占位（看起来"拆分文档没了"）；面板头状态词在预览未到达节点时用过去式撒谎（未拆分却显示「已拆分」）

### 不做什么
1. 不在工具代码中硬编码自动执行 git 命令
2. 不强制 agent 必须执行（agent 可根据实际情况判断）
3. 不改变现有 worktree 的手动创建方式
4. 不影响其他非 reqboard 弹框的超时时间
5. 不改 StageDetail / StageOverview 数据契约与台账 schema（面板 UX 修正全部落在 client 渲染层）
6. 不回溯修改历史需求的台账数据（展示按新口径自然生效）

## 产品定义

**核心问题**：多个 agent 窗口在同一台机器上并行工作时，如果都在主工作区操作，会产生 Git 冲突（分支切换、文件修改冲突）。

**解决方案**：每个需求使用独立的 worktree（`.worktrees/REQ-{id}/`），在各自的分支上工作，互不干扰。

**实现方式**：

### 1. Worktree 提示词注入
通过**节点提示词注入**的方式，在关键节点向 agent 传达 worktree 操作规范。

### 2. 弹框超时时间调整
将所有节点的确认弹框超时时间从 2 分钟（120 秒）调整为 1 小时（3600 秒），给用户更充足的思考和确认时间。

**核心价值**：
- **解决多 agent 并行工作的 Git 冲突问题**
- 每个需求在独立 worktree 中开发，互不干扰
- Agent 获得清晰的 worktree 操作指引
- 用户有足够时间审阅和确认，不会因超时错过确认

## 用户与角色

- **Agent 窗口**（主要用户）：在关键节点收到 worktree 操作提示，按规范执行；确认弹框有更长等待时间
- **人工用户**：审阅需求文档、设计方案、拆分计划时不会因 2 分钟超时而中断
- **系统维护者**：在节点提示词模板中维护 worktree 规范

## 功能点

- **FR-1: implementing 节点提示词注入** — 需求进入 implementing 状态时，节点提示词中注入创建 worktree 的规范和命令示例

- **FR-2: 子任务完成时在 worktree 中 commit** — 每个子任务完成（reqboard_task_move → done）时在 worktree 中提交代码（每个子任务都形成 commit 检查点，修改后重新 commit，可回滚到正确版本）

- **FR-3: 归档节点提示词注入** — 需求验收通过（accepting → archived）时，提示词中注入合并并删除 worktree 的规范

- **FR-4: 提示词模板机制** — 利用现有的节点路由提示词机制（类似 brainstorming/design 的路由提示词），在对应节点自动注入

- **FR-5: reqboard_ask_confirm 超时调整** — 将 reqboard_ask_confirm 工具的默认超时时间从 120000ms（2 分钟）改为 3600000ms（1 小时）

- **FR-6: ask_user_question 超时调整** — 将 ask_user_question 工具在 reqboard 上下文中的超时时间调整为 1 小时

- **FR-7: 配置化超时参数** — 超时时间应可配置，方便未来调整，不应硬编码

- **FR-8: 设计节点头部进展胶囊对齐新管线** — stageHeadSummary 的 design 分支不再以「计划提交」为口径（2026-09-21 起设计阶段只写设计文档、不提交计划，导致该胶囊恒显示「待提交计划」），改按设计文档交付/确认状态取词；存量旧管线需求（design 阶段已有 plan 记录）保持旧文案兼容

- **FR-9: 节点文档行可点化与「待交占位」口径统一** — 设计节点已交付（✅）的设计文档渲染为可点击文档行（复用 docItem，右侧栏打开），未交付保持 ⬜ 纯文本；拆分节点在未提交 decomposition.md 时渲染「⬜ 拆分计划：decomposition.md（未交）」占位行，与设计节点必交清单的占位口径一致

- **FR-10: 面板头状态词按节点到达状态取词** — 节点面板头部状态胶囊在预览「未到达」节点（stageRowState=pending）时不再使用过去式（已拆分/已设计等），显示中性词「未开始」；已到达（done）与当前（current）节点保持现取词不变

## 接口定义

### Worktree 提示词注入

#### 输入
- **节点状态**: implementing / task_done / done
- **需求 ID**: REQ-xxxxxx
- **任务信息**（子任务完成时）: task_id, task_title

#### 输出
- **系统提示词段落**：在对应节点的提示词中注入 worktree 操作规范

### 弹框超时时间

#### 输入
- reqboard_ask_confirm / ask_user_question 调用（reqboard 上下文）

#### 输出
- 超时时间：3600000ms（1 小时）

#### 配置位置
- 工具定义中的 timeoutMs 参数
- 或统一的 reqboard 配置文件

## 数据契约

无数据模型变更。

## 迁移与兼容

- **旧节点**：无影响，新提示词只对新推进的节点生效
- **已有弹框**：立即生效，所有新发起的弹框都使用 1 小时超时
- **回滚**：可直接回滚

## 验收标准

### Worktree 提示词注入验收

```bash
# 1. 需求推进到 implementing 后，查看系统提示词
# （在 agent 对话中应能看到 worktree 创建规范的提示）

# 2. agent 执行后验证
ls .worktrees/REQ-xxxxxx/  # 应存在
git worktree list | grep REQ-xxxxxx  # 应可见
```

### 弹框超时时间验收

```bash
# 1. 触发任意 reqboard 确认弹框（如 reqboard_ask_confirm）
# 2. 等待超过 2 分钟（旧超时时间）
# 3. 验证弹框仍然存在，未超时
# 4. 等待接近 1 小时
# 5. 验证弹框在 1 小时左右超时
```

### 节点面板 UX 验收（FR-8/9/10）

```bash
# 1. FR-8：打开一个处于 design 阶段的新管线需求详情
#    头部第二胶囊不再显示「待提交计划」，显示设计文档交付/确认状态
# 2. FR-8 兼容：打开旧管线需求（design 阶段有 plan 记录，如 REQ-47939a）
#    头部仍显示计划类文案（计划待批准/已批准）
# 3. FR-9：设计节点已交付的设计文档可点击，右侧栏打开文档
#    拆分节点（未提交 decomposition.md）显示「⬜ 拆分计划：decomposition.md（未交）」
# 4. FR-10：需求处于 design 阶段时点开「拆分」节点预览
#    头部状态胶囊显示「未开始」而非「已拆分」
# 5. 单测：npx vitest run packages/web/dsh-pmboard/tests/stage-panel.test.ts 全绿
```
