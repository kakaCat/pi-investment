## 汇报 1（2026-09-27T08:52:28.350Z，窗口 8ae828f6-441f-4b25-baa6-720853c4821f）

复核结论：design/interfaces I-1..I-4 四份可执行契约与实现逐条**无偏离**（静态对账 + dev/integrate 两卡的线上 9 条实调证据）。I-6 契约门禁有 2 条已文档化/口径级偏离：①ClearPauseTool 仍是旧式 parameters.schema（test 白名单显式留债，与 interfaces.md 无条件表述有出入）；②tools-schema 的「构造全部工具」是手写 18 项清单+length 断言，非从 src/index.ts 派生。另发现 1 条**非规格但真实的功能缺陷 R-1**：reqboard_task_run/execute 的渲染器错配（AdvanceTool 仍 wire reqboard_move 的 moveSummary），失败时读 o.note（I-1 返回的是 error）→ 渲染成「❌ 需求推进被拒：见明细」，**丢掉真实错误文本**；成功时不显示 status/job_id/run_id/chain/next_ready。R-1 建议返工，根因是 I-1 契约改造未传导到渲染层，而 output-contract 门禁只扫 return 顶层键、扫不到渲染器读取的键。

### 完成项

- I-1 无偏离：parameters task_id?/requirement_id?；autoRun 副作用写进描述（ADVANCE_PROMPT 明写「调用即写 req.autoRun=true」）；output.schema 12 键 = 返回体；subtask_executed/blocked/stopped 已从 schema 与返回体删除（grep 仅剩注释）；三错误码在位（NO_BOUND_REQ / DSH_JOBS_UNAVAILABLE / REQBOARD_DISPATCH_FAILED）。依据：源码 + 线上 L3/L4/L5
- I-2 无偏离：保留工具名（线上 L6 可直接调用）；Object.assign 复用 defineAdvanceTool 同一 factory（同 parameters/output/execute，无第二套实现）；描述首句「【已弃用：等价 reqboard_task_run，请改用后者】」；线上 L4 与 L6 同输入**逐键同形**

- I-6 偏离 2 条（已文档化/口径级，非阻断）：①ClearPauseTool 仍 parameters:{schema:{}}，tools-schema 以 LEGACY_PARAM_SHAPE 白名单+旧式断言显式留债——与 interfaces.md「不得出现 parameters.schema」的无条件表述有出入；②tools-schema 的「全部已注册工具」实现为手写 FACTORIES 18 项 + toHaveLength(18) 断言，未从 src/index.ts 注册清单派生——今日等价，但新增工具只改注册不改清单时门禁不会红（设计意图『少一个即红』只覆盖清单自身）
- R-1（非规格但真实缺陷，建议返工）：AdvanceTool.ts:66 render:renderSmart(moveSummary) 用错渲染器——moveSummary 属 reqboard_move，只读 requirement_id/from/to/note；I-1 实际返回 error/status/next_ready/chain → 失败分支渲染「❌ 需求推进被拒：见明细」（丢真实错误原因），成功分支渲染「🔀 REQ-…」不显示 job_id/run_id/status/chain/next_ready。另 taskRunSummary 未被任何 src 引用且仍读已删除的 stopped/subtask_executed（render-summaries.ts:174/176），tests/render-summaries.test.ts:28 也仍以 subtask_executed 为输入——渲染层整体停留旧契约
- R-1 根因与门禁盲区：本次 I-1 契约改造只改工具壳 + output.schema，未传导到渲染层；I-6① 的 output-contract 只扫描工具工厂 return 顶层键，**渲染器读取的键不在门禁覆盖内**——故『声明与行为一致』的门禁对渲染层无约束力（本次即漏检）
