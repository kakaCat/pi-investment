## 边界

### 做什么

1. **会话「流程节点」面板里的 DAG 换成 Canvas 真图**：
   - 实施阶段的 `[DAG]` 页签（当前渲染 `renderDag`）；
   - 拆分阶段的「📊 DAG 层级」块（同一 `renderDag`，同一份观感债）。
2. **两处共用同一个面板构建函数**，画布 id 参数化（`buildDagCanvas`/`mountDagCanvas`/`tryMountDagCanvas`
   各增一个可选 `canvasId`，缺省 = 现有画布 id）；需求详情与流程节点面板可同时各挂一块，互不抢占。
3. **挂载幂等、时机正确、按容器宽度自适应**：同一 id 先释放再挂；HTML 进 DOM 之后再挂（rAF + 存在性检查）；
   容器宽度变化（侧栏展开/收起、窗口缩放）按新宽度重排，不写死宽高。
4. **面板骨架皮肤统一到会话面板的 np 苹果风**（订正项；2026-09-29 裁定 B 后**无标题行 / 无统计条**）：说明 / 工具条 / 画布区滚动条 / 图例
   一套 DOM + 一套样式，两处（会话面板、需求详情）由同一函数产出、DOM 类名与结构逐项相同；
   样式口径 = `--dsh-pm-np-*` 苹果风令牌（白底圆角、980px 胶囊、#f5f5f7 块、轻阴影），不再引用 `--dsw-*` 主题变量。
5. **开关 / 图例同源**（2026-09-29 裁定 B：统计条已删）：纵向·横向、关键路径、只看主线三项开关与图例，
   两处逐字一致。

### 不做什么

1. **不改 canvas 卡片绘制、不改 `dag/*` 渲染语义**：卡片层折叠 / 传递归约 / 箭头分级 / 类型·端侧徽标 /
   208×72 几何 / 配色全部沿用。**（2026-09-29 裁定 D 覆盖：父卡左侧蓝条删除，`card-renderer.ts` 不再是零 diff——改动仅此一处。）** 两处共用同一渲染器，天然一致。
2. **不动泳道页签、五列小看板、甘特图、任务表格、任务卡详情**；不新增第二套 DAG 实现；不改任务打开链路
   （画布双击仍走既有 open-task 事件委托）。
3. **不改数据契约**：入参仍是既有任务形状（`id/title/status/phase/side/dependsOn/parentId/stageKind/cardDoc`），
   台账字段与队列文件零改动。

## 产品定义

### 一句话目标

「会话右上角看到的依赖图」与「需求详情里的依赖图」**是同一张图、同一套皮肤**（会话面板的 np 苹果风）：
同一份数据桥、同一套绘制、同一套统计与开关、同一套外壳样式，不再一个分层列出、一个真图，也不再两种观感。

### 核心价值

1. **认知一致**：同一个需求，两处看同一张图、同一种观感，不必先在心里翻译布局与配色差别。
2. **各少一套**：DAG 展示只剩一条实现路径、一套面板皮肤，后续改 DAG 只改一处。
3. **复用已交付能力**：折叠 / 归约 / 箭头降噪 / 悬停高亮 / 钉住 / 切向，全部白拿。

## 用户与角色

| 角色 | 场景 | 期望 |
|---|---|---|
| 会话使用者（人） | 在会话里看当前需求的依赖拓扑 | 右上角那张图与需求详情逐项一致（含皮肤），能一眼看出可开工卡与关键路径 |
| 流程节点面板（`renderNodePanel`） | 渲染实施/拆分阶段内容 | 复用 `buildDagCanvas` 的面板骨架与 np 皮肤，不改自身其它区块 |
| 需求详情（`buildDag`） | 既有消费方，本轮**也**换肤 | 面板骨架从 `DAG_CSS`（dsw 主题）换成 np 苹果风；画布卡绘制不变 |

## 功能点

- **FR-1: 流程节点面板的实施阶段 [DAG] 页签改渲染 Canvas 真图面板**
  - 输入：该阶段 payload 的 `tasks`（全量，含子卡）；输出：`buildDagCanvas(tasks, 容器 id, 画布 id)` 的面板 HTML + 挂载后的交互式画布。
  - 判据：HTML 含 `dsh-pm-dag-panel` 骨架 + 独立 `<canvas id>`；不含旧 `dsh-pm-np-dag` 分层列表；三个开关 / 图例与需求详情逐字相同（两处均无标题行 / 统计条）。
- **FR-2: 拆分阶段的「📊 DAG 层级」块同步改渲染同一 Canvas 真图**
  - 判据：该块 HTML 与 FR-1 同源同结构（同一构建函数的产物），同样含独立 canvas 骨架与同一套工具条 / 图例。
- **FR-3: 画布 id 参数化，同页两实例互不干扰**
  - 接口：`buildDagCanvas(tasks, containerId, canvasId?)`、`mountDagCanvas(tasks, ready?, canvasId?)`、`tryMountDagCanvas(tasks, ready?, canvasId?)`；缺省即现有画布 id（需求详情调用方不改、行为不变）。
  - 判据：两处 DAG 同时存在时 DOM 里两个 canvas 的 id 不同；各自挂载的 viewer 互不释放对方。
- **FR-4: 挂载幂等且按容器宽度自适应**
  - 判据：同一 canvasId 连续两次 `tryMountDagCanvas` 不产生两块画布、不抛异常；容器宽度变化后画布按新宽度重排。
- **FR-5: 面板侧挂载时机正确（HTML 进 DOM 之后再挂）**
  - 复用 `requestAnimationFrame` + `document.getElementById(canvasId)` 存在性检查的既有模式；目标 canvas 不存在时静默返回（不抛、不报错、不空白）。
  - 判据：面板未展开 / 未渲染时调用不报错；展开后画布正常绘制；DAG↔泳道 页签来回切换后画布仍在。
- **FR-6: 面板骨架皮肤统一为会话面板的 np 苹果风（两处同皮肤；canvas 卡片零改动）**
  - 实现：面板块由同一个 `buildDagCanvas` 产出（同一份类名与 DOM 结构）；样式口径改用 `--dsh-pm-np-*` 苹果风令牌与 np 视觉值（白底圆角、980px 胶囊、#f5f5f7 块、轻阴影），不再引用 `--dsw-*` 主题变量。
  - 判据：两处 DAG 面板 DOM 类名集合逐项相同；`grep -n -- '--dsw-' src/client/styles/dag.ts` 无命中；`card-renderer.ts` 的改动**仅限** 2026-09-29 裁定 D（删除父卡左侧蓝条），徽标 / 几何 / 配色零改动。
  - 已知取舍（显式记录）：np 皮肤是固定浅色，DAG 面板不再随明暗主题变化——用户 2026-09-29 追认。
- **FR-7: 面板侧 ready 口径诚实标注** —— **2026-09-29 用户裁定 B 作废**
  - 作废原因：面板不再有统计条（裁定 B「两处都删标题行 + 统计条」），「统计条标『推导』」这条判据不成立。
  - 保留语义：`ready` 仍是两态（`undefined` = 前端按依赖推导；传空数组 = 队列确实无可开工卡），
    但它现在只驱动画布上的**可开工绿点**，不再有任何文字标注（不冒充队列口径这条纪律本身不撤）。

## 接口（对外入口的输入 / 输出 / 错误语义）

| 入口 | 输入 | 输出 | 错误语义 |
|---|---|---|---|
| `buildDagCanvas(tasks, containerId, canvasId?)` | 任务全量（含子卡）；面板容器 id；画布 id（可选） | 面板 HTML 字符串（空任务 → 空态占位） | 无副作用；空态返回占位串 |
| `mountDagCanvas(tasks, ready?, canvasId?)` | 同上 + 队列 ready[]（可选） | `DagViewer \| undefined` | 找不到画布或顶层卡为空 → 返回 `undefined`（不抛） |
| `tryMountDagCanvas(tasks, ready?, canvasId?)` | 同上 | `void`（rAF 后执行） | 内部 catch 并 `console.error`，不打断宿主渲染 |

- **入参类型放宽**：面板侧给的是 `StageTaskRef[]`（`StageOverview` 的任务引用），字段是 `TaskRecord` 的**子集**
  （无 `requirementId/scope/acceptance/context` 等）。三个函数的入参类型须收敛为「绘制真正用到的那几个字段」的
  结构类型（或最小适配层），不要求面板侧伪造完整 `TaskRecord`——`StageTaskRef` 已含
  `id/title/status/phase/side/dependsOn/parentId/stageKind`，绘制所需字段齐全。
