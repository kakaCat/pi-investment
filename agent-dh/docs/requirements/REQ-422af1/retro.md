## 二、踩了什么坑（可复用教训）

1. **并发写入会让门禁给出瞬时假红**：修复浏览器包泄露后首次 `tsc` 报 exit 2，复跑 exit 0 —— 因为另一个子代理正在改 src，门禁跑在"半个写入"的状态上。**最终门禁必须在所有写入者停止后再跑一次**。
2. **用 grep 判断"是否 import 框架"会被注释骗**：`grep -n "@deepseek-ai/" src/application/` 命中 2 处，实际都是注释（其中一条还写着"不 import …"）。守卫正则必须**行首锚定**（`^s*import .*@deepseek-ai`）。
3. **用 `git diff --cached` 核验 plumbing 提交会误判**：临时索引 + `commit-tree` 建提交时，`git diff --cached` 的基准是**当前 HEAD（wip 分支）**而不是你正在构建的 main，于是显示 1535 文件含 1360 残留，实际提交只有 136 个文件且 0 残留。核验 plumbing 提交要用 `git show <branch>` / `git diff <base> <branch>`。
4. **重建产物会暴露既有耦合**：t7 把 StagePromptSpec 接到 prompt/index 后，t11 一次 `build:client` 就让全部提示词分片（+83KB）进了浏览器包——HEAD 的 bundle 里没有它们。**"重建"不是无害操作**，它会把原本只在服务端跑通的 import 链带进客户端产物；改依赖方向时必须跑一次客户端构建并检查产物。
5. **验收材料证据路径按工作区根解析**：写包内相对路径（`tests/x.test.ts`）会被判定"疑似编造"拒收。证据引用必须给仓库根相对路径。
6. **完成任务时容易漏关卡**：t3 被构建新鲜度门拦下后，我在批量关单里跳过了它，直到提交验收材料被 `blockers` 拦下才发现。**关单要点名核对清单，不靠印象**。
7. **测试残留会污染提交**：工作区里 1360 个 `docs/requirements/REQ-abc*/tasks/*` 残留来自测试；本次用精确路径清单提交（临时索引 + 白名单）避免把它们带进 main。
