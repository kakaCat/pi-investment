# UI 规格（serves: FR-3, FR-7, FR-9）

## D-UI-1 交付范围 `serves: FR-3, FR-7, FR-9`

**本需求基本无 UI 交付**——校验在插件进程内执行，产物是 Markdown 文档。
唯一例外（**显式声明**，避免"没写 = 漏了"）：

| 界面 | 变更 | serves |
|------|------|--------|
| 需求详情页 · 验收单 | 新增"**需求级**"分组（现有只有任务级） | FR-9 |
| 需求详情页 · 条款列表 | 每条功能点显示**接收状态**（已被 T-# 接收 / 已完成+证据 / 本轮不做 / **未被接收（红）**） | FR-3 |
| 看板卡片 | 任务标题用**业务语言**（数据源已是业务标题，无需改渲染） | FR-7 |

## D-UI-2 明确不做 `serves: FR-7`

- 不做 RTM 追溯视图 / Dashboard（需求 §8 边界，等闸门跑稳再定）；
- 不做文档健康分、门禁违规警示卡；
- 不改既有渲染框架。

## D-UI-3 交互规格（仅上述三项） `serves: FR-3, FR-9`

- **未被接收（红）**必须**显眼**——R9 能溜过去，正因为它当时在任何界面上都没有"没人接"的痕迹；
- 验收单"需求级"与"任务级"**并列**呈现，不折叠、不默认隐藏。
