# 迁移与回滚（serves: FR-12, FR-13）

## D-MIG-1 存量需求豁免 `serves: FR-12`

**问题**：门禁上线时历史需求都不带编号字段 → 若硬拦，全线告警。

**方案**：复用既有 isLegacy 判据（req.artifacts 为 undefined 或空数组）

| 需求状态 | 行为 |
|---------|------|
| 存量（artifacts 为空） | 第三级**跳过**，只警告 |
| 新建（走新流程） | 第三级**硬拦** |

**不新增豁免参数**（否决上一版设计里的 exemptionDate）——既有 isLegacy 语义已经够，
少一个可配置项就少一处漂移。**无数据回填**：老需求不强制补编号。

## D-MIG-2 灰度与开关 `serves: FR-12`

按需求 §9 版本切分灰度，**不是一次性全开**：

| 阶段 | 开启 | 观察指标 |
|------|------|---------|
| MVP | 覆盖门禁 + 编号串联 | 拦截率（预期 15–25%）、误报率（目标 <5%） |
| V2 | 接收标记 / 证据 / 全链路 / 三方一致性 / 验收四件套 | 拦截项分布 |
| V3 | 业务化 / 分类文档集 | 人工可读性抽检 |
| V4 | 注入聪明 / E2E 门禁 | — |

**开关**：新增门禁可**单独关闭**（关闭后行为回到今天），满足非功能"可回滚"。

## D-MIG-3 回滚步骤 `serves: FR-12`

1. 关闭新增门禁开关 → 三级退化为原两级；
2. 若需代码回滚：git revert（第三级调用点集中在 artifact-gates.ts 一处，回滚面小）；
3. **无数据库迁移**，无需数据回滚。

## D-MIG-4 不做什么 `serves: FR-12`

- 不做存量需求的编号回填（成本高、收益低，且会制造"看起来合规"的假象）；
- 不迁移既有 decomposition.md / 任务卡格式（新流程适用新格式，老文件只警告）。
