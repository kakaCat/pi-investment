# 会话进度节点详情 · 单节点面板设计稿 v3

## 0. 设计前提（用户已拍板的方向）

- **一个一个的**：点哪个节点只看哪个节点的内容，不把 8 个节点塞进一个面板。
- **一眼看全**由顶部流程条承担（8 节点状态始终可见），详情区专注当前选中节点。
- **用途是监控**：3 秒回答三个问题——①agent 走到哪了 ②这一步都干了什么 ③需要我做什么。
- **简约不等于简陋**：克制用色（1 主色 + 绿=完成 + 红=警示）、清晰信息层级、充分留白。

## 1. 布局总览（会话框进度面板）

```

│ ✓立项─✓需求分析─✓技术设计─✓拆分─●实施─○验收─○完成─○归档 │ ← 流程条=全局进度（一眼看全）
├────────────────────────────────────────────────────────┤
│  ●  实施 [进行中]                              第 5/8 步 │ ← 面板头：徽章+节点名+状态+步序
│      8/9 完成 · 进行中：构建部署实测与文档更新            │ ← 副标题：这一步在干什么
├────────────────────────────────────────────────────────┤
│  （节点专属内容区，见 §3 逐节点设计）                     │
│                                                        │
│  产物                                                   │ ← 固定区块：产物 chips（可点开文档）
│  [📄 需求文档] [📄 实施计划] [📄 拆分方案]                │
│                                                        │
```

## 2. 三种节点状态的视觉语言

```
├────────────────────────────────────────────────────────┤
│  进度                                                   │
│  ██████████████████████░░░░  8/9                        │
│                                                        │
│  任务                                                   │
│  ✓  t-fb59e6  定义节点契约与产物模型               已完成 │
│  ✓  t-b84dca  看板同源化+产物 chips                已完成 │
│  ◐  t-64a0c2  构建部署实测与文档更新    开发中 ←高亮行    │
```

- 徽章：18px 实心主色圆 + 2s 脉冲扩散环（CSS animation，一眼找到"当前"）
- 当前任务行：主色 6% 底 + 左侧 2px 主色条
- 进度条：6px 圆角，主色填充，右侧 x/y 数字

```
┌────────────────────────────────────────────────────────┐

│      计划已批准 · 9 任务                                │

```

- 徽章：绿底白✓；右侧带该节点完成时间（相对时间）

### 2.3 未开始节点（验收 · pending）— 灰，一句话预告

```
┌────────────────────────────────────────────────────────┐
│  ○  验收                                    第 6/8 步  │
│      待提交验收材料                                     │
├────────────────────────────────────────────────────────┤
│  还未到这一步——实施完成后 agent 提交验收材料，            │
│  由你人工审核（通过 / 退回返工）。                       │
└────────────────────────────────────────────────────────┘
```

- 徽章：灰描边空心圆；内容区只有一句"这一步会发生什么"的预告，不堆空区块。
- 分类跳过节点（如 bug 无需求分析）：虚线徽章 + 删除线标题 + "本分类跳过"说明。

## 3. 逐节点专属内容（点哪个看哪个）

| 节点 | 专属内容区 |
|---|---|
| 立项 | 需求标题(大字)+分类 pill + 描述(3行截断) + 来源窗口/创建时间 |
| 需求分析 | 评论对话流（作者色点：人=蓝/Agent=紫/系统=灰）+ 需求文档 chip |
| 技术设计 | 计划状态 pill(待批准/已批准/已退回) + 摘要 + 任务数 + 提交/批准时间（退回显示原因）|
| 拆分 | 任务表：id + 标题 + 状态 pill |
| 实施 | 进度条 + 任务执行表（图标+标题+状态 pill+认领窗口）+ 窗口分工 chips |
| 验收 | 结论 pill(待审核/通过/返工) + 结论摘要 + 证据列表（前 5 条）|
| 完成 | 完成时间 + 验收结论 |
| 归档 | 归档目录 + 索引条目 + 合并去向 chips |

固定区块（每个节点都有）：产物 chips → 动态 → 追溯链一行。

## 4. 视觉规格（spec）

| 元素 | 规格 |
|---|---|
| 节点名 | 14px / 700 |
| 副标题(这一步干了什么) | 11.5px / 次要色 |
| 区块标签（任务/产物/动态） | 10px / 600 / 大写 / 字距 .05em / 第三级色 |
| 正文/列表 | 11.5–12px |
| 时间 | 11px / tabular-nums / 相对时间（刚刚·N 分钟前·昨天 HH:mm·MM-DD）|
| 徽章 | 18px 圆：done=绿底白✓ / current=主色底+脉冲环 / pending=灰描边空心 / skipped=虚线 |
| 状态 pill | 10px 胶囊，语义色（绿=通过/已完成，主色=进行中，黄=待批准，红=退回/待确认）|
| 进度条 | 6px 圆角，主色填充 |
| 产物 chip | 11px 胶囊灰底；hover 主色描边；点击弹窗看文档全文；缺失必备产物=红虚线框 |
| 用色纪律 | 主色 #4a7dff 一处（当前/链接），绿 #28a745（完成），红 #dc3545（仅警示），其余灰阶 |
| 间距 | 区块间距 12px，行内 4–6px，面板内边距 12px |
| 暗色模式 | 全部走 dsw 主题变量，自动适配 |

## 5. 交互

- 点流程条节点 → 详情区**就地切换**为该节点（一次取数，切换零等待）。
- 再点当前节点 / 「收起」→ 关闭面板。
- 数据 15s 轮询自动刷新（真监控）；需求有任何推进即更新。
- 产物 chip 点击 → 文档弹窗（会话面板补此能力；看板侧已有，同一渲染器同源）。
- 有待人工确认的产物 → 面板头红 pill「待确认」+ 产物区红虚线框标记。

## 6. 与看板的关系

同一渲染器、同一数据源（/stages 接口）：看板详情页点节点按钮 = 同款面板，两边永远不会再"脱节"。

## 7. 明确不做

- 不要 8 节点手风琴全展开（v1 方案，已否决）。
- 不要卡片套卡片、大色块、多层折叠（原始版，已否决）。
- 不在面板里放操作按钮（审批/确认按钮留在看板「本阶段操作」条——那里是操作位，这里是观察位）。
