# 用户场景设计（REQ-260928222643-4d34）

> 读者：产品/验收人。只覆盖需求文档 UC 卡装不下、但会改变实现的分支（其余见 requirement.md）。

## UC-1 看完节点直达需求详情（主路径） `serves: FR-1, FR-2`

**谁**：坐在会话前的操作者（PM/开发者）。
**何时**：刚在节点面板里看完某个节点，想核对这条需求的完整追溯信息（Token / 追溯 / 条款接收 / 验收单）。
**做什么**：点状态行里的「项目看板 ↗」。
**看到什么**：
1. 画面切到项目看板，呈现的是**这条需求**的详情页（不是默认泳道/列表）；
2. 会话头部的节点面板已关闭；
3. 会话本身没有被切走（回来时还在原会话、原位置）。

**覆盖用例**：TC-1、TC-7、TC-12、TC-15。
**实现落点**：I-3（入口）、I-1（持有器）、I-5（消费）、I-6（顺序不变量）。

## UC-2 分类跳过节点也要能走 `serves: FR-1`

**谁**：操作者。**何时**：当前需求类型跳过了某节点（如 bug 需求没有「需求分析」节点），
面板只显示「本分类跳过该节点」。
**做什么**：点该状态行里的「项目看板 ↗」。
**看到什么**：与 UC-1 完全一致——跳过的节点**不构成**「这里点不了」。

**为什么不特殊处理**：入口写在两个分支共用的 `renderHead` 内，跳过态天然获得入口；
若写在正常分支里，跳过态会漏（这是把「7 个节点全显示」做成结构性保证而非 7 处补丁的原因）。

**覆盖用例**：TC-2。

## UC-3 目标已不在台账 `serves: FR-3`

**谁**：操作者。**何时**：需求已被归档/删除，但会话头面板还持有旧 id（轮询间隔内）。
**做什么**：点「项目看板 ↗」。
**看到什么**：**仍停在会话页**，面板内出现一行红字：「需求 {id} 不在台账（可能已归档或被删除），未跳转」。

**不接受的行为**：静默（点了没反应）；切过去才发现是看板列表（"骗人"）；白屏。

**覆盖用例**：TC-10、TC-13、TC-15④。

## UC-4 页面导航服务未注入 `serves: FR-3`

**谁**：操作者。**何时**：宿主版本/时机导致 `ctx.layout` 未注入（`getPageLayout()` 返回 `undefined`）。
**做什么**：点「项目看板 ↗」。
**看到什么**：不切页，提示「页面导航服务不可用（layout 未注入），请刷新页面后重试」。

**覆盖用例**：TC-9、TC-13。

## UC-5 刷新 / 再次进入看板（非粘滞） `serves: FR-2`

**谁**：操作者。**何时**：从 UC-1 的详情页刷新，或切回会话再点侧栏「项目看板」。
**看到什么**：看板显示**默认视图**（泳道/列表），不再自动钉在刚才那条需求上。

**为什么必须这样**：定位是「一次点击的一次性交接」，不是「把看板设成该需求的常驻视图」——
否则人会失去"回到全局"的入口，且旧 id 会长期影响后续打开行为。

**覆盖用例**：TC-8、TC-15③。
