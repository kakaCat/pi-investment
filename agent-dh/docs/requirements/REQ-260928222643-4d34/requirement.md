## 边界

### 做什么

1. 会话**节点面板状态行**新增「项目看板 ↗」入口（方案②位置：与「12 分钟前」同排）；**7 个节点全显示**，
   含「本分类跳过该节点」的节点。
2. 点入口 → **打开项目看板并直接定位到当前需求详情**；节点面板关闭；会话本身不切换、不丢。
3. 目标不可达时**先校验、不切页**，就地提示失败原因（不许静默，也不许「切过去才发现是列表」）。
4. **下掉「🔄 执行流程」折叠块**：面板里连那一行标题都不出现。
5. 面板**不再为已下掉的块拉取**注入留痕与隔离留痕（打开面板少打两次请求）；后端接口与采集链路保留。

### 不做什么

1. **不改项目看板自身的既有行为**（泳道/列表/筛选/排序/详情页结构/自动链控制面等一律不动），只新增
   「被定位到某条需求」的能力与它的降级路径。
2. **不删后端 `/injection-log`、`/isolation-log` 接口与留痕采集链路**（看板等其它消费方仍可能用），
   本轮只动「面板这一侧」。
3. **不加方案①/③/④ 的其它入口位置**（面板头 REQ 行、底部 sticky 条、流程条尾部），也不动侧栏
   「项目看板」入口与流程条本身。

## 产品定义

### 一句话目标

让「这个节点看完了，我要看这条需求的全景」从**关面板 → 侧栏点项目看板 → 找这条需求**（三步），变成
**一次点击直达该需求详情**；同时把面板里没人消费的「🔄 执行流程」整块下掉，还面板一个干净。

### 核心价值

1. **少绕路**：入口长在「这条需求是谁」的那一行，点一下就到该需求详情（Token / 追溯 / 条款接收 / 验收单）。
2. **不骗人**：到不了就当场说清原因并留在原页——不接受「点了没反应」，也不接受「切过去发现是列表」。
3. **少噪声**：执行流程块连标题行一起消失，面板打开也不再为它多打两次接口。

## 用户与角色

| 角色 | 谁 | 在本需求里做什么 |
|---|---|---|
| 会话操作者 | 坐在会话前的人（PM / 操作者） | 看完节点面板后点「项目看板 ↗」，期望直接看到这条需求的完整详情 |
| 窗口 agent | 会话里的 agent | 行为不变；面板以人的可读性为准（去掉没人看的执行流程块） |

## 接口与契约（行为层；具体载体与实现选择留 design 节点）

- **入口输入**：当前需求 id（面板已持有，来自会话进度接口 `requirement.id`）；可见性（7 个节点全显示）。
- **入口输出（成功）**：① 当前页切到项目看板主面板；② 看板呈现的是**该需求详情**（不是默认列表/泳道）；
  ③ 节点面板关闭；④ 会话本身不切换、不丢。
- **入口输出（失败）**：不切页 + 一条**可见的失败提示（含原因）**；禁止静默。
- **数据契约**：不新增/变更台账字段、不动 `REQBOARD_SCHEMA_VERSION`；只读既有 `requirement.id`。
  「被定位」是**一次性**状态：消费后即清，刷新或再次进入看板回到默认视图（不得形成粘滞状态）。

## 功能点

- **FR-1: 节点面板状态行新增「项目看板 ↗」入口**

  面板 7 个节点（含「本分类跳过该节点」态）都在状态行出现该入口，**文案固定**为「项目看板 ↗」，与相对时间同排。
  判定：对任一节点渲染面板，输出 HTML 含该文案；对分类跳过态同样含该文案。

- **FR-2: 点入口 = 打开看板并定位到该需求详情**

  一次点击完成三件事：切到项目看板主面板、看板进入「该需求详情」状态、节点面板关闭；会话不切换。
  判定：点入口后看板显示的是**该 REQ 的详情**（而非看板列表/泳道），且节点面板不再展开。

- **FR-3: 目标不可达时不切页 + 就地提示原因**

  导航前先确认目标可达（该 REQ 仍在台账 / 看板拿得到）；不可达则**不切页**，就地给出含原因的可见提示。
  判定：用不存在的 REQ id 触发入口 → 仍停留在会话页且有提示（不是静默、不是白屏、不是「切过去看到列表」）。

- **FR-4: 下掉「🔄 执行流程」折叠块（连标题行都不出现）**

  面板不再渲染该 `<details>`；任何节点面板的渲染输出里都不出现「🔄 执行流程」这一行标题。
  判定：面板渲染单测断言输出不含「🔄 执行流程」字样；渲染器不再调用 `renderProcessFold`。

- **FR-5: 面板不再为已下掉的块拉取注入 / 隔离留痕**

  打开节点面板时不再发起该需求来源窗口的注入留痕与隔离留痕请求；
  后端 `/injection-log`、`/isolation-log` 路由与采集链路**保留**（其它消费方不受影响）。
  判定：面板侧代码不再引用这两个查询（grep 断言）；接口本身仍可用（curl 可复核）。

## 迁移与兼容

- **无数据迁移、无 schema 变更**（不新增台账字段、不动 `REQBOARD_SCHEMA_VERSION`）。
- **旧行为兼容**：若「定位」通路不可用，FR-3 生效（留在原页 + 提示），不产生悬挂状态、不影响其它入口。
- **回滚**：本次为页面插件（前端）改动——回退源码后重建客户端产物（`pnpm build:client` + 构建校验）并重启即回滚；
  台账与后端无残留。
