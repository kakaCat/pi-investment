# REQ-4842fe 设计 · 界面：父子卡展示与控制面

> 定位：**看板是观察与控制面，不是必经的推进入口**（FR-16）。所有推进动作由自动链完成；看板只用于"看进度"与"必要时干预"。

## 1. 层级展示  `serves: FR-12`

```
需求卡 REQ-4842fe        [运行中] 父卡 2/5 · 子卡 4/13
  ├─ 父卡 t-abc  [自动]  子卡 4/4  → 收尾中
  │    ├─ dev        ✓ done
  │    ├─ integrate  ✓ done（已跳过：skipIntegration）
  │    ├─ review     ✓ done
  │    └─ test       ✓ done
  ├─ 父卡 t-def  [自动]  子卡 0/4  → 排队（依赖 t-abc）
  └─ 父卡 t-ghi  [手动]  存量卡：走原五段状态机
```

**渲染规则**：
- 子卡在父卡下缩进展示（可折叠，默认展开在跑的父卡）；
- 子卡显示 `stageKind` 徽标 + `attempt`（>0 时显示失败重试次数）；
- 存量卡标注 `[手动]`，不显示子卡区；
- 父卡收尾/排队状态用文字徽标表达，不新增图形体系。

## 2. 控制面（autoRun）  `serves: FR-12`

| 控件 | 位置 | 行为 |
|---|---|---|
| 自动状态徽标 | 需求卡右侧 | 运行中 / 已暂停 / 熔断 / 手动 |
| 暂停 | 需求卡操作区 | 置 `autoRun=false`，已在跑的 run 允许跑完，不再推下一步 |
| 继续 | 同上 | 置 `autoRun=true` 并触发一次推进事件 |
| 终止 | 同上 | 暂停 + 取消在跑卡（取消为人工资格动作，需确认） |
| 进度条 | 需求卡 | 父卡 x/y、子卡 x/y |

**纪律**：控制面只改开关与状态，不直接触发"跑某张卡"（那是自动链的事）；人工要单卡干预时用既有 `reqboard_task_move`（例如取消某卡）。

## 3. 弹框交互面  `serves: FR-16`

| 弹框 | 时机 | 内容要点 |
|---|---|---|
| 需求文档确认 | brainstorming→design（既有，不变） | 产物路径 + 摘要 |
| **批准计划（改造）** | design→decomposing | 文案必须含："批准后将**自动拆分任务卡并立即开跑**，中途不再打断；如需干预可随时在看板暂停或取消" —— 同时承担原「确认拆分清单」门的职责（该门并入本门） |
| **失败处置（新增）** | 实施链 PAUSE 时 | 卡住位置 + 失败原因 + 三选：重跑该卡 / 退回上游重新描述需求 / 取消 |
| 验收 | accepting（既有，不变） | 逐项验收单 |

**交互纪律**：弹框只承载"人要决策"的点；节点推进不弹框、不要求进看板点击。

## 4. 状态与空态  `serves: FR-12`

| 情形 | 展示 |
|---|---|
| 父卡已开工但子卡未展开 | 正常流程不会出现（懒展开与开工同事务）；若出现则显示"子卡展开中"并可手动重试 |
| 子卡失败退回到 todo | 子卡徽标显示 `第 n 次尝试`，父卡状态显示"暂停待处置" |
| 需求已进 accepting | 自动徽标变为"已完成"，控制面关闭（继续按钮不可用） |
| 存量卡 | 与现状一致，无子卡区 |
