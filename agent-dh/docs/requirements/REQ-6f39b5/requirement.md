# REQ-6f39b5 项目看板需求详情页界面优化

## 1. 问题分析

通过代码审查（`packages/pages/dsh-pmboard/src/client/view.ts`），发现需求详情页存在**严重的信息架构重复问题**：

### 1.1 核心问题：Tab 与折叠区功能重复

**问题描述**：
- 顶部有 **8 个节点导航 Tab**（`dsh-pm-stage-nav`）：draft → brainstorming → planning → decomposing → implementing → accepting → done → archived
- 下方有 **10+ 个折叠区**（`<details>`）：需求描述、文档记录、时间线、任务看板、甘特图、DAG、**实施计划**、**验收**、**归档**、评论
- **重复内容**：
  - **实施计划**：既在 planning Tab 中，又单独是一个折叠区
  - **验收**：既在 accepting Tab 中，又单独是一个折叠区
  - **归档**：既在 archived Tab 中，又单独是一个折叠区

**用户困惑**：
1. 不知道该点 Tab 还是展开折叠区
2. Tab 点击后加载到 `#dsh-pm-stage-detail-container`，与下方折叠区平行，分不清边界
3. 同一内容在两处呈现，维护成本高，体验割裂

### 1.2 其他设计问题

**问题 2：信息扁平化不足**
- 所有折叠区默认折叠（除了"需求描述"和"文档记录"）
- 核心信息（任务进度、阻塞状态）需要展开才能看到
- 用户必须记住"任务在哪个折叠区"

**问题 3：任务列表展示效率低**
- 6 列看板布局（`dsh-pm-taskcols`）需要横向滚动
- 任务卡片信息密度低
- 无法快速浏览全部任务状态

**问题 4：视觉层次不清**
- 所有折叠区样式一致，没有轻重缓急
- 大量灰色背景，缺乏视觉引导
- 状态指示不明显


**问题 8：节点推进缺乏人工确认**
- Agent 窗口完成某阶段后，直接调用 `reqboard_move` 推进状态
- 用户没有明确的"确认/拒绝"交互点
- 应该先用 `ask_user_question` 征询用户是否推进
- 例：头脑风暴完成 → 弹框"是否进入 planning 阶段？" → 用户确认 → 推进
## 2. 优化目标

### 2.1 核心目标
1. **消除 Tab 与折叠区重复**：统一为 Tab 体系，按需求生命周期组织信息
2. **信息优先级明确**：重要信息前置，次要信息可折叠
3. **提升浏览效率**：核心任务信息不折叠，一屏可见

### 2.2 设计原则
- **单一信息源**：同一内容只在一处呈现
- **生命周期驱动**：按需求所处阶段动态显示相关 Tab
- **核心信息前置**：任务、进度、操作始终可见，不依赖折叠/Tab

## 3. 优化方案

### 3.1 新信息架构

#### 方案：取消 8 个节点 Tab，改为 4 个核心 Tab + 固定内容区

```
┌─────────────────────────────────────────────────┐
│ 详情头部（固定）                                 │
│ - 标题、状态、时间、操作按钮                     │
│ - 8 态进度指示器（点状，标注当前阶段）            │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│ Tab 切换区                                       │
│ [概览] [执行] [时间线] [归档]                    │
└─────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────┐
│ Tab 内容区                                       │
│                                                  │
│ 【概览 Tab】                                     │
│   ├─ 需求描述（展开）                            │
│   ├─ 当前阶段详情（动态：planning 显示计划、     │
│   │                  accepting 显示验收材料等）   │
│   └─ 文档记录（展开）                            │
│                                                  │
│ 【执行 Tab】                                     │
│   ├─ 任务列表（表格，不折叠）                    │
│   ├─ 进度统计卡片                               │
│   └─ 甘特图（可折叠）                            │
│                                                  │
│ 【时间线 Tab】                                   │
│   ├─ 状态变更记录                               │
│   └─ 评论（展开）                                │
│                                                  │
│ 【归档 Tab】（仅 done/archived 状态显示）        │
│   ├─ 验收材料                                   │
│   └─ 归档清单                                   │
│                                                  │
└─────────────────────────────────────────────────┘
```

#### 为什么是 4 个 Tab？

1. **概览 Tab**：回答"这是什么需求？现在到哪了？"
   - 需求描述（目标、背景）
   - **当前阶段详情**（根据 status 动态显示）：
     - draft/brainstorming：显示提案内容
     - planning：显示实施计划（原折叠区内容）
     - decomposing：显示拆分结果
     - implementing：显示执行进度摘要
     - accepting：显示验收材料（原折叠区内容）
     - done/archived：显示归档清单（原折叠区内容）
   - 文档记录（需求相关文档链接）

2. **执行 Tab**：回答"有哪些任务？谁在做？进度如何？"
   - 任务列表（紧凑表格）
   - 进度统计（完成率、阻塞数）
   - 甘特图（可选折叠）
   - DAG 图（可选折叠）

3. **时间线 Tab**：回答"发生了什么？谁说了什么？"
   - 状态变更时间线
   - 评论列表

4. **归档 Tab**：回答"最终交付了什么？"（仅 done 阶段）
   - 验收材料汇总
   - 归档文档清单

### 3.2 核心改进点

#### 改进 1：消除重复，统一信息源
- **删除**：8 个节点导航 Tab（`dsh-pm-stage-nav`）
- **删除**：独立的"实施计划/验收/归档"折叠区
- **整合**：这些内容根据当前 status 动态显示在"概览 Tab"的"当前阶段详情"区

#### 改进 2：任务列表前置到"执行 Tab"
- **当前**：任务在折叠区，默认折叠
- **优化后**：执行 Tab 中的任务列表始终展开
- **表格列**：状态 | 任务标题 | 阶段 | 负责人 | 依赖 | 操作

#### 改进 3：头部简化，操作外置
- **当前**：头部 + 操作条 + 闸门提示
- **优化后**：
  - 头部只显示：标题、状态、更新时间
  - 8 态进度点（可视化当前位置）
  - 主操作按钮（大按钮，明显）
  - 次要操作收入"···"菜单

#### 改进 4：动态内容区（当前阶段详情）
- **规则**：在"概览 Tab"中，根据 `req.status` 显示对应内容：
  - `status === 'planning'` → 显示实施计划（plan 对象）
  - `status === 'accepting'` → 显示验收材料（verification 对象）
  - `status === 'done' || 'archived'` → 显示归档清单（archive 对象）
  - 其他状态 → 显示阶段进展提示


#### 改进 6：节点推进确认流程
- **当前**：Agent 直接调用 `reqboard_move` 推进
- **优化后**：
  - Agent 完成阶段性工作后，调用 `ask_user_question` 弹框
  - 选项：[是，进入下一阶段 (Recommended)] [否，需要修改] [暂停]
  - 用户确认后，Agent 再调用 `reqboard_move` + `reqboard_confirm_artifact` 落章
  - 在详情页显示"等待确认"状态（如：⏳ 等待推进到 planning）
  - 看板上的"确认产物"按钮仍保留（两种确认方式并存）

## 6. 对比：优化前后

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| **信息组织** | 8 个节点 Tab + 10+ 个折叠区 | 4 个功能 Tab + 固定内容区 |
| **功能重复** | 实施计划/验收/归档在 Tab 和折叠区都有 | 无重复，单一信息源 |
| **任务查看** | 折叠区内，默认折叠 | 执行 Tab 内，始终展开 |
| **当前阶段** | 点击 Tab 加载到独立容器 | 概览 Tab 动态显示 |
| **折叠区数量** | 10+ 个 | 仅在执行 Tab 保留 2 个（甘特/DAG） |

## 8. 原型验证与反馈

### 8.1 原型文件
- **位置**：`docs/requirements/REQ-6f39b5/prototype.html`
- **版本**：v2（已根据反馈优化）

### 8.2 用户反馈与优化

#### 反馈 1：执行 Tab 的甘特图不需要
**原因**：甘特图信息密度低，占用空间大，DAG 已经能清晰展示依赖关系

**优化**：移除甘特图，执行 Tab 不再有折叠区

#### 反馈 2：任务依赖图应放到任务列表上方
**原因**：先看依赖关系，再看任务明细，逻辑更清晰

**优化**：调整布局顺序为 进度统计 → DAG → 任务表格

#### 反馈 3：8 态进度点文字相互遮盖
**原因**：原设计进度点和文字横向排列，间距不足导致重叠

**优化**：
- 改为纵向布局（圆点在上，文字在下）
- 增大间距（gap: 16px）
- 文字单行显示（white-space: nowrap）

### 8.3 最终确认的设计

#### 信息架构
- **4 个功能 Tab**（概览/执行/时间线/归档）
- **0 个折叠区**（执行 Tab 所有内容直接展示）
- **单一信息源**（无重复内容）

#### 执行 Tab 布局（核心）
```
┌─────────────────────────────┐
│ 进度统计（4 个卡片）         │
├─────────────────────────────┤
│ 任务依赖图（DAG，分层展示）  │
├─────────────────────────────┤
│ 任务列表（表格，8 列）       │
└─────────────────────────────┘
```

#### 视觉优化
- 8 态进度点采用纵向布局，清晰不重叠
- DAG 节点用颜色区分状态（完成=绿/进行中=蓝/待办=灰）
- 任务表格紧凑高效，支持悬停高亮
