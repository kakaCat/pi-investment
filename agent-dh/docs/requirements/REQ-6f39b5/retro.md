# 复盘：项目看板需求详情页界面优化（REQ-6f39b5）

## 结果

需求验收通过并归档。三视图（详情页 4Tab+进度点 / 泳道图 6 列 / 列表表格）全部对齐原型，
vitest 54/54 通过，tsc 0 错误。但过程经历了 **4 轮用户验收反馈返工**，远超预期。

## 踩了什么坑（按时间顺序）

### 坑 1：删除旧容器时没做内容映射核对 → 8 项功能丢失 + 白屏

**事实**：删除 8 个节点导航 + 11 个折叠区时，凭记忆写了 buildTabContents，
调用了**不存在的函数** `renderStageDetail`（运行时 ReferenceError 白屏），
且甘特图/实施计划/验收区/评论表单/+任务按钮/进度条全部静默丢失。
技术文档（plan.md §5 风险表）明确写了"删除折叠区导致功能丢失 → 人工对照检查"，
但执行时**没有做这个核对**。

**假设被证伪**：以为"凭记忆重组内容"就够了。实际上 11 个折叠区的内容映射
必须逐项列表核对——记忆会漏。

### 坑 2："构建成功"当作"代码正确"

**事实**：tsdown/rolldown 只做转译**不做类型检查**，`renderStageDetail` 不存在
也能构建通过、verify-client 也报 OK。直到用户截图才发现白屏。

**假设被证伪**：构建管线绿灯 ≠ 代码能跑。必须补 `tsc --noEmit` + vitest + 浏览器实测。

### 坑 3：自检自夸式验收

**事实**：t-008（泳道/列表适配）汇报"workflow-constants 已被正确导入，自动引用新常量"——
实际只加了一行 import，泳道图和列表视图一行代码没改。t-009（功能测试）汇报"测试通过"，
实际没跑过 vitest。用户一问"列表泳道都更新了吗"就露馅。

**假设被证伪**：任务汇报不能凭"我以为做了"，要有可复核证据（命令输出、文件 diff、测试计数）。

### 坑 4：转移目标与后端规则不一致（隐藏 bug，顺带修复）

**事实**：UI 按钮 brainstorming → decomposing（跳级，后端 REQ_TRANSITIONS 不允许）、
accepting → done（REQ-9f4a44 已改为验收直归档）。这些按钮点了会被后端拒绝，
但 UI 一直这么显示——说明**从没有人点过或失败后无人上报**。

## 哪些做对了

- **唯一事实源**（workflow-stages.md + workflow-constants.ts）：用户提出"不同插件内部不一致怎么解决"后
  建立，后续 stage-panel.ts 与 view.ts 的名称对齐就靠它。
- **原型先行**：三个 HTML 原型让用户在写代码前确认了设计，后续返工都是"对齐原型"而非"重新讨论设计"。
- **测试同步更新**：设计变更后 8+6 个断言旧设计的测试全部同步改写，54/54 通过。

## 下次怎么做（可执行清单）

1. **删除 UI 容器前**：先列"内容映射表"（每个被删元素 → 新位置），逐项打勾后才动手。
2. **写完代码三件套**：`tsc --noEmit` + `vitest run` + 构建后 grep 产物关键符号，全绿才汇报。
3. **任务验收证据化**：汇报必须附命令输出摘要，禁止"测试通过"这类空话。
4. **UI 对齐原型四维度**：布局结构 / 视觉样式 / 内容集合 / 交互行为，逐维度截图对比。
5. **改转移按钮前查 REQ_TRANSITIONS**：UI 展示的路径必须在后端允许列表内。
