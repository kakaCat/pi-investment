## 0. 设计输入：需求确认后新增的关键事实 `serves: SP-1`

1. **进化任务失败的直接原因已定位**（agent_os_logs scheduler + scheduler_manage get，2026-10-19）：
   `evolution-distill-daily` 连续重试失败，报错 `fork/exec /bin/true: no such file or directory`。
   任务详情显示：webhook 配置正确（`http://127.0.0.1:13080/agent-os-trigger`，payload.prompt 完整），
   但 command 字段是占位符 `/usr/bin/true`，**调度器 Executor 执行了占位命令而不是走 webhook**。
   ⇒ 大量「🧠 Agent任务」的 ❌ failed 很可能同根因：执行器选错了执行通道。这是本次最重要的新发现——
   进化机制不是"空转"，是**根本没被触发**，而失败状态无人处置。
   （注：webhook 型任务应只走 webhook；executor 为何执行 command、/bin/true 为何报 no such file，待 spike 排查 agent-os 源码 executor.go:140 确认。）

2. 策略库污染比需求文档更严重：125 条策略中大量 `TEST-*` 残留（strategy_list 首页 20 条几乎全是）。

## 1. 设计目标与原则 `serves: SP-1, SP-2, SP-3, SP-4`

- **北极星**：进化的有效性必须用投资结果度量——信号胜率、决策超额收益、账户收益改善；工程纪律只是手段。
- **先修触发，再谈优化**：进化流水线当前多处"假装在跑"，先把触发链修通，否则一切 KPI 都是无源之水。
- **样本先行、授权后置**：造样本分两级——观察计分（零风险，立即可做）与小仓位试单（需用户授权，给出边界建议）。
- **不改交易规则**：本需求不触碰任何 R-xxx 交易规则/仓位档位/止损线（R-016）。

## 4. 需用户拍板的决策点（实施前） `serves: SP-3, SP-4`

1. **试错预算**：方向 B 小仓位试单的月度最大可接受亏损（建议：单票 ≤2% 总资产、月度试单亏损预算 ≤0.5% 总资产 ≈ 2500 元，仅模拟盘 agent_brain）。
2. **策略库处置尺度**：TEST-* 残留策略是直接删除（留 decision_audit + memory 痕迹）还是先归档禁用。
3. **进化降频阈值**：连续几周 KPI 无改善触发进化任务降频（建议 4 周）。

## 6. 风险与边界 `serves: SP-1`

- W1 修改 agent-os 执行器属跨子项目改动，须在独立 worktree 开发并故障注入实测（教训：只测成功路径等于没测）。
- 修复后进化任务会真实高频触发，需先确认其 payload prompt 仍有效（部分任务 prompt 指向的技能/SOP 可能已变更）。
- 本 spike 不承诺"进化一定能提升收益"——承诺的是"进化的有效性从此可度量、假运转被消灭、样本不再为零"。
