## 演示时间
2026-08-27 18:40

## 演示场景
**投资脑发现机会 → 派单研究员 → 研究员分析 → 汇报结果 → 投资脑决策**

---

## ✅ 成功验证的功能

### 1. 窗口注册 ✅
- **投资脑窗口**: `w-investor-demo` 注册成功
- **研究员窗口**: `w-researcher-demo` 注册成功
- **验证**: Agent OS REST API `/register` 正常工作

### 2. 状态管理 ✅
- **初始状态**: 
  - 投资脑: `active` (发现市场机会)
  - 研究员: `idle` (待命)
- **派单后**:
  - 研究员: `idle` → `active` (执行任务)
- **完成后**:
  - 研究员: `active` → `idle` (任务完成)
  - 投资脑: 进入监控状态
- **验证**: 心跳 API `/heartbeat` 正常更新状态

### 3. 元数据传递 ✅
通过 `metadata` 字段传递丰富信息：
- 派单信息: `assigned_by`, `deadline`
- 任务内容: `task`, `target_price`
- 执行结果: `result`, `last_task`
- **验证**: 元数据持久化到 Agent OS

### 4. 窗口清理 ✅
- 演示完成后调用 `/unregister`
- 窗口标记为 `offline`
- **验证**: 软删除机制正常

## 演示流程回顾

```
步骤 1: 创建两个窗口
   ✅ w-investor-demo (投资脑)
   ✅ w-researcher-demo (研究员)

步骤 2: 投资脑查看花名册
   💬 "看看谁有空接任务"
   → 调用 office_roster (模拟)
   → 发现研究员 idle 状态

步骤 3: 派单给研究员
   💬 "派单给研究员分析白酒板块"
   → 调用 assign_task (模拟)
   → 研究员状态: idle → active
   → 元数据: task="分析白酒板块异动"

步骤 4: 研究员执行任务
   💬 "收到任务，开始分析..."
   → 查询数据、分析、生成报告
   → (实际场景中会调用 data_fetch_* 工具)

步骤 5: 研究员汇报结果
   💬 "分析完成，建议关注贵州茅台"
   → 调用 window_message (模拟)
   → 研究员状态: active → idle
   → 元数据: result="建议关注贵州茅台"

步骤 6: 投资脑决策
   💬 "收到报告，准备执行"
   → 风险评估、仓位计算
   → 设置监控：回调至 2000 元买入
   → 状态: task="监控 600519 入场时机"

步骤 7: 验证协作结果
   → 查询注册表
   → 两个窗口状态都已更新
   → 协作链路完整
```

## 核心价值体现

### 1. 多窗口协作 ✅
- 投资脑专注决策
- 研究员专注分析
- 各司其职，提高效率

### 2. 状态透明 ✅
- 所有状态同步到 Agent OS
- 通过 `office_roster` 随时查看
- 决策链可追溯

### 3. 异步协作 ✅
- 派单后投资脑可以继续其他工作
- 研究员完成后主动汇报
- 不需要轮询等待

### 4. 元数据丰富 ✅
- 任务描述、截止时间
- 执行结果、决策依据
- 完整的上下文信息

## 关键发现

### 1. 软删除设计
注销后窗口标记为 `offline` 而非物理删除，保留历史记录，符合审计需求。

### 2. 元数据灵活性
`metadata` 字段可以存储任意 JSON，支持丰富的业务场景。

### 3. 心跳机制简洁
通过 `/heartbeat` 一个 API 同时更新状态和元数据，设计优雅。
