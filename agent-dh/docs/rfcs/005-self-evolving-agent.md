## 1. 设计哲学

**智能 = 盈利能力**。Agent 的进化目标不是"系统不出错"，而是"每天比昨天更会挣钱"。

进化的单元不是代码，而是**认知**：

- **提示词** = 思维框架（怎么看待市场、怎么权衡信号）
- **交易规则** = 盘感（"恐慌底 + 机构吸筹 + RSI<30 → 低吸"这类可执行判断）
- **蒸馏知识** = 经验结晶（从大量决策中提炼的高置信度模式）
- **策略参数** = 手感（止损位、仓位系数、阈值）

这些构成 Agent 的**基因组（Genome）**，被盈亏这个选择压力持续筛选。

### 进化的两层：认知进化为主，能力进化为辅

**第一层 认知进化（日常）**：提示词、交易规则、策略参数、蒸馏知识——这是进化的主体，高频、自动、经回测+模拟盘验证门。

**第二层 能力进化（按需）**：当**代码限制了能力**时，Agent 可以也应该改代码。判定标准不是"代码有 bug"，而是"**认知被代码卡脖子**"：

| 触发场景（举例） | 能力缺口 |
|---|---|
| 判断需要某类数据，但没有对应工具 | 新增工具/数据源适配 |
| 工具返回的数据没法用于决策（覆盖不足、字段缺失、太陈旧） | 改工具实现/回填管线 |
| 一个重复性认知劳动每次都要手算 | 固化为新工具，释放认知带宽 |
| 现有工具行为错误导致决策基于错误数据 | 修复工具 |

能力进化的门槛比认知进化**更高**：自动生成/通过测试 → self_restart wip 检查点部署 → 验证通过后 self_finalize 合并 → 飞书告知变更内容。涉及交易执行、风控、资金的路径必须人工审批（复用 lifecycle 的审批机制）。

原 Master Plan 的 Sprint 0-9（事件总线、代码安全层、测试基础设施等）作为**独立计划废弃**——不禁止改代码，但拒绝"为了自愈而自愈"；代码改动必须由能力缺口驱动，且复用本方案的验证与回滚机制。

## 2. 宪法层（不可进化的硬约束）

以下规则写死在基因组之外，任何提示词改写、规则生成、参数调整都不能突破：

| 类别 | 约束 |
|---|---|
| 交易时间 | A 股 9:30-11:30 / 13:00-15:00，盘前盘后及深夜禁止下单；进化活动（蒸馏/改写/回测）安排在盘后和周末 |
| 交易制度 | T+1（当日买入次日可卖）、100 股整数倍 |
| 风控上限 | 单票仓位上限、止损纪律、总仓位 regime 映射（继承方案二 M4 的仓位表） |
| 标的禁区 | ST/退市风险/操纵嫌疑高分股 |
| 变更纪律 | 每轮进化只改一个变量（可归因）；所有版本留痕可回滚；连续 N 次进化无效自动暂停并告警人工 |
| 代码红线 | 能力进化（改代码）不得绕过/弱化宪法层硬校验；涉及交易执行、风控、资金路径的代码改动必须人工审批 |

实现上：宪法层是一段**独立的、不参与改写**的系统提示词 section + 工具层硬校验（如 portfolio_trade 前置检查交易时段），双保险。prompt_evolver 改写时宪法 section 不在可编辑范围内。

## 3. 核心闭环

```
┌────────────────────────────────────────────────────────┐
│  基因组 = 提示词段落 + 交易规则库 + 策略参数 + 蒸馏知识    │
│  每个版本：可追溯、可回滚、附带实盘/模拟盘成绩             │
└────────────────────────────────────────────────────────┘
                        ↓
① 交易（9:30-15:00）：带当前基因组版本做决策
   每笔交易打标：{genome_version, 使用的规则ID, 决策理由, 上下文}
                        ↓
② 归因（15:30 盘后）：结算当日盈亏，归因到具体规则/提示词版本
   赚钱的是哪条知识？亏钱的是哪条？
                        ↓
③ 学习：经验沉淀 memory/experience（learning_track 已有）
                        ↓
④ 蒸馏（盘后/每日）：N 次决策 → 高置信度规则候选
   写入规则候选库，标记置信度与样本数
                        ↓
⑤ 变异（周末）：prompt_evolver 改写提示词段落
   强化有效规则、删除亏损模式、纳入新蒸馏知识 → 基因组 vN+1
                        ↓
⑥ 选择（验证门）：回测 + 模拟盘 A/B 对比新旧版本
   通过 → 下周一启用；失败 → 回滚并记录"此路不通"
                        ↓
              回到 ①，基因组逐轮增强
```

## 4. 组件设计

### 4.1 genome_manager（基因组管理）〔新插件核心〕

- 基因组结构化存储：提示词段落 / 规则库 / 参数集 / 蒸馏知识，各有独立版本号
- 每个版本记录：父版本、变异原因（哪条经验驱动）、启用时间、成绩快照
- 支持：查询当前版本、历史版本对比、一键回滚到任意版本
- 存储：JSON 文件 + git 版本控制（基因组变更即提交）

### 4.2 decision_tagging（决策打标）

- 所有交易类工具调用自动附加 `genome_version` 和 `rules_used[]`
- 扩展 learning_track 的自动拦截，把打标数据写入经验记录
- 这是归因的地基：**没有打标就没有进化**

### 4.3 attribution（盈亏归因）

- 盘后任务：当日成交按规则/提示词版本分组结算
- 维护每条规则的滚动胜率/平均盈亏/样本数
- 规则健康度：<60% 胜率且样本 ≥10 → 标记 `deprecated` 候选

### 4.4 distill_engine（每日蒸馏）

- 输入：近 N 天经验记录（成功与失败都要）
- 输出：规则候选（条件 → 行动 → 置信度 → 样本数）
- 去重与合并：与现有规则库比对，强化/弱化已有规则置信度
- 高置信度候选进入"待验证"队列，不直接生效

### 4.5 prompt_evolver（提示词进化）

- 周末运行：读取本周归因报告 + 蒸馏出的新规则 + 失效规则清单
- 改写范围：仅限标记为 `evolvable` 的提示词段落（如"决策原则""信号权衡""复盘教训"段）
- 改写原则：每轮一个主题（可归因）、保留历史教训不丢、引用规则ID而非复制规则文本
- 输出：基因组 vN+1 草稿 + 变更说明（changelog）

### 4.6 validation_gate（验证门）

用户确认的门槛：**回测 + 模拟盘**，通过后自动启用，无需人工审批。

1. **回测**：新规则/参数在牛/熊/震荡三区间回测，样本外夏普 >1 且最大回撤不劣于当前版本
2. **模拟盘 A/B**：新版本在 agent_virtual 模拟盘启用，观察期（默认 5 个交易日）对比基准
3. **裁决**：胜率/夏普/回撤三维不劣于旧版本 → 正式启用；任一维度显著恶化 → 自动回滚 + 记录失败原因
4. 验证结果全部落库，成为下一轮进化的经验

### 4.7 evolution_scheduler（进化调度）

| 时间 | 活动 |
|---|---|
| 09:00-09:30 | 盘前：用**当前正式版**基因组扫描信号（不用未验证版本） |
| 09:30-15:00 | 交易时段：只交易 + 打标记录，**冻结一切进化活动** |
| 15:30-16:30 | 盘后：当日归因 → 经验沉淀 → 每日蒸馏 |
| 周六 | 周度进化：prompt_evolver 生成 vN+1 → 回测 |
| 周日 | 模拟盘 A/B 准备与上周观察期裁决 |
| 周一 09:30 | 通过验证的新版本随开盘启用 |

铁律：**进化永不在交易时段改动正在使用的基因组**。

### 4.8 capability_evolution（能力进化，按需触发）

- **触发**：学习/归因过程中发现"认知被代码卡脖子"（缺工具、数据不足、工具输出不可用、重复认知劳动可固化）
- **提案**：生成能力缺口提案（要解决什么决策问题、为什么现有代码不够、改什么）
- **实施**：自主改代码 → 自动测试 → self_restart wip 检查点部署 → 验证 → self_finalize 合并/回滚
- **审批分级**：普通工具/数据层改动自主完成并飞书告知；交易执行、风控、资金路径改动必须人工批准
- **记录**：每次能力进化关联到驱动它的认知需求，纳入经验库（"这次改代码带来了多少决策质量提升"可追踪）

## 5. 分期实施

### Phase 1：基因组地基（1-2 周）

- genome_manager：基因组结构化 + 版本化 + git 留痕
- 现有 system prompt 切分为 `constitution`（宪法，锁定）与 `evolvable`（可进化）两类 section
- decision_tagging：交易打标接入 learning_track
- 验收：任意一笔虚拟盘成交能查到对应的基因组版本与规则 ID

### Phase 2：每日归因与蒸馏（1-2 周）

- attribution 盘后任务 + 规则健康度追踪
- distill_engine 每日运行，规则候选库上线
- 验收：连续 5 个交易日产出归因报告；蒸馏出的候选规则带置信度与样本数

### Phase 3：提示词进化闭环（2-3 周）

- prompt_evolver + validation_gate（回测 + 模拟盘 A/B）
- 自动启用/回滚 + 失败记录
- 验收：完成至少 1 轮完整进化周期（变异→验证→启用或回滚），全程留痕

### Phase 4：元学习（后续）

- 分析"哪类变异有效"：改提示词 vs 加规则 vs 调参数 vs 改代码，各自的胜率贡献
- 进化速度自适应：连续有效则加快节奏，连续无效则放慢并告警
- 与方案二（盈利引擎）对接：基因组驱动 M1-M4 模块的决策质量

> **能力进化（改代码）不设独立 Phase**：它由能力缺口按需触发，贯穿所有 Phase；每次触发走 4.8 的提案→测试→部署→验证流程。

**2026-08-31 补充说明（self_finalize 修复）**：capability_evolution 闭环此前存在断点——`self_finalize` 工具声称支持 `action=merge/rollback`（RFC 005 §4.8 部署→验证→合并流程的收尾端），但实现只写日志 + `process.exit(0)` 直接关机，从不执行 git 合并/回滚，工具 schema 也没有 action 参数。已修复（commit 于 main）：

- `action=merge`：把 self_restart 的 wip 检查点分支快进合并回基线，更新 last-known-good，删除 wip 分支，清理 pending——**验证通过后的正确收尾**
- `action=rollback`：放弃 wip 分支改动，硬重置到 last-known-good，强制删除 wip 分支——**验证失败后的正确收尾**
- `action=exit`：仅保存状态退出（保留旧版关机语义，显式调用才关机）
- 无 wip 检查点（改动已直接在基线）时 merge/rollback 自动降级为仅确认/清理，**不再误杀进程**
- 补集成测试 10/10（merge/rollback/exit 三路径 + resetHard/deleteBranch(force)）

至此 RFC 005 的完整闭环（变异 → wip 部署 → 验证 → merge/rollback 收尾）全部可用。

## 6. 成功指标

| 指标 | 目标 |
|---|---|
| 蒸馏规则存活率 | 启用 20 个交易日后胜率 ≥60% 的规则占比 >50% |
| 提示词版本进步 | 每代版本模拟盘夏普不劣于上一代，3 代内有显著提升 |
| 归因覆盖率 | 100% 成交可追溯到基因组版本与规则 |
| 进化节奏 | 每日蒸馏不断档，每周至少 1 个变异候选进入验证门 |
| 宪法零突破 | 交易时段外下单数 = 0，风控突破数 = 0 |

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| 过拟合：规则只拟合近期行情 | 验证门强制三区间（牛/熊/震荡）回测；规则带衰减机制，久未命中自动降权 |
| 提示词漂移：多轮改写后丢失核心原则 | 宪法层锁定 + 每轮只改一个主题 + 全版本可回滚 |
| 经验样本不足导致错误蒸馏 | 规则候选有最低样本数门槛（如 ≥10），不足只标记不生效 |
| 进化空转：连续多轮无改进 | 连续 3 轮验证失败自动暂停，飞书告警人工复盘 |
| 模拟盘与实盘差异 | 现阶段本就是虚拟账户；未来接实盘时验证门自动加"小额实盘"一级 |
| 能力进化改坏代码 | self_restart wip 检查点 + 启动失败自动回滚兜底；交易/风控/资金路径人工审批；每次改动关联能力需求可复盘 |
