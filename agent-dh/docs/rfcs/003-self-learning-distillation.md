# RFC 003: Agent Self-Learning and Distillation System

## 摘要

设计一套基于**强化学习**思想的自我学习、知识蒸馏和持续进化系统，让 Agent-DH 能够：
1. **从执行结果中学习**（成功/失败经验 → 策略优化）
2. **蒸馏知识**（复杂推理 → 快速规则，降低决策成本）
3. **自我进化**（代码/配置/prompt 自动优化 → 重启验证 → 合并）
4. **能力迁移**（跨任务知识复用）

参考训练模型的方法论（Experience Replay、Policy Gradient、Knowledge Distillation），但适配于符号 AI Agent。

---

## 1. 核心概念

### 1.1 训练循环类比

| 模型训练 | Agent 学习 | 实现方式 |
|---------|-----------|---------|
| 数据集 | Experience Buffer | memory + 结构化日志 |
| 损失函数 | Reward Signal | 交易盈亏、任务成功率、用户反馈 |
| 反向传播 | Policy Update | 策略参数调整、代码生成 |
| 验证集 | Backtest | 历史数据回测 |
| 模型保存 | Checkpoint | git wip 分支 + self_restart |
| Early Stopping | Auto Rollback | 启动失败/指标下降自动回滚 |

### 1.2 学习层次

```
L4 元学习层 ━━━ 学习如何学习（调整学习策略本身）
    ↓
L3 架构层 ━━━━ 修改代码、插件、系统架构
    ↓
L2 策略层 ━━━━ 优化交易策略参数、决策规则
    ↓
L1 记忆层 ━━━━ 积累经验、案例库
```

## 2. 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│  Experience Collection（经验收集）                            │
│  • ExecutionTracker: 记录每次工具调用 + 结果                  │
│  • RewardCalculator: 计算奖励信号（盈亏/成功率/反馈）          │
│  • ExperienceBuffer: 存储到 memory（带 replay 采样）          │
└─────────────────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────────────────┐
│  Learning Engine（学习引擎）                                  │
│  • PatternMiner: 挖掘成功/失败模式                            │
│  • PolicyOptimizer: 生成改进建议（参数/规则/代码）             │
│  • KnowledgeDistiller: 提取可复用规则                         │
└─────────────────────────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────────────────────────┐
│  Evolution & Validation（进化与验证）                         │
│  • CodeGenerator: 生成优化代码/配置                           │
│  • BacktestValidator: 历史数据验证                            │
│  • self_restart + git wip: 安全应用改动                       │

              ↓
┌─────────────────────────────────────────────────────────────┐

```

## 3. 核心工具设计

### 3.1 learning 插件（自我学习核心）

#### learning_track - 追踪执行经验
记录每次决策和结果，形成结构化经验库。

#### learning_analyze - 分析学习机会
从经验中挖掘模式：成功案例的共性、失败的根因。

#### learning_distill - 知识蒸馏
从复杂推理中提取简单规则，降低决策成本。

#### learning_apply - 应用学习结果
生成代码/配置改动 → 安全验证 → 重启生效。

### 3.2 metalearn 插件（元学习）

#### meta_profile - 自我画像
返回 Agent 的能力档案：强项、弱项、学习速度。

#### meta_curriculum - 课程规划
根据当前能力和目标，生成学习路径。

#### meta_transfer - 跨任务知识迁移
将一个领域的知识应用到另一个领域。

### 3.3 benchmark 插件（性能基准）

#### benchmark_run - 基准测试
运行标准测试集，量化能力水平。

#### benchmark_compare - 版本对比
A/B 测试，对比改进效果。

## 4. 学习流程示例

### 示例 1: 策略参数优化（L2 层）

1. **收集**: 跟踪 20 次策略执行，记录参数、市场环境、结果
2. **分析**: 发现 "MA(20) 在震荡市夏普 0.3，趋势市 1.2"
3. **蒸馏**: 生成规则 "波动率 > 15% 时用 MA(10)"
4. **验证**: 历史回测验证规则
5. **应用**: 更新策略代码
6. **监控**: 实盘跟踪新版本表现

### 示例 2: 代码自我改进（L3 层）

1. **触发**: 连续 3 次工具调用超时
2. **诊断**: 识别性能瓶颈（如重复计算）
3. **生成**: LLM 生成优化代码（缓存、向量化）
4. **验证**: 单元测试 + benchmark
5. **部署**: self_restart 应用
6. **回滚**: 若性能下降 > 5% 自动回滚

### 示例 3: 元学习优化（L4 层）

1. **跟踪**: 记录每次学习的效果
2. **分析**: 因子优化成功率 80%，参数调整仅 40%
3. **调整**: 学习策略优先因子优化
4. **迁移**: 将高效方法应用到其他领域

## 6. 知识蒸馏策略

### 规则蒸馏
复杂推理链 → 简单决策规则

输入: 50 次完整分析过程
输出: if-then 规则树

### 特征蒸馏
高维特征 → 关键因子

输入: 50 个因子的模型
输出: 核心 10 因子（保留 85% 预测力）

### 策略蒸馏
黑盒模型 → 可解释规则

输入: 神经网络策略
输出: 可审计的决策树

## 7. 安全机制

### 改动限制
- 单次改动 ≤ 3 个文件
- 关键模块需额外验证
- 必须通过 benchmark

### 回滚触发
- 启动失败（已有）
- 关键指标下降 > 10%（新增）
- 连续 3 次失败（新增）

### 学习速率控制
- 初期: 保守（只调参）
- 稳定期: 激进（可改代码）
- 异常期: 冻结（只记录）

## 9. 成功指标

### 短期（1 个月）
- 策略优化成功率 > 60%
- 蒸馏规则准确率 > 75%
- 改进周期 < 24 小时

### 中期（3 个月）
- 夏普比率提升 20%
- 代码质量改进 15%
- 技能库 > 50 条

### 长期（6 个月）
- 学习效率提升 2x
- 知识迁移案例 > 10
- 自主解决 80% 常见问题
