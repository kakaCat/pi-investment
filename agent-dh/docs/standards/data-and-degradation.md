# 数据与降级规范

**这页回答**：数据从哪来、什么样的数据不能用来决策、降级时怎么写才算诚实。

## 结论先行

1. **派生/审计数据必须登记数据契约**：`quantsys-v2/config/data_contracts.json`
   （owner / kind / 上游 / TTL / 删除策略 / 软引用检查）。未登记 = "无人负责的数据陷阱"。
2. **风控与决策前必须先校验数据新鲜度**：跨源交叉验证（两个独立实现应给同一数）、
   窗口一致性（30/90/180/250 日窗口结果完全相同 = 序列太短，不可只信单值）、
   与账户事实对照（现金占比与回撤不相称 = 可疑）。
3. **降级必须显式**：`degraded` / `stale` / `as_of` 字段必须如实返回；**禁止**用 db 缓存冒充实时、
   禁止把空结果当"没有事件"。数据源冻结/降级期间产生的风控信号一律降级为"待复核"，不直接下单。
4. **引用数据必须标来源 + 时点**（R-013）：写"现价 12.34（data_fetch_quote 实时，09-06 14:05）"，
   不写裸数字；记忆里的模糊数字不得当现价。
5. **删聚合前先查谁还指着它**：外键显式声明依赖策略（审计用 ON DELETE SET NULL + 冗余身份字段；
   派生先清或级联；生产优先状态位不硬删）。

## 关键机制

- 多源降级链：行情/分钟线/资金流等工具返回 `source`（实际服务源）与 `attempted_sources`；
  全失败**显式报错**，不返回空。
- 数据质量工具：`data_quality_report`（缺失/延迟/异常）、`data_manager`（refresh/cleanup/backup）。
- 巡检：`data-hygiene-weekly` 跑 `quantsys-v2/scripts/data_hygiene_probe.py`（退出码 1 = 有问题）。

## 依据

- K 线静默冻结期间，熔断读到的 60 日回撤 -10.71%（真实 -6.77%）——4 个点之差越过 -8% 阈值并自动挂减仓单；
- `strategy_stock_matching` 800/800 行指向已删策略、105 天未更新且零引用，直到人工追查才发现（R-020）；
- 多处"解析失败 → 空数组落库 → 幂等检查把空结果当有效"导致永久挡住重扫。
