# M3-2 策略回测矩阵 - 通过 Agent 执行指南

## 问题说明

原计划的 Python 脚本（`scripts/m3-2-strategy-backtest-matrix.py`）直接调用 quantsys-v2 HTTP API，但发现：
- ❌ quantsys-v2 **没有策略回测的 HTTP API**（`/api/strategies/{id}/backtest` 不存在）
- ✅ 回测功能通过 **agent-dh 的 `strategy_execute` 工具**提供

因此，M3-2 回测矩阵需要**在 DSH 会话中由 Agent 执行**。

---

## 执行方式

### 方式 A：交互式执行（推荐）

在 DSH Web UI (http://localhost:13080) 中，向 Agent 发送以下指令：

```
执行 M3-2 策略回测矩阵：

5个策略 × 3个环境 = 15次回测

策略列表：
1. V13 XGBoost Multi-Factor (ID: 13)
2. V14 XGBoost Multi-Factor Optimized (ID: 14)
3. Strategy 272 (ID: 272)
4. Strategy 273 (ID: 273)
5. Strategy 274 ML (ID: 274)

环境定义（使用近期数据）：
1. 近期反弹：2026-01-01 ~ 2026-02-28（预期 +3.5%）
2. 近期调整：2026-03-01 ~ 2026-04-30（预期 -1.7%）
3. 近期震荡：2026-05-01 ~ 2026-06-30（预期 -1.6%）

执行步骤：
1. 验证3个环境的K线数据完整性
2. 对每个策略×环境组合调用 strategy_execute(mode='backtest')
3. 收集15次回测结果
4. 生成Markdown报告（策略排名表 + 详细矩阵）
5. 筛选生产策略（夏普>1 且回撤<20%）

初始资金：100000
超时设置：每次回测10分钟
```

Agent 会自动：
- 调用 `strategy_execute` 工具执行回测
- 使用 `memory_write` 保存结果
- 生成完整报告

### 方式 B：分步执行（调试用）

如果一次性执行失败，可以分步测试：

重复步骤2，覆盖所有策略。

## 故障排查

### Q1: strategy_execute 返回错误

**可能原因**：
- 策略ID不存在
- 日期区间无K线数据
- 策略代码有bug

**排查**：
1. 先调用 `strategy_list()` 确认策略ID
2. 调用 `data_fetch_kline(symbol='000001', start_date='...', end_date='...')` 验证数据
3. 查看错误日志

### Q2: 回测超时

**原因**：策略计算量大或股票池太大

**解决**：
- 缩小股票池范围
- 增加超时时间（默认10分钟）

### Q3: 某个策略全部失败

**原因**：策略代码bug或依赖缺失

**解决**：
- 跳过该策略
- 用剩余策略完成矩阵
