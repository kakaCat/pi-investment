## Project Overview

**PI Investment Monitoring Dashboard** — A Vue 3 visualization frontend that displays the autonomous AI agent's work and decisions.

### System Role in Three-Layer Architecture

This frontend is the **human oversight interface**:

```
Human User → Monitor & Intervene
      ↓ View
web-frontend (this project) → Monitoring Dashboard
      ↓ HTTP/WebSocket
quantsys-v2 → Backend Service (data source)
      ↑ Operations
agent-ts → Autonomous AI Employee (generates data)
```

### Core Mission: Transparency & Oversight

**Purpose**: Provide visibility into what the AI agent is doing:
- What decisions did it make?
- Why did it make those decisions?
- What were the results?
- When should humans intervene?

**Key Principle**: Make the agent's work **transparent and auditable**.

## Key Features

### 1. Agent Activity Dashboard

**Display**:
- Recent decisions (pool refresh, stock purchase, strategy adjustment)
- Decision reasoning (why this action?)
- Execution results (success/failure, P&L)
- Active tasks and schedules

**Purpose**: Let users understand what the agent is doing in real-time.

### 2. Stock Pool Monitoring

**Display**:
- All stock pools (static/dynamic)
- Pool health status (quality score, risk level)
- Recent changes (stocks added/removed, with reasons)
- Performance vs market benchmark

**Game Intelligence Views** (Future):
- Battlefield assessment (competitive advantage score)
- Opponent behavior (retail/institution flows)
- Risk signals (institution exit, retail chase)

### 3. Signal History

**Display**:
- Buy/sell signals generated by agent
- Signal quality (win rate, avg return)
- Active positions (entry price, current P&L)
- Trade execution details

**Purpose**: Track signal performance and identify issues.

### 4. Decision Audit Trail

**Display**:
- All agent decisions with full context
- Decision outcomes (profit/loss)
- Learned lessons (what worked, what didn't)
- Decision quality trends over time

**Purpose**: Enable learning and continuous improvement.

### 5. Real-time Alerts

**Display**:
- Market opportunities (panic selloffs, oversold quality stocks)
- Risk warnings (institution distribution, manipulation detected)
- Agent alerts (pool health deterioration, strategy failure)

**Purpose**: Notify humans when attention is needed.

## Design Principles

### 1. Agent-Centric, Not User-Centric

Traditional UIs are designed for **user actions**. This UI is designed for **agent observation**.

❌ **Traditional**: "Add stock to pool" button
✅ **This UI**: "View agent's pool decisions and changes"

The primary user action is **monitoring**, not operating.

### 2. Show Reasoning, Not Just Results

Don't just show "Pool refreshed, 3 stocks added".

Show:
- **What**: 3 stocks added (600519, 000858, 000001)
- **Why**: "ROE improved above 18% threshold"
- **Context**: "Previous members 600036, 000333 removed due to deteriorating fundamentals"
- **Game Context**: "Added during retail panic (-5% day), good entry timing"

### 3. Visualize Game Dynamics

Help users understand the **competitive landscape**:

**Good Visualizations**:
- Opponent flow chart (retail vs institution money flow)
- Pool battlefield heatmap (which pools have competitive advantage)
- Risk signal timeline (when did institutions start exiting?)
- Game phase indicator (accumulation/markup/distribution/markdown)

### 4. Highlight Anomalies

Agent works autonomously, so **exceptions need attention**.

**What to Highlight**:
- 🔴 Pool health dropping sharply
- 🔴 Multiple failed trades in a row
- 🔴 Agent decision conflicts with market reality
- 🟡 Strategy performance below expectation
- 🟢 Exceptional profits (learn from success)

### 5. Support Learning Visualization

Show how the agent is **improving over time**:

**Useful Charts**:
- Decision quality trend (win rate over time)
- Strategy effectiveness comparison (which strategies work best)
- Parameter optimization history (how has the agent tuned parameters)
- Learned lessons timeline (knowledge accumulation)

## Key API Endpoints (quantsys-v2)

### Pool Management
- `GET /api/pools` — List all pools
- `GET /api/pools/:id` — Pool details
- `GET /api/pools/:id/history` — Change history

### Agent Decisions

### Game Intelligence (Future)
- `GET /api/market/opponent-behavior` — Opponent tracking
- `GET /api/pools/battlefield-assessment` — Competitive analysis
- `WebSocket /ws/game-alerts` — Real-time alerts

## WebSocket Integration

Real-time updates via WebSocket:

```typescript
// Connect to quantsys-v2 WebSocket
const ws = new WebSocket('ws://127.0.0.1:5003');

// Subscribe to relevant topics
ws.send(JSON.stringify({
  type: 'subscribe',
  topics: ['pool_changes', 'signals', 'game_alerts']
}));

// Handle messages
ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  if (data.type === 'pool_change') {
    updatePoolDisplay(data);
  } else if (data.type === 'game_alert') {
    showAlert(data);
  }
};
```

## Development Guidelines

### When Adding New Views

1. **Identify the Story**: What narrative does this view tell?
   - Not: "Show stock data"
   - Yes: "Show how the agent identified this opportunity"

2. **Include Context**: Always show the "why"
   - Raw data without context is meaningless
   - Agent reasoning is the most valuable information

3. **Make It Actionable**: What can the user do?
   - Override agent decision (if needed)
   - Provide feedback (for agent learning)
   - Drill down for more details

### When Designing Charts

1. **Time-series by Default**: Most metrics are time-series
2. **Annotate Events**: Mark important decisions/events on charts
3. **Comparative Views**: vs market, vs expectation, vs last period
4. **Drill-down Support**: Click for details

### When Handling Alerts

1. **Severity Levels**: Critical / High / Medium / Low
2. **Actionable**: What should the user do?
3. **Context-rich**: Why is this important now?
4. **Dismissible**: Allow user to acknowledge

## Common Issues

### WebSocket Connection Fails
- Ensure quantsys-v2 WebSocket server is running (port 5003)
- Check CORS configuration in quantsys-v2

### API 404 Errors
- Check Vite proxy configuration in `vite.config.ts`
- Ensure quantsys-v2 REST API is running (port 5001)

### Real-time Updates Not Working
- Verify WebSocket connection is established
- Check browser console for errors
- Ensure topics are correctly subscribed
