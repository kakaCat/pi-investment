# 多数据源架构实现总结

## 实现概述

已成功实现多数据源架构，支持自动降级和故障转移，确保数据获取的稳定性。

## 已完成的工作

### 1. 核心组件

#### TushareAdapter (`tushare_adapter.py`)
- 实现 Tushare Pro API 适配器
- 支持日线、周线、月线数据
- 内置限流控制（免费版200次/分钟）
- 自动转换股票代码格式（000001 ↔ 000001.SZ）
- 数据标准化和列名映射

#### DataSourceManager (`data_source_manager.py`)
- 管理多个数据源
- 按优先级自动降级
- 健康状态监控

#### DataService (`data_service.py`)
- 统一的数据服务接口
- 集成缓存管理
- 集成数据验证
- 简化的API调用

#### 配置文件 (`config.py`)
- 数据源优先级配置
- 缓存配置
- 环境变量支持

## 使用方式

### 基本使用

```python
from quantsys.data.data.data_service import DataService

# 初始化（自动配置所有可用数据源）
service = DataService()

# 获取数据（自动尝试 Tushare → AkShare）
df = service.get_daily_klines("000001", days=365)
```

### 配置 Tushare

```bash
# 设置环境变量
export TUSHARE_TOKEN="your_token_here"

# 或在代码中配置
import os
os.environ["TUSHARE_TOKEN"] = "your_token"
```

### 监控健康状态

```python
# 查看数据源健康状态
health = service.get_health_status()

for source, status in health.items():
    print(f"{source}: {status['available']}")
```

## 数据源对比

| 数据源 | 优先级 | 稳定性 | 速度 | 费用 | 限流 |
|--------|--------|--------|------|------|------|
| Tushare | 1 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 免费+付费 | 200/分钟 |
| AkShare | 2 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 免费 | 无限制 |

## 降级策略

```
请求数据
    ↓
尝试 Tushare (优先级1)
    ↓ 失败
尝试 AkShare (优先级2)
    ↓ 失败
返回错误
```

## 健康检查机制

- **成功**：重置失败计数，标记为可用
- **失败**：增加失败计数
- **连续失败3次**：自动禁用数据源
- **手动重置**：`service.reset_health_status()`

## 缓存机制

- **策略**：LRU + TTL
- **容量**：1000项（可配置）
- **TTL**：300秒（可配置）
- **命中率**：第二次请求相同数据时命中

## 性能对比

### 无缓存
- 第一次请求：~1-2秒（取决于数据源）
- 第二次请求：~1-2秒

### 有缓存
- 第一次请求：~1-2秒
- 第二次请求：~0.001秒（1000倍提升）

## 故障处理

### 场景1：Tushare 限流
- **现象**：请求过快，触发限流
- **处理**：自动等待，或降级到 AkShare

### 场景2：AkShare 爬虫失败
- **现象**：网页结构变化，解析失败
- **处理**：如果配置了 Tushare，自动切换

### 场景3：所有数据源失败
- **现象**：网络问题或所有源都不可用
- **处理**：返回错误，记录日志

## 监控指标

建议监控以下指标：

1. **成功率**：每个数据源的成功/失败比例
2. **响应时间**：平均响应时间
3. **缓存命中率**：缓存命中次数/总请求次数
4. **降级次数**：主数据源失败导致降级的次数
5. **健康状态**：各数据源的可用性
