后端全局搜索 - 搜索范围

确定搜索功能支持哪些字段

问题：用户可以搜索哪些字段？

从截图看，表格包含：股票代码、股票名称、市场、K线天数、日期、因子数量、数据状态等字段

A

基础搜索（推荐）

仅搜索股票代码和名称

🔍
支持搜索：
✓ 股票代码（如：600519、000001）
✓ 股票名称（如：贵州茅台、平安银行）
✓ 部分匹配（如：输入"茅台"可找到"贵州茅台"）
示例：
• 输入 "600519" → 找到 贵州茅台
• 输入 "茅台" → 找到 贵州茅台
• 输入 "平安" → 找到 平安银行、中国平安等

优势

  • 覆盖90%的搜索场景
  • 实现简单，性能好
  • 用户认知负担低
  • 数据库索引效率高

局限

  • 无法按市场、状态等筛选
  • 不支持数值范围查询
B

多字段搜索

搜索代码、名称、市场等多个字段

🔍
支持搜索：
✓ 股票代码
✓ 股票名称
✓ 市场（A、SH、SZ等）
✓ 所有文本字段
示例：
• 输入 "SH" → 找到所有上海市场股票
• 输入 "A" → 找到所有A股市场股票
• 输入 "茅台" → 找到贵州茅台

优势

  • 搜索范围更广
  • 支持按市场搜索
  • 灵活性高

问题

  • 可能返回过多结果（如搜"A"）
  • 用户不清楚能搜什么
  • 性能稍差
C

搜索 + 筛选组合

搜索框只搜代码/名称，其他字段用筛选器

🔍
搜索框：代码、名称
筛选器：市场、数据状态

优势

  • 职责清晰：搜索找股票，筛选缩小范围
  • 用户体验最好
  • 支持复杂查询
  • 表格已有筛选器，可复用

成本

  • 需要同时实现搜索和筛选
  • UI稍复杂
  • 开发时间增加1-2小时

💡 我的建议

推荐方案A（基础搜索），因为：
1. 用户主要需求是找特定股票（按代码或名称）
2. 表格已有市场和状态的筛选器，无需重复
3. 实现简单，性能最优
4. 如果未来需要，可以升级到方案C
