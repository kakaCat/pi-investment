2. 后端 API 设计

新增端点：GET /api/stocks/search

请求参数：
?q=搜索词&page=1&pageSize=20
• q: 搜索关键词（必填）
• page: 页码，默认1
• pageSize: 每页数量，默认20，最大100
SQL 查询逻辑：
SELECT s.symbol, st.name, st.market, s.kline_days,
       s.earliest_date, s.latest_date, s.factor_days, s.factor_count
FROM stock_data_summary s
JOIN stocks st ON s.symbol = st.symbol
WHERE (s.symbol LIKE '%' || ? || '%'
       OR st.name LIKE '%' || ? || '%')
  AND s.factor_count >= 30
ORDER BY s.symbol
LIMIT ? OFFSET ?
响应格式：
{
  "total": 3,
  "page": 1,
  "pageSize": 20,
  "stocks": [
    {
      "symbol": "600519",
      "name": "贵州茅台",
      "market": "SH",
      "kline_days": 515,
      "data_complete": true
    }
  ]
}

3. 前端交互设计

用户交互流程
① 初始状态
显示全部股票（分页）
② 用户输入
⏱ 等待300ms（防抖）...
③ 发起搜索
🔄 搜索中...
④ 显示结果
✓ 找到 1 个结果
600519 - 贵州茅台
关键点
• 300ms 防抖
• 显示加载状态
• 显示结果数量
• 空搜索显示全部
• 支持清空按钮

4. 性能优化

数据库优化
• 在 symbol 和 name 字段创建索引
• 使用 stock_data_summary 预计算表
• LIMIT 限制返回数量
• 查询时间目标：< 50ms
前端优化
• 300ms 防抖减少请求
• 显示加载状态提升体验
• 取消上一次未完成的请求
• 空搜索词不发起请求

5. 边界情况处理

场景 处理方式
搜索词为空 显示全部股票（原有分页逻辑）
无搜索结果 显示"未找到匹配的股票"提示
搜索请求失败 显示错误提示，保留上一次结果
快速输入 防抖处理，只发送最后一次请求
搜索词过短（1个字符） 仍然搜索（可能返回较多结果）
