# Plan: application/services 深层限界上下文拆分 (application-services-bc-split)

> Generated by Prometheus (ulw-plan). Intent: clear. Review required: false.

> Source draft: `.omo/drafts/application-services-bc-split.md`.

## Context & Goal
`application/services/` currently holds ~130 flat service modules with no subdomain
boundary, which is the #1 domain-division problem identified in the v2 review.
Goal: reorganize them into **bounded-context subdomain packages** under
`application/<sub>/services/`, and (deep split) introduce **per-subdomain
interfaces/ports** so cross-boundary dependencies depend on interfaces resolved via
the existing DI container — not concrete classes.

## Hard constraints (Must-NOT-Have / invariants)
- **No segfault regression**: do NOT add eager `from .heavy import X` at module top
  of any `application/<sub>/__init__.py` or `application/<sub>/services/__init__.py`.
  Preserve the 2026-08-20 discipline (module-level singletons keep lazy
  `from application.<sub>.services import x` import style). See `application/services/__init__.py`.
- **No behavior change**: HTTP/WebSocket API contracts, scheduler jobs, DB schema,
  and runtime outputs must be identical. This is pure structure + DI rewiring.
- **No dual path**: after the move, `application/services/` must not exist. Exactly
  one import path per service.
- **Scope guard**: do NOT modify `domain/` (problems #2/#3 are separate plans);
  do NOT touch `adapters/outbound/repositories/*` (only their *references* updated
  if they import application services — they don't); do NOT do doc-drift cleanup
  (#4 is a separate plan) beyond a one-line architecture note.
- **No `_backup`/`_old`/`_v2` parallel files**; use `git mv` semantics (rename).

## Subdomain taxonomy (18 bounded contexts)
Each maps to `application/<sub>/services/...`; existing nested subdirs preserved
under their owner subdomain (e.g. `watch_engine/` → `application/monitoring/services/watch_engine/`).
