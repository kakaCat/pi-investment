# Registry 页面深度分析

**核心问题**: Registry 应该展示什么？为用户提供什么价值？

---

## 🤔 首先理解：Registry 是什么？

### 服务注册中心的本质

**类比理解**:
- 就像**公司员工名册** - 记录谁在上班、做什么工作
- 就像**电话簿** - 想找谁做什么事，查一下就知道联系方式
- 就像**值班表** - 显示谁在线、谁离线

### 当前 Agent OS 的 Registry 存储什么？

从数据库表结构看：
```sql
CREATE TABLE agents (
    agent_id VARCHAR(100),           -- "quantsys-v2-12345"
    agent_type VARCHAR(50),          -- "trading-system"
    status VARCHAR(20),              -- "idle" / "busy" / "offline"
    host VARCHAR(255),               -- "127.0.0.1"
    port INT,                        -- 5001
    capabilities TEXT[],             -- ["kline-data", "backtesting", ...]
    metadata JSONB,                  -- {"api_base": "http://...", ...}
    registered_at TIMESTAMP,         -- 注册时间
    last_heartbeat_at TIMESTAMP      -- 最后心跳
);
```

**存储的核心信息**:
1. **是谁** - agent_id, agent_type
2. **在哪** - host, port, api_base
3. **做什么** - capabilities（能力列表）
4. **状态如何** - status, last_heartbeat_at
5. **何时注册** - registered_at

## 🎯 用户需求分析

### 场景 1: 我是系统管理员

**我想知道**:
1. ✅ **现在有哪些服务在运行？**
   - quantsys-v2 在吗？
   - agent-dh 注册了吗？

2. ✅ **这些服务健康吗？**
   - 最后心跳是什么时候？
   - 有没有掉线的？
   - 运行了多久？

3. ✅ **服务的基本信息**
   - 地址端口（如果要手动调试）
   - 进程 ID（如果要重启）
   - 版本号（如果要升级）

4. ⚠️ **出问题时快速定位**
   - 哪个服务挂了？
   - 什么时候掉线的？
   - 如何重启？

### 场景 2: 我是开发者（开发 agent-dh）

**我想知道**:
1. ✅ **quantsys-v2 提供了什么能力？**
   - 我可以调用哪些功能？
   - backtesting 接口在哪？

2. ✅ **如何调用这些服务？**
   - API 地址是什么？
   - 需要什么参数？

3. ⚠️ **服务发现**
   - 谁能做回测？（按能力搜索）
   - 找到后如何调用？

4. ❌ **我如何接入 Registry？**
   - 注册需要什么信息？
   - 示例代码在哪？

### 场景 3: 我是普通用户

**我想知道**:
1. ✅ **系统正常运行吗？**
   - 一眼看到绿色 ✅ = 正常
   - 红色 ❌ = 有问题

2. ✅ **现在在做什么？**
   - quantsys-v2 是 idle 还是 busy？
   - 如果 busy，在执行什么任务？

3. ❌ **技术细节我不关心**
   - 不需要知道 host:port
   - 不需要看 JSON 配置

## 🎨 Registry 页面应该展示什么？

### 核心原则

1. **信息分层** - 重要的大而明显，细节隐藏可展开
2. **状态优先** - 第一眼看到健康/异常
3. **操作便捷** - 常用操作一键完成
4. **面向场景** - 不同用户看到不同信息

## 🎯 核心价值总结

### Registry 页面的本质目的

**不是**: 
- ❌ 展示复杂的技术细节
- ❌ 提供所有功能的入口
- ❌ 替代监控系统

**而是**:
- ✅ **快速了解** - 谁在运行、状态如何
- ✅ **服务发现** - 找到需要的服务和能力
- ✅ **健康监控** - 一眼看出是否正常
- ✅ **便捷操作** - 常用操作一键完成

### 给用户的核心价值

**管理员视角**:
- "现在有哪些服务在跑？"
- "quantsys-v2 挂了吗？"
- "最后一次心跳是什么时候？"

**开发者视角**:
- "quantsys-v2 能做什么？"
- "回测 API 怎么调用？"
- "我的服务注册成功了吗？"

**普通用户视角**:
- "系统正常吗？"（看到绿色 ✅）
- "现在忙不忙？"（idle / busy）
